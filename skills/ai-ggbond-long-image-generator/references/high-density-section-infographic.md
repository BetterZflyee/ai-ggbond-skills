# 高密度章节信息图：语义设计与验收

## 适用场景
公众号文章章节图、观点型信息图、企业咨询图。目标不是“配一张好看的图”，而是让图片脱离正文后仍能独立传递该章节的论证。

## 一、先做内容结构，再写生图提示词

从章节中提取五层信息：

1. **问题/冲突**：读者为什么要看？
2. **前置条件**：现象为何成立？
3. **核心机制**：中间发生了什么？
4. **控制或行动**：如何解决？
5. **结论**：读者应记住什么？

优先使用递进因果链，而不是平行堆标签：

```text
条件 → 现实问题 → 机制/控制 → 责任/行动 → 结果
```

每张图至少包含：标题、3—5个逻辑模块、模块内短标签、明确箭头或关系线、底部结论。单纯“左边好、右边坏”通常只是观点示意图，不算高密度信息图。

## 二、提示词设计规则

- 明确声明：这是“咨询公司交付式结构化信息图”，不是海报、插画或氛围图。
- 指定版式：五栏因果链、流程图、矩阵、分层漏斗等；不要让模型自由发挥结构。
- 为每个模块列出允许显示的精确中文标签。
- 明确禁止：舞台、观众、人物背影、抽象裂缝、城市背景、大面积装饰、无意义机器人。
- 图标必须服务论点；图标内部禁止字母、软件标志和伪文字。
- 默认不添加作者名、日期、年份或“飞哥”落款。只有用户明确要求时才添加。可按品牌要求保留小型“AI朱朱侠”水印。
- 不要把“信息密度最大化”误解为填满画布。密度来自逻辑层级和有效信息，不来自小字与拥挤。

## 三、双重质检

### A. 文字质检
逐字核对：
- 标题、模块名、标签、结论是否完整准确
- 是否有错字、乱码、漏项、重复项
- 是否出现额外英文、字母、软件图标文字
- 是否擅自出现日期、署名、作者或来源

### B. 表达质检（比OCR更重要）
让质检者站在“没读过文章的普通读者”视角回答：

1. 3秒内能否说出这张图的核心观点？
2. 箭头是否表达明确的因果或递进，而非仅装饰？
3. 每个模块为什么会导向下一个模块？
4. 图是否覆盖章节的核心机制，而非只画开头现象？
5. 去掉视觉特效后，信息结构是否仍成立？

只要出现“画面很酷，但不知道想说什么”，即判不通过。视觉质检通过不等于表达质检通过。

## 四、云雾 API 稳定调用

- 使用 GPT-Image-2 前，先做1张样图，避免直接批量消耗。
- `/v1/models` 返回200只说明令牌可访问模型列表，不能替代图片生成验证；应使用低成本测试提示词实际调用 `/v1/images/generations`。
- 同一配置可能存在多个用途不同的令牌，不要默认取“第一个”；应验证所选令牌是否真的有图片生成权限。
- 高密度中文图可能生成较慢。采用连接超时与读取超时分离，例如 `(30, 480)`，并对读取超时做有限重试和指数退避。
- 主链路超时可切换已配置的同服务备用域名，但不得擅自更换模型。
- API Key不得打印到日志或消息；只输出指纹、长度、状态码和错误摘要。

## 五、通过标准

一张合格的章节信息图必须同时满足：

- **准确**：文字与文章一致
- **独立**：不读正文也能理解
- **递进**：模块形成因果或机制链
- **高密度**：至少3层信息层级，不是装饰图
- **克制**：无擅自署名、日期和无关元素
- **可读**：字号、对比度和留白支持快速扫读
