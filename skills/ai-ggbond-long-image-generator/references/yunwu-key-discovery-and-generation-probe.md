# 云雾图片 Key 发现与生成级验证

## 适用场景

当 `image_generate` 报 `Incorrect API key provided: dummy`，而本机历史配置、备份配置或技能 `.env` 中可能仍保存云雾凭据时使用。

## 核心教训

### 1. 不要默认取配置中第一个完整 Key

同一份 Hermes 历史配置可能同时包含：

- 已失效的主模型 Key
- 仍有效的图片专用 Key
- 被 `...` 掩码的展示值
- 示例文件中的假 Key

用正则找到“第一个 `sk-...`”并不可靠。应收集全部未掩码候选 Key，去重后逐个验证；日志只输出指纹和来源路径，不输出完整 Key。

### 2. `/v1/models` 返回 200 不代表图片生成可用

最终判断必须调用图片端点做一次低成本生成探针：

```http
POST https://api.openlux.ai/v1/images/generations
Authorization: Bearer <candidate-key>
Content-Type: application/json

{
  "model": "gpt-image-2",
  "prompt": "纯蓝色圆形，白色背景，不要文字",
  "n": 1,
  "size": "1024x1024",
  "quality": "low"
}
```

只有图片端点返回 200，才可将该 Key 用于正式批量生成。

### 3. 候选 Key 验证顺序

1. 当前 profile 的 `image_gen.api_key` 或 `key_env`
2. 当前 profile 的 `.env`
3. 该技能自己的 `.env`
4. Hermes 历史配置备份中的 `image_gen` 区块
5. 其他候选配置中的完整 Key

忽略：含 `...` 的掩码值、`dummy`、长度不足的值、`.env.example` 中的示例 Key。

### 4. 安全输出

禁止打印完整 Key。只打印哈希指纹、状态码与来源路径。

### 5. 批量生成前必须先做一张正式图

1. 生成一张正式章节图
2. 检查 API、余额、模型权限与文件保存
3. 用视觉/OCR核对全部指定中文
4. 首张通过后再批量生成其余图片

这样可避免错误 Key、错误模型或中文渲染问题连续消耗余额。

## 中文图标陷阱

即使指定中文都正确，模型仍可能在表格、软件或设备图标里自动加入 `X`、英文缩写等额外字母。

提示词要明确：

> 图标内部绝对不要放任何字母、数字、文字或软件标志；使用纯图形化图标。

生成后按“文字白名单”逐项检查。品牌名 `AI朱朱侠` 中的 `AI` 可以保留；任何未在白名单中的可见字母都应判为不通过并单张重做。
