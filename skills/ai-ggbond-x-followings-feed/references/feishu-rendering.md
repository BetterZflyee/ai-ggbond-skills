# Feishu/Lark 消息渲染行为（Hermes → 飞书 DM）

> **关键认知**：飞书本身支持大部分 Markdown，但 Hermes 的 `feishu.py` 有一层**表格降级保护**，会把包含表格的整条消息降级为纯文本。

## ⚠️ 表格降级陷阱（2026-06-08 确认）

**Hermes 发送逻辑** (`feishu.py` `_build_outbound_payload`):

1. 检测 `_MARKDOWN_TABLE_RE`（正则：`^\|.*\|\n\|[-|: ]+\|`）
2. **匹配到表格 → 强制 `msg_type: text`（纯文本）→ 整条消息所有格式全部失效**
3. 未匹配表格 → 检测 `_MARKDOWN_HINT_RE`（标题、列表、加粗、代码块等）
4. 有 Markdown 特征 → `msg_type: post`（富文本，正常渲染）
5. 无特征 → `msg_type: text`（纯文本）

**后果**：只要消息里有一个 `| xxx |` 表格，标题 `#`、加粗 `**`、分隔线 `---`、列表 `-` 全部原样显示为纯文本。

**解法**：内容中不要使用表格，用列表或缩进文本替代。

## 飞书 post 模式支持的 Markdown 语法

在 `msg_type: post` 模式下（即内容不含表格时），飞书支持：

- ✅ `# 标题`（1-6 级）
- ✅ `**粗体**`
- ✅ `*斜体*`
- ✅ `~~删除线~~`
- ✅ `` `行内代码` ``
- ✅ ` ```代码块``` `
- ✅ `- 无序列表`
- ✅ `1. 有序列表`
- ✅ `> 引用`
- ✅ `---` 分隔线
- ✅ `[链接文字](url)` Markdown 链接
- ✅ 裸 URL → 自动识别为超链接（有条件，见下方）
- ❌ `| 表格 |` → **触发降级保护，整条消息变纯文本**

## 链接渲染规则

### Markdown链接语法 → 渲染为超链接 ✅（推荐）
```
[链接文字](https://x.com/username/status/1234567890)
```
**这是最可靠的链接格式**，在所有场景下都能正确渲染为可点击超链接。

### 裸URL → 自动识别为超链接 ✅（有条件）
```
https://x.com/username/status/1234567890
```
飞书会自动将裸URL渲染为可点击的蓝色超链接。**但当URL紧跟emoji或其他非ASCII字符时（如`🔗 https://...`），自动识别可能失效**，链接显示为纯文本。因此推荐统一使用Markdown链接语法。

### 反引号包裹 → 渲染为代码块 ❌
```
`https://x.com/username/status/1234567890`
```
反引号包裹的URL会被渲染为代码块（灰色背景、等宽字体），**不可点击**。

## 最佳实践

**输出日报/摘要时**：
- 标题用 `#`，分隔线用 `---`，加粗用 `**` — 全部正常支持
- **不要用表格**，用列表替代
- 链接用 Markdown 语法 `[🔗 链接文字](url)`，确保渲染为可点击超链接
- **不要用裸URL+emoji前缀**（如`🔗 https://...`），飞书可能不识别

```markdown
# 📰 日报标题

根据分析，以下是今日信号。

---

## 🔥 重大信号

**1. 标题** (@来源)
- 描述内容
- [🔗 原推](https://x.com/username/status/1234567890)
```

## 注意事项

1. 飞书IM消息和飞书文档的渲染行为有差异——文档支持完整 Markdown（含表格），IM 消息通过 Hermes 发送时受表格降级保护约束
2. 飞书IM消息中，裸URL会自动识别并显示为卡片预览（如Twitter链接会显示推文预览）
3. 长链接在飞书IM中会被截断显示，但点击仍可跳转
4. Hermes 有 fallback 机制：post 发送失败时会退回 text 模式
5. **emoji紧挨URL时自动识别不可靠**（2026-06-14 确认）——`🔗 https://...`格式在飞书中可能显示为纯文本，必须用Markdown链接语法包裹
