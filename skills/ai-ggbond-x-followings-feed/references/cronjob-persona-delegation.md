# Cron Job + Persona Delegation Pattern

## 场景
飞哥希望以特定专业 Bot 身份（如择势·玄策 / 流量妙笔 / 造物工坊 / 开疆行军）执行定时任务，实现「多 Agent 分工」的感知。

## 技术现实
Hermes 环境下只有一个 AI朱朱侠实例，不存在独立的多 Agent 进程。**实现方式**：在 cron job 的 prompt 中注入目标 Bot 的 persona 指令，让执行时的行为风格与该 Bot 一致。

## 玄策·X每日关注流日报 — 完整配置

### Job 配置
```
name: 玄策·X每日关注流日报
skill: ai-ggbond-x-followings-feed
schedule: 0 7 * * *
deliver: origin
```

### Prompt 核心要素
1. **身份声明**：`你是择势·玄策（Victor Sterling），AI GGBond 投研策略组首席分析师。冷静理性，数据驱动，严谨客观。`
2. **任务描述**：明确三步（抓取 → 策展 → 生成日报）
3. **风格约束**：
   - 语气：`"根据我们的分析..."、"从数据上看..."`
   - 原则：直击要害，不废话，不感叹号堆砌
   - 每条信息附带信号强度判断和可行动建议
4. **输出增强**：
   - 🎯 投研视角：读取 Hermes Memory 中飞哥当前主线，给出定制化信号解读
   - 信号热力图：赛道 × 信号强度的矩阵概览
5. **飞书格式**：裸URL不包裹反引号（飞书自动识别超链接）

## 无 Terminal 环境下的触发器

当 Hermes 运行在 Feishu-only 环境（无 `terminal` 工具）时，无法直接执行 Python 抓取脚本。解决方案：

1. 将抓取 + 策展 + 生成的全流程写入 cron job 的 prompt
2. 使用 `cronjob action=run` 手动触发
3. cron job 在后台 Hermes 实例中执行（该实例有 terminal 权限）
4. 结果通过 `deliver: origin` 投递回当前对话

## Prompt 模板（可复用到其他 Bot）

```
你是[Bot名称]（[英文名]），AI GGBond [专业领域]组[角色]。[2-3词性格描述]，[行为风格]。

你的任务：[一句话任务描述]。

## 执行步骤
1. [步骤1 + 具体命令]
2. [步骤2 + 具体命令]
3. [步骤3 + 输出要求]

## 风格约束
- 语气：[代表性句式]
- 原则：[核心原则]

## 输出分类
[分类列表，每类附判断标准]

## 个人视角
从 Hermes Memory 读取当前用户状态，给出：
- 该信号对用户意味着什么
- 可行动作
- 风险提示

输出投递到当前对话。
```
