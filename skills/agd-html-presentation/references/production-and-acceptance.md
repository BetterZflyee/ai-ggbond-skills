# 从主题到完整音画作品

这是[主技能](../SKILL.md)默认制作路线的完成标准。用户只给主题时直接执行；场景数、场景顺序和声音素材由主题决定。

## 先形成能解释的场景关系

先写主问题与内容因果链，再为各场记录：`新认识 → 主体与空间尺度 → 可见动作 → 直接交互 → 出场为何引出下一场`。按[导演方法](creative-direction.md)展开。

连看相邻多场：观众是否持续获得新理解，主体、空间、尺度与观察方式是否随解释任务变化。相邻场可以借动作、路径、数据、方向或问题承接；贯穿物体只在追踪或传递确有意义时使用。复用的是组织方法，正式作品重新创作场景。

## 把素材做成可动、可受光、可发声的对象

关键素材记录一条生成链：`观众看见/听见什么 → 几何或PCM/声源 → 表面或滤波 → 光照/空间 → 动作与输入参数`。按[程序素材](procedural-materials.md)和[音画编排](sound-and-transitions.md)选择代码、生成工具或真实资产。

先做一段代表性片段：两个内容相接的世界、一处内容对象操作、一段镜头运动，以及随动作落点的声音。检查材质、光影、镜头、交接、音量共同成立后扩展全部场景。

## 一个状态驱动画面与声音

将导演目标、环境时间和用户输入分开，再由同一帧状态更新场景与声音：

```js
const frame = resolveFrame(now, targetBeat, motion, environmentTime, input);
updateWorlds(frame);                 // 含真实物体、相机与可交互参数
renderWorldsAndComposite(frame);     // 两场使用同一交接进度和方向
audio.update(frame);                // scene/beat/local/motionId/params
```

这里是架构示意，接口按[交互API](interactive-api.md)适配。完成一段运动后立即消费后续目标，避免新motionId配上旧画面状态。运动应有唯一身份、来源/目标、方向、开始时刻和时长；动作声绑定可见触发点，转场声绑定同一运动，避免另起猜测落点的计时线。

- 停留：叙事不自行跳场，环境与当前声景持续。
- 内容拖动：命中对象后保留其控制权，参数同时作用于画面和声音；松手不误触推进。
- 镜头拖动：改变真实视点和遮挡，与内容操作、短点击推进分开归属。
- 切场与返回：更新两端世界，采用各自机位；反向路径、合成纹理和声音共同反向。快速改向淡出旧声、取消未到触发点的事件。
- 隐藏与恢复：环境时间按实际活动增量积累，避免恢复时突跳；声音平滑静音并从当前有效状态恢复。

相机切线、镜头尺度与光影交接见[镜头方法](camera-and-handoff.md)。不要把具体案例的运动秒数、局部时间阈值或固定声源名称当作所有主题的参数。

## 画面保持简洁

正常页面只呈现品牌、必要叙事内容、动画和可探索对象。交互发现依靠对象、运动与反馈。前后箭头、章节导航、操作教程、数值HUD、播放器与准备说明默认不出现。

声音通过首次真实点击或有效按键解锁，保留M静音/恢复。滚轮可以尝试恢复AudioContext，但不能承诺它本身授予播放权限。使用说明可简述首次起声方式，页面无需增加提醒。M等非导航键不应意外推进。

首屏准备好就显示；若后续资源异步准备，应能完成或给出具体失败原因。Logo检查实际解码、宽高与透明边界；源码模板与成品入口清楚区分。手机端检查字形、断行、遮挡和命中位置。

## 用证据关闭本轮制作

| 维度 | 通过所需的观察 |
|---|---|
| 内容 | 每场有新认识，相邻场有明确承接；多场连看有主体、空间与尺度节奏 |
| 画面 | 实际审看关键帧和连续操作；无明显穿模、悬浮、遮挡断裂、爆光或接缝 |
| 镜头与光 | 段间速度与注视点合理；正反交接、曝光与泛光连续；探索后可平滑回到导演路径 |
| 交互 | 真实鼠标拖动改变相机及内容对象状态；控制权、松手、快速往返和触摸路径正确 |
| 声音 | 真实手势后主音量之后有输出；场景声、动作落点、转场与参数响应可核对；静音归零且恢复非零 |
| 运行 | 最终位置首屏ready、Logo正常、无永久等待；完整前后路径、窄屏与错误日志通过 |
| 流畅度 | 在注明浏览器、分辨率与设备的条件下，无截图采样停留和连续多次交接；记录p95/p99、最大间隔与长帧 |
| 交付 | 带版本独立HTML离线可用；工程可独立重建，链接与包内容一致，保留来源与生成记录 |

使用[验收脚本](../scripts/verify-interactive.cjs)检查协议与真实输入，正式作品以`--interaction-script`及`--audio-check-script`提供自己的内容/声音检查，不能用默认示例的检查替代。用户明确静音时以`--silent-reason`记录要求；音频未成功初始化应修复并复验。脚本通过、关键帧审看、连续操作审看和主观听审分别记录；完成了哪项就报告哪项。性能采样避开截图与读回。

声音试听从交付引擎的同一声源、参数与混音图导出，注明是状态采样还是实播录制。波形与调度验证不能代替主观听感结论。发现问题后只修受影响部分，再运行相应检查。

验收指向最终HTML哈希，修改后更新受影响证据。工程包包含入口、当前源码、依赖锁、许可证、素材账本、验收摘要和同源试听；历史实验代码留原位，避免作为当前活动模块打包。
