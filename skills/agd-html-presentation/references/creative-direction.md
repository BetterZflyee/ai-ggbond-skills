# 从主题到原创演示

用户只给主题时，由你完成导演、研究、设计和实现决策。先阅读[技能入口](../SKILL.md)，动作实现按[动作配方](motion-recipes.md)选择。

## 1. 把主题改写成结果

先在工作记录中写三句话：

- 观众是谁，他们进入演示时已经知道什么。
- 结束时希望他们理解、感受到或决定什么。
- 哪一个现有直觉需要被改变，哪一个问题需要被解释。

这些是制作假设，直接推进。用户已给出的受众、品牌、时长、格式和立场优先。
主题涉及用户当前业务时，优先使用已提供的项目背景与真实素材；通用主题则自行选择最有解释价值的切入点。
没有指定受众时，按能够理解主题背景的非专业观众设计，首次出现的关键概念通过画面建立。

## 2. 默认自主决定

自行决定受众层次、论证目标、讲述时长、场景数、节拍、视觉语言、交互方式和结束方式。
篇幅先按认知节点与探索路径确定。需要讲述尺度时可构想约五至八分钟能讲完的作品；用户推进的HTML不设自动播放片长。
场景数量从解释任务推导。不要把参考作品的十三场景、四十三拍或主题顺序写成制作标准。
完成研究和草图后进入实现，在实际画面中调整。用户无需依次批准大纲、风格、脚本和分镜。
只有缺少必需输入、权限、身份确认或明确资源约束，才提出阻塞问题；其余由判断补齐。
用户中途提供新方向时，更新导演方案和实现，保留仍有用的工作。

## 3. 建立一条能被看见的主线

将内容压成一个主问题和一条因果链，明确每个场景如何推动下一步。主线可以跨越不同主体与空间；用场景间的认识递进组织作品，再选择视觉承接手法。
可采用解释、比较、调查、体验、决策或故事结构；主题需要混合时自由组合。
先找三个有价值的时刻：首次改变预期、最难理解的机制、最终获得的新视角。
围绕这些时刻安排张弛、留白与转折，再补上必要的证据与过渡。

每个主要场景写一张导演卡：

| 字段 | 要写清的内容 |
|---|---|
| 认知变化 | 观众看完后新增或改变什么理解 |
| 主体与空间 | 本场解释什么、主要看谁，以什么尺度和空间呈现 |
| 画面事件 | 哪个对象发生什么变化，为什么值得看 |
| 状态与节拍 | 初态、触发、运动、发现、停留、交接 |
| 证据 | 真实素材、数据、来源或明确标注的假设 |
| 交互 | 观众能改变什么，变化怎样影响结果 |
| 出场连接 | 哪个动作、数据、方向或问题引出下一场；观众为什么需要继续 |
| 声音落点 | 本场持续声景、需要同步的可见动作，以及交接时保留或替换的声层 |

先用一句承接句检验相邻两场：“上一场发生/解释了什么，因此下一场需要看什么；下一场带来什么新认识。”再为这层关系设计运动或切点。

将这句话与出入场状态写入实际执行的叙事数据：场景ID、节拍文案、局部目标时间、相邻关系与交接方式由同一份数据驱动画面和声音。导演稿变更后同步执行脚本，避免说明已改而HTML仍播放旧内容。用静态文字顺序读一遍承接，再关闭文字连看画面，分别检查内容关系和视觉关系。

这张卡是制作工具。交付页面保留观众需要的信息。

## 4. 视觉语言为这次主题重新发明

先确定整体的空间、材质、光线、排版和运动气质，再设计场景。
可以采用实拍与标注、平面图形、程序几何、文字雕塑、可探索模型、三维环境或混合语言。
允许大场面、超现实、幽默和戏剧性转折；用主题目标决定它们的规模与位置。
为至少一个关键场景创造专属的视觉规则，使观众能记住这次主题的独特关系。
场景变化要有内容理由，也要被看见：按解释任务安排新主体、近远尺度、内外空间或不同运动机制。大场面应重新设计对象、空间构成、运动逻辑和镜头路径；替换固定模板的标题与颜色不足以完成原创。
例如系统主题可以由个体近景转向网络全景，再进入处理机制与结果现场；真正的变化是解释对象和观察尺度。即使沿用一个视觉母题，也让它在需要时退出中心，把空间让给新主体。
借鉴的是动作机制与组织能力：预期建立、空间揭示、尺度变化、交互验证、首尾回扣。
不要把参考作品的船、骨牌、宇宙、日历、字体蒙太奇连续搬到新主题。

## 5. 隐喻必须有可解释的映射

选择熟悉的物体或规则，确定它承载的概念与变化参数。
例如距离可以承载误差传播，流量可以承载瓶颈，遮挡可以承载认知盲区。
先写明映射，再决定是否需要物理、几何、Shader、实拍或二维动画。
真实数量关系用正确尺度；情绪或概念隐喻允许夸张，通过简短标识避免被读成实测。
当隐喻开始遮蔽主题时，切回真实对象、数字或证据画面。
一个视觉母题可以多次出现，每次承担新的含义；不要为重复本身增加场景。

## 6. 研究与证据进入画面的方法

研究深度取决于论点。需要实际事件、产品能力、价格、政策或近期指标时，检索并核对拥有这些信息的来源。
优先原始资料、官方文档、论文和用户提供的业务记录；保留可回查的标题、链接、日期和使用位置。
从本地作品学到的技巧可以直接作为制作知识，其中的事件与数据需要独立核验后再用于新主题。
建立简洁的来源表，把每条关键事实关联到使用它的场景。

| 内容性质 | 呈现方式 |
|---|---|
| 实测或历史事实 | 给出处、时间、单位与必要统计口径 |
| 来源方预测 | 标出预测主体与适用条件 |
| 自行推演 | 写明输入假设，使模型可以检查 |
| 视觉示意 | 标注示意；避免用装饰刻度伪装精确测量 |

图表的运动不能悄悄改变分母、坐标含义或比较对象。
有数据时让它决定关键状态；缺少数据时改用可说明机制的假设模型，不补造业务成绩。
来源入口、必要注释和详细阅读材料可以放在信息层，避免持续覆盖主画面。

## 7. 把交互写入论证

交互从一个可回答的问题出发：如果改变这个条件，会发生什么。
让拖动、选择、点击、旋转或释放改变真实状态、模型参数、对比范围或观察视角。
交互前让可操作对象可发现；操作时立即反馈；结束后给出有意义的状态或结论。
为讲述者安排默认演示路径，也让自主观看者能探索、复位和继续。
复杂场景优先保留一个清晰的主要操作，其他自由度逐步开放。
拖动期间把控制权交给用户，释放后再按明确规则停留或缓慢恢复演示。

极简界面的可发现性来自内容：比较边缘可抓取、材料表面随靠近受光、设备操作后立即改变流动或声音。正常页面保留主题文字与画面；不因缺少教程而把真实交互退化成点击换页。命中内容对象时优先修改内容，空白处拖动改变镜头，短点击推进；用移动阈值与pointer capture区分归属，释放后不额外推进一拍。

## 8. 用转场延续理解

先确定上一场的结果或未解问题如何引出下一场，再选择动作接力、数据延伸、空间方向、问题递进或构图呼应。
局部共享对象、纹理或投影可以加强已经成立的内容关系。同物体投影交接适合相邻片段中确有传递、追踪或形态转化的内容；其余场景保留各自主体与机位。同一物体反复换背景、整篇锁定同一个观察中心，都不能代替场景叙事。
使用切换、遮挡、淡入、空间穿越或投影对齐，由内容关系决定。
一场连续运动结束后留出阅读停顿，避免每个场景都以高速转场争夺注意力。
声音可以提前预告、跨场延续或在关键动作上落点，保持整个作品的节奏连续。

相邻场可维护一条轻量交接记录：`内容承接 / 出场动作与方向 / 入场主体与尺度 / 视觉锚点或遮挡 / 声音接力 / 正反边界`。城市光流承接成输送路径、实体航路承接为状态节点，是关系迁移的例子；按当次主题重新选择。转场强度随段落变化，机制复杂也应让观众看清哪一场正在退出、下一场为什么出现。

## 9. 让结尾改变开头的含义

回看主问题，判断观众现在多了什么能力、视角或选择。
可以返回开场对象、放大最初细节、收回贯穿的动作，或让用户完成最后一次决定。
回扣必须在此前埋下线索，最后的变化应能被观众自己认出。
需要业务决策时，把范围、依据和下一步放到结束状态；需要知识理解时，让最后的互动验证核心机制。
结尾保留足够停顿，使最后一个动作和问题有时间成立。

## 10. 用成片修正导演方案

在真实浏览器中操作首场、最复杂场景、全部交接和结束状态，再调整密度与过渡时长。
检查每次关键动作是否真的发生、每项交互是否改变状态、每个停顿是否够读。
逐场说明新增认知及前后因果，再连看一段多场序列，检查主体、空间、尺度、构图、光影和运动节奏是否形成变化。若观众只看到围绕同一物体换景，或无法说清为何进入下一场，先调整内容与场景安排，再修技术接缝。
如果画面很好看而论点仍需重复口头解释，重新安排对象关系和揭示顺序。
如果信息过多，先缩小本场解释任务，再改排版。
形成完整体验后交付，把设计决策和必要限制简要写在交付说明中。
