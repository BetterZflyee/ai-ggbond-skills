# 镜头与对象交接

先用[创意导演](creative-direction.md)建立内容因果链与场景关系。连续轨道、光影与性能方法可按需采用；对象局部坐标投影交接，只适合相邻场景确有追踪、传递或形态转化理由的局部片段。

场景连贯来自观众的认识递进，主体、空间和尺度可以随解释任务改变。同一物体换背景、全篇锁定主物体，即使像素接缝完全对齐，也不能替代这层关系。下文包裹仅是代码案例中的锚点；其他内容可使用数据、动作、方向、问题或构图承接。

## 场景各自成立，再连接两场

每场先设计自己的主体、前中远层次、主光和native机位。用近景解释材料或动作，用中景看机制关系，用远景看系统规模；局部目标时间决定本场的揭示，环境时钟维持风、雾、件流等持续运动。用户停留在当前拍时，叙事保持、空间仍活着。

交接期间同时更新出场尾段和入场头段，分别渲染到A/B离屏目标，保留各自深度与焦点，再合成。桥接锚点可取方向出口、光路节点、门框或文字对象的投影；只约束交接起点与运动方向，后场镜头仍服务新主体。未使用同物体交接时，不调用对象对齐器把两场重新锁到同一个中心。

为每条相邻边记录稳定的转场mode和锚点语义。扫描带、汇聚光流、门缝、云层、玻璃与纸面只是可适配配方；边缘厚度、折射、纤维和阴影从同一形变或遮罩场导出。shader应在`p=0`严格返回出场纹理、`p=1`严格返回入场纹理，避免端点残留亮边。

返回时重用这条边的mode，交换前后纹理及锚点，并按`1-p`执行同一合成。只倒放progress而不交换纹理，会把运动方向与前后场身份错配。首尾循环和非相邻跳转明确指定mode；视觉与声音读取同一边和方向，不按两套index规则猜测。

## 连续轨道与有意停点

关键帧同时记录位置、注视点、FOV，必要时加roll。内部控制点共享切线，阅读停点显式设零切线。设段时长为`d`、原始进度为`u=(t-t0)/d`，Hermite轨道为：

```js
const u2=u*u,u3=u2*u;
const h00=2*u3-3*u2+1,h10=u3-2*u2+u;
const h01=-2*u3+3*u2,h11=u3-u2;
// p0/p1是位置或目标，v0/v1是每秒切线。
result.copy(p0).multiplyScalar(h00)
  .addScaledVector(v0,h10*d)
  .addScaledVector(p1,h01)
  .addScaledVector(v1,h11*d);
```

内部切线可从相邻关键帧差分得到`(P[i+1]-P[i-1])/(T[i+1]-T[i-1])`。位置与目标使用同一时间基准，段交界共用速度。FOV也可用相同标量轨道，保持合理范围。

切线按关键帧间真实时间计算，不能把非等距时刻当等距点。可适当缩短切线控制过冲，仍保留内部共享速度；只在段落端点或明确阅读停点设零切线。镜头抵达目标的缓动与场景内部路径分别设计，避免每一个控制点都成为停顿。

轨道输入用原始进度；或选简单路径配合一种进度缓动。避免对进度、局部时间、轨道再次叠加smoothstep，造成每小段反复刹停。用户探索的镜头偏移可单独用指数阻尼，并在推进时平滑回归导演目标。

绕物体运动时用球面方位、仰角与距离；对方位角选较短角差，跨尺度距离用`exp(mix(log(r0),log(r1),u))`。路径需要扫过较大角度时明确设计方向，避免邻接机位反复穿过主体。朝向可用quaternion slerp，机位变化仍需检查实际轨迹与遮挡。

## 局部采用对象坐标交接

先确认这一次边界为什么需要保留对象，并限定重合窗口；片段完成后让新场的主体与机位承接讲述。前后场分别保留同一身份的对象表示：共同几何比例、材质、贴图和识别细节，各自拥有本地接触阴影与前景遮挡。

1. 每帧先更新两场的环境、对象与native机位，分别推进出场尾段和入场头段。
2. 取得对象世界位置`P`、旋转`Q`与统一缩放`s`，将相机与注视点转为对象局部坐标：`cLocal = inverse(Q) * (cWorld-P) / s`。
3. 以一份进度在局部坐标中混合相机、目标、FOV和up，生成共同观察姿态。
4. 分别通过各自`P/Q/s`还原到两个世界。相同对象的八角点或轮廓应投影到相同像素位置。
5. 两场渲染后再交接背景或遮挡边缘，主体位置、比例与朝向保持连续。普通换场可缩短重合窗口；跨尺度揭示可延长。

交接首尾分别匹配出场、入场的native机位。物体在这段时间仍可移动，两边每帧重算对象变换，避免静态截图掩盖运动断点。双场同时推进时，环境时钟与叙事目标分开管理。

## Three.js参考代码

[continuity-three.js](continuity-three.js)是原创的渲染器无关交接助手，依赖项目提供的`three`。它不改变默认太阳/海面起点，也不添加界面。可复制到确需局部同物体交接的工程再适配；不要默认在全篇每个场景持续启用。

示例沿用物流实现的`createParcelContinuity()`和`world.storyParcel`命名。对象本地八角点固定为`±1.2 / ±0.8 / ±0.85`，对应2.4×1.6×1.7几何，前后对象须共同比例并采用统一缩放。换成别的对象时，按实际模型改锚点、角点或轮廓采样。`userData.storyId`用于核对身份。

每个world需提供：

- `scene`、`camera`、`lookTarget`；每帧先计算native机位。
- `storyParcel`：贯穿对象根节点，原点与本地轴定义一致。
- `lights.sun`、`lights.fill`：带target的DirectionalLight。
- 可选场景顶层HemisphereLight与FogExp2。

```js
const continuity=createParcelContinuity();

updateWorld(a,exitState,environmentTime,input);
updateWorld(b,enterState,environmentTime,input);
if(continuity.align(a,b,handoffProgress,width,height)){
  try{
    renderWorld(a,targetA);
    renderWorld(b,targetB);
    composite(targetA,targetB,{
      progress:handoffProgress,
      anchor:continuity.anchor,
      halfSize:continuity.size
    });
  }finally{
    continuity.restore();
  }
}
```

`align()`计算共同相机和局部光源，返回是否具备两端锚点；返回false时使用场景自身的过渡。`getState()`给出八角最大投影误差、身份、光源和雾参数。`restore()`恢复临时光源与雾；下一帧由`updateWorld`重新生成native机位。这个调用顺序避免把上帧的交接结果再次当成原始轨道累积。

助手保留两场的真实几何深度与阴影。若另建悬浮英雄物体层，需补当地接触阴影、玻璃/舱壁遮挡与透射；只有投影连续还不足以建立接触关系。

## 光线、雾与后处理

常规场景交接保留各场的主光逻辑，通过天空、雾色、明暗方向和曝光衔接气氛；新场主体可以因受光揭示而出现。只在已选择同物体投影交接的片段，将主光、补光方向转到共同对象局部坐标中混合，再转换回两个世界；同时混合颜色、强度、天光与地面反射。归一化后的方向避免旋转缩放带来亮度差异。相反方向经过零向量时应选明确的绕转路径。

FogExp2密度先换成对象单位`density*s`混合，再按各场尺度还原。天空、雾色和背景过渡保持同一方向与时间；助手覆盖的字段之外由场景/合成器处理。

曝光、Bloom强度、阈值和景深焦点也随交接连续变化，避免结束帧按场景index硬切。原始高亮在Bloom预滤波时保留余量，检查胶带、金属与玻璃的颜色和表面细节。焦点服务本场解释的主体；新主体出现时设计移焦的时机与路径，局部同物体交接期间再保持共同焦点。

一个可用的后处理顺序是：各场在线性HDR目标渲染 → 按各自深度与主体做轻景深 → 材质化交接 → 多尺度高亮提取与Bloom → 连续曝光、色调映射与最终输出。颜色空间与色调映射只在约定位置转换；先确认关闭Bloom仍有材质、接触阴影和空间层次。压低金属/胶带过曝应先调整材质粗糙度、补光和高亮提取，避免用整体压暗丢失信息。后处理参数取自同一交接进度，不在换index那帧突然重置。

## 验证接缝与流畅度

- 先回答观众为什么进入下一场、将获得什么新认识；连看多场，确认主体、空间尺度与镜头节奏按内容变化。
- 选用同物体交接的局部片段，再在0、1及多个中间进度独立投影角点/轮廓，记录最大像素误差；换尺度、旋转与横竖屏后复核。
- 检查对象身份、朝向、尺寸、机位首尾、光线恢复和连续曝光；看实际接触、透明遮挡与阴影。
- 使用真实输入走完整前后路径、快速改向和重复进入。数值一致后仍需审看连续画面。
- 检查镜头路径全段的前景遮挡、主体裁切、穿模和文字遮挡，窄屏也检查中间状态；端点都好看不能证明轨迹成立。镜头修正后再看跨场方向是否一致。
- 单独记录不带截图的RAF轨迹与场景边界，报告p95/p99、最大间隔和长帧。截图或读回采集与纯交互采样分列。

性能采样覆盖停留、双场同时渲染和快速反向，使用最终成品、实际渲染器与明确视口。像素预算先按GPU与屏幕限制离屏目标尺寸，Bloom可分辨率递减，阴影只留关键关系。预热shader后再采连续交互；首场ready与首次切场的等待另行记录。达到本机帧时间目标后停止重复压力测试，保留机器、浏览器与采样范围，不能把单机结果写成所有设备承诺。

本次参考代码的CPU数学检查覆盖不同位置、旋转、统一缩放、角度跨界和光线恢复；它验证交接计算，不代表任何成品的浏览器性能或视觉审看通过。
