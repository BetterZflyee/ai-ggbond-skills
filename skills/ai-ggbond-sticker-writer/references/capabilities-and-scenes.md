# 能力与使用场景

当前能力由写作判断、可执行脚本和平台操作三层组成。文件存在不等于已调用模型或通过微信验收。

| 能力 | 现有基础与 v3 应用 | 适用场景 |
|---|---|---|
| 内容总结与标题 | 保留资料提炼、标题候选、短文案和自然表达；新增纯文本与编辑稿分离 | 原生贴图、朋友圈文案、连续多图 |
| 新闻与人物研究 | 合入 Hermes 较新的选题、背景补充、非官方实录分层及数字冲突处理 | X 链接、新闻、人物档案、会议摘编 |
| 公众号写作方法 | 接入真实图片与证据卡、人物故事节奏、数据口径和个人品牌身份边界 | 事件解释、人物系列、商业与基础设施主题 |
| 连续多图 | 一份计划固定页序、每页任务、文字与来源，数量不按 Markdown 标题自动扩张 | 概览、机制、案例、操作、结尾的阅读顺序 |
| 信息图视觉 | 商业杂志编辑风是当前默认；科技风、高密度、复古波普、文件夹、票据、手帐与矢量保留为选项 | 步骤、对比、数据、时间线、清单 |

| 生图 | 当前环境原生工具优先；兼容外部生图脚本保留配置、指定模型、图片下载与可选水印能力 | 真正生成和编辑图片，必须区分模型输出与计划 |

## 语义组件复用

同一份内容选择不同的呈现方式：

- 操作步骤：贴图中做顺序图；长文用 `steps`，保留可复制文字。
- 多方案比较：贴图中保留共同指标；长文用 `table` 或 `comparison`，避免把比较改成互不相干的记录。
- 人物/项目演进：贴图用时间线或档案页；长文用 `timeline`，来源跟随日期和节点。
- 数据：贴图突出少量准确数值；长文用 `metrics/chart/table` 保留单位、精度和来源。
- 问答/揭秘：原生图片中完整表达问题与答案；长文才按需要提供静态问答与实验互动候选。

原生图片不会自动变成可编辑表格，也不能把浏览器动画或 SVG 作为原生贴图图片上传。需要哪些图由内容决定，不强制每篇塞满组件。

## 当前验证边界

本地构建器和适配器不访问账号。生成能力取决于当前工具与配置；没有实际生图、上传、草稿读回、真机操作时，各项保留未测。历史失败说明仅作排障线索，不宣称当前必然失败；历史成功也不能代替新内容的验收。
