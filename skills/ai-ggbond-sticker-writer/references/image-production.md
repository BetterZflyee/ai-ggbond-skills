# 生图与素材处理

## 环境路由

- Codex：有内置 `image_gen` 时使用它，遵从当前工具参数与图像编辑要求。生成前保存计划与 prompt，结果按工具提供的本地文件或原生展示交付；不为了贴图调用外部服务脚本。
- Hermes：优先当前 Profile 已配置、获授权的图像工具。保留用户指定的模型、提供商与代理设置，不写入其他 Profile 的凭据。
- 已明确使用外部兼容脚本的环境：`generate_sticker_images_v2.py` 使用现有配置。请求路径、支持尺寸与模型参数需匹配实际服务；脚本模板不是服务端能力保证。

旧合集记录的用户指定外部模型是 `gpt-image-2.6-flare`，因此兼容脚本和新配置模板以该名称作为回退默认，调用已有该链路时显式传 `--model gpt-image-2.6-flare`。这不是对当前服务可用性的保证，也不改写已有配置。Codex 内置工具不能选择此型号时，不宣称同型号已执行；若本次明确要求这个外部型号，则使用已授权且实际可用的对应链路，无法使用时说明缺口，不暗中换模型。

当前计划构建器从不调用模型，也不读取凭据。一次技能维护或本地预览测试不等于授权发起收费生图。

## 生成与核对

每张图按计划独立生成，保持身份、字体层级和配色连贯。对正文、品牌名、数值、单位逐项核对。OCR 只辅助发现错字和缺字；视觉核对检查字形、层级、拥挤和裁切。实际看到成图后，才写 `review.status:passed`、方法及该文件的 SHA-256。

新方向优先一张样图，再沿已确定方向完成整套。用户已给完整参考与整套授权时按授权继续，不因历史“四签”反复暂停。实拍图和视频帧可作为编辑参考，保留真实结构与证据上下文，不将生成补画当原始影像。素材权利标识不默认清除；成图上的正文与标题不能被去水印工具当作待删除内容。

图片变更、裁切、压缩或水印后重新检查成品，不沿用旧文件的哈希。编辑图片遵从当前环境图像编辑工具要求；只有用户明确要求程序化处理且当前工具政策允许时，才采用现有代码水印或拼接路径。完整长图可参考长图技能的分段与接缝方案，不能把拼接计划当已完成长图。

## 兼容脚本的边界

旧 Markdown 生图脚本已补齐普通段落提取，不再只读取短项目符号；解析仍是小范围导入，复杂 Markdown 建议使用明确图片计划。部分生图失败会报告实际完成数并返回失败，已成功文件保留。未知风格不再静默改为其他模板。

16:9 请求模板使用 1600×900，3:4 使用 1200×1600；可用 `YUNWU_IMAGE_SIZE_16_9` / `YUNWU_IMAGE_SIZE_3_4` 配置实际服务接受的尺寸。若服务不支持，报告具体错误，不自动改模型或假称比例正确。实际尺寸由交付构建器再次测量。

已配置单一服务地址时只使用该地址；只有明确列出的多地址池可轮询。429/超时按有界重试策略处理，先检查已落盘文件，避免重复生成。401/403、内容拒绝和无效参数不应靠更换未知提供商、隐藏意图或绕过审批处理。错误日志不输出密钥或完整响应中的敏感字段。

`sticker_manager.py` 仅管理文案与 prompt，不生成图片；同分钟同标题再次保存会新建版本目录，避免覆盖。`generate_images.py` 是旧接口兼容脚本，新任务使用当前环境工具或 V2 脚本；不要把旧模板中的尺寸、评分、模型性能描述当现行事实。
