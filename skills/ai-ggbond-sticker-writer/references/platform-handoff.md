# 公众号发布交接

先区分原生图片消息和长文章。用户仅要求制作或升级时交付本地包；用户已经授权推送时完成相应操作，不重复询问。公开发布和创建草稿的授权范围不同。

## 原生贴图

本地交接路径：

```bash
bun "<publisher-skill>/scripts/wechat-api.ts" \
  "/path/to/bundle/newspic-bundle.json" --type newspic --dry-run
```

适配器读取纯文本正文与有序图片列表，校验每张图片的哈希和顺序，不再给短文案套长文章主题，也不把图注、标签或 HTML 包装送进原生正文。第一张图片承担封面。部分上传失败应停止创建草稿，不能静默少图发布。

dry-run 只核对本地文件，返回图片数量、ID 顺序、原生正文及核对状态。移除 `--dry-run` 是外部草稿操作，只能沿用户已有授权执行；未完成核对时先完成核对，不需要额外批准。指定已有草稿 ID 时本创建入口会拒绝重复创建，须走更新接口或已可用的浏览器流程。

平台当前的图片数量、文字大小、文件类型限制以 [微信新增草稿接口](https://developers.weixin.qq.com/doc/subscription/api/draftbox/draftmanage/api_draft_add.html) 和目标账号为准。500 字为个人编辑预算。历史 45166、网络错误或“贴图 menu not found”仅是历史排障记录，当前使用时看实际错误，不推导固定成功率。

## 长文章与信息卡

`layout-input.json` → 公众号精排模块 → `article.html` / `handoff.json` → 现有发布器。标题、摘要、封面分离，图片 alt 不变成可见图注。不能把原生贴图 JSON 当 Markdown 转换，也不把长文 HTML 当原生正文。

## 验收层级

分别记录：本地文件与图文核对、浏览器阅读预览、模型实际生成、上传结果、目标草稿 ID 与正文/图片读回、手机微信及深色模式。每次修改图片都绑定新哈希；只上传成功不能称为读回或真机通过。

写入后记录目标账号、草稿 ID、图片页序和时间；修改旧稿优先更新同一 ID，避免重复草稿。账号未知只阻塞账号相关操作，文案、图片计划与本地预览可以继续完成。
