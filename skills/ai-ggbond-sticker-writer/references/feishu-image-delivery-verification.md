# 飞书贴图交付验证：生成成功 ≠ 用户已收到

## 触发场景

用户要求“生成图片并以附件发送”“把图发给我”“我没有收到附件”时使用。

## 核心规则

只有同时满足以下三项，才可以说“已发送”：

1. 图像工具或指定模型真实返回成功结果；
2. 本地图片文件真实存在，并完成尺寸与内容质检；
3. 最终回复中包含可投递的 `MEDIA:/绝对路径/文件.png`。

缺任意一项，都不得使用“已画好”“见上图”“已作为附件发送”“请查收”等完成态措辞。

## 执行顺序

1. **生图能力预检**：正式制作前检查指定模型链路是否有可用凭据；不要等文案、目录、提示词全部完成后才发现最终生图不可用。
2. **真实生成**：严格使用用户指定模型。失败时不得用 SVG、PIL、HTML 或占位图冒充模型成品。
3. **落盘验证**：确认文件存在、非空、扩展名正确，并读取实际尺寸。
4. **视觉/OCR质检**：检查比例、裁切、文字、图文一致性；不合格则修复或重生。
5. **附件投递**：最终回复单独放置 `MEDIA:/absolute/path/to/output.png`，路径必须指向已验证文件。
6. **发送后措辞**：只有 MEDIA 已实际写入本次回复，才说“附件如下”。

## 失败分支

### 模型/API失败

直接说明：

> 图片尚未生成，因此目前没有附件可以发送。模型返回：`<简短错误>`。

可以交付已落盘的 Markdown / prompt 文件，但必须明确它们不是图片成品。

### 用户反馈“没有收到”

把反馈视为交付失败证据，不要重复口头声称“已发送”。立即检查：

- 上一条回复是否真的含 `MEDIA:`；
- MEDIA 路径是否为绝对路径；
- 文件是否真实存在且可读；
- 是否误把工具返回、聊天内预览或文字描述当成附件。

修复后重新发送，回复保持简短，不再解释不存在的成功。

## 禁止

- 工具返回 401、429 或超时后说“已画好”；
- 没有 MEDIA 行却说“附件已发送”；
- 把工具调用、链接或聊天预览称作飞书附件；
- 用户连续说未收到时继续重复完成态回复；
- 用本地拼图冒充指定模型输出。只有用户明确授权“本地草稿/占位图”时才可使用，并必须显著标注。
