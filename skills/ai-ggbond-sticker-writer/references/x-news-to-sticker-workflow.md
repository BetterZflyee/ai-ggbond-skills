# X新闻转贴图工作流

当用户从X日报中挑选某条新闻要求转成微信贴图时，执行以下流程。

## 触发场景

- 用户说"把这个新闻做成贴图"、"这条转贴图"
- 用户从X日报中指定某条内容要求转化
- 用户给一条X推文链接要求转贴图
- **用户说"哪些可以转换成贴图"、"哪些适合做贴图"** → 批量筛选模式

## 两种模式

### 模式A：批量筛选模式（飞哥问"哪些可以做贴图"）

**触发**：飞哥看完X日报后问"哪些可以转换成贴图"或"哪些适合做贴图"

**流程**：
```
X日报打分结果 → 按贴图选题标准筛选 → 推荐3-5个+理由 → 飞哥选一个 → 出内容+prompt
```

**筛选标准**（从272条推文中筛出4个的实战验证，2026-06-24）：

| 维度 | 好素材特征 | 差素材特征 |
|------|-----------|-----------|
| **场景感** | 能让读者"看到"具体场景（"@一下就有AI帮忙"） | 抽象描述（"AI协作范式升级"） |
| **数字冲击** | 有具体数字（65%代码、30秒视频、-32%跌幅） | 只有定性描述（"大幅提升"） |
| **反直觉** | 认知冲击（"你以为AI很强？其实在烧煤"） | 常识确认（"AI越来越强"） |
| **争议性** | 有正反两面可以讨论（"干翻Claude？先看三个坑"） | 一面倒的好/坏 |
| **热度窗口** | 今天刚发、正在讨论 | 过时新闻 |

**输出格式**：
```
从今天的日报里筛，按"普通人分享好东西"的视角，最适合做贴图的有 X 个：

1. **标题** ⭐ 最推荐
场景感最强：[一句话说明为什么适合做贴图]

2. **标题**
数字冲击力：[一句话说明]

3. **标题**
反直觉认知冲击：[一句话说明]

---
我的判断：先做第X个，因为[理由]
```

**注意**：
- 不要把所有日报内容都列出来，只列3-5个最适合的
- 每个推荐必须给出具体理由（场景感/数字/反直觉/争议性）
- 给出"我的判断"推荐哪个优先做，但让飞哥最终决定

### 模式B：单条深挖模式（用户指定某条新闻）

**流程**：
```
用户指定X新闻 → 深挖新闻详情 → 搜索补充背景 → 按贴图风格写内容 → 生成配图
```

### 步骤1：获取新闻详情

**优先用 fxtwitter API**（无需auth，不会过期）：

```bash
export HTTPS_PROXY=http://127.0.0.1:7897
curl -s -x $HTTPS_PROXY "https://api.fxtwitter.com/{user}/status/{tweet_id}" > /tmp/tweet_detail.json
```

解析要点：
- 推文原文（`tweet.text`）
- 引用推文（`tweet.quote`）
- 媒体文件（`tweet.photos`、`tweet.videos`）
- 互动数据（`tweet.retweets`、`tweet.likes`）

### 步骤2：搜索补充背景

用 `web_search` 搜索新闻涉及的公司/产品/人物，获取：
- 公司背景（成立时间、融资、创始人）
- 产品详情（功能、定价、用户量）
- 行业数据（市场规模、竞品对比）

**搜索策略**：
```
"{公司名} {产品名} {年份}"
"{公司名} YC batch"
"{创始人名} background"
```

### 步骤3：按贴图风格写内容

**核心原则**（参考主技能"普通人分享好东西"风格）：

1. **场景化 > 参数化**
   - ❌ "Kinro AI 是 YC P26 孵化的保险科技公司"
   - ✅ "凌晨3点想买保险，一个AI给你讲了20分钟，然后你买了"

2. **短句+加粗+口语化**
   - 每段2-4行
   - 核心判断加粗
   - 用"你"拉近距离

3. **不说教，不替读者下判断**
   - ❌ "这说明AI正在颠覆保险行业"
   - ✅ "AI卖保险不是新闻，AI把买保险变简单了，才是"

4. **500字以内**

### 步骤4：贴图结构模板

```markdown
# [标题]

---

## [第一段：场景钩子/新闻事件]

[用场景引入，让读者"看到"这个东西]

---

## [第二段：核心信息]

[具体数据/功能/特点，加粗关键点]

---

## [第三段：行业背景/数据]

[补充背景信息，让读者理解重要性]

---

## [第四段：不同视角]

[提出有趣的角度，但不下结论]

---

## [第五段：普通人视角]

[从普通人角度看这件事的意义]

---

## [一句话总结]

[收束，但不说教]

---

*信息来源：[具体来源]*
```

### 步骤5：生成配图

按主技能的配图流程执行：
- 默认科技风（深色背景#0A1628 + 霓虹蓝#00D4FF）
- 默认16:9横版
- 提示词全中文（专有名词除外）

## 写作风格迭代记录（2026-06-18 血泪教训）

飞哥纠正了3轮才找到正确的写作风格，必须记住这个迭代路径：

### ❌ 第1版：太AI味

**问题**：有标题格式、加粗、"不是X是Y"对比结构，像产品说明书

### ❌ 第2版：分析师评论调子

**问题**：还是"分析师评论"的调子，"我想了半天"太端着

### ✅ 第3版：普通人分享新奇东西

刚刷到一个东西，真的惊到我了。
有个 AI，自己把保险卖出去了。
你没看错。不是帮销售打辅助，是从头到尾，报价、答疑、成交，一个活人都没插手。

**对味了**：普通人发现新奇东西的反应，跟朋友分享的语气

1. 开头用「荒诞事实」必杀技

## 朱朱侠内容创作方法论在贴图中的应用

参考 `ai-ggbond-article-writer` 技能中的「内容创作方法论升级」，贴图写作同样适用：

### 1. 开头必杀技（选一种）

| 模式 | 用法 | 示例 |
|------|------|------|
| **荒诞事实** | 直接抛出一个让人"？？？"的事实 | "有个事情挺魔幻的。" |
| **好奇心驱动** | 抛出钩子，制造疑问 | "刚刷到一个东西，真的惊到我了。" |
| **叙事启动** | 从一件具体小事讲起 | "昨天凌晨三点，我突然想买份保险。" |

### 2. 找反差角度（拒绝第一直觉）

拿到新闻后，先列出所有人都会写的常规角度，再主动排除：

```
常规角度 1：AI抢饭碗 → 太老套
常规角度 2：YC又投了个AI公司 → 太冷
常规角度 3：保险科技新玩家 → 太行业
最终选择的陌生化角度：买保险这件事可能要变简单了，主动权回到消费者手里
```

### 3. 升番节奏（三层递进）

- **第一层**：给判断/事实（"有个AI卖出去了一份保险"）
- **第二层**：给反差（"不是高级客服，是全流程无人参与"）
- **第三层**：给更大的认知跃迁（"主动权跑你手里了"）

### 4. 弱者思维（不要装懂）

- ✅ "我第一反应是：扯呢吧？"
- ✅ "我一开始也觉得，保险这么复杂的事，AI能搞定？"
- ✅ "后来想了想，简单的确实能。"
- ❌ "这说明AI正在颠覆保险行业"（你在替读者下判断）

## Pitfalls

### ⚠️ yunwu.ai API key可能没有图像生成权限（2026-06-24 发现）

**症状**：调用 `image_generate` 工具报 `401 Incorrect API key provided: dummy`，或用脚本直接调 yunwu.ai 的 `/v1/images/generations` 返回 `403 该令牌无权访问模型`。

**原因**：`~/.hermes/config.yaml` 中 `image_gen.api_key` 配置的 key 可能只开通了文本模型权限，没有开通图像生成权限（dall-e-3、gpt-image-1、gpt-image-2 等）。

**验证方法**：
```bash
# 检查config中的image_gen配置
cat ~/.hermes/config.yaml | grep -A 5 "image_gen"

# 测试API权限
python3 -c "
import requests, re, os
with open(os.path.expanduser('~/.hermes/config.yaml')) as f:
    content = f.read()
    match = re.search(r'image_gen:.*?api_key:\s*(sk-[^\s]+)', content, re.DOTALL)
    if match:
        key = match.group(1)
        r = requests.post('https://api.openlux.ai/v1/images/generations',
            headers={'Authorization': f'Bearer {key}', 'Content-Type': 'application/json'},
            json={'model': 'dall-e-3', 'prompt': 'test', 'n': 1, 'size': '1024x1024'},
            timeout=30)
        print(f'Status: {r.status_code}')
        print(r.text[:200])
"
```

**解决方案**：
1. **飞哥提供有图像生成权限的API key**（OpenAI/FAL/SiliconFlow都行）
2. **把prompt给飞哥**，让他丢进ChatGPT或豆包生成
3. **检查是否有其他provider配置**（如FAL_KEY环境变量）

**不要**：反复尝试不同模型（都是同一个key，都会403）。

## yunwu API 配置位置

贴图配图使用 yunwu API，配置文件位置：
- **技能目录**：`/Users/admin/.hermes/profiles/neirong/skills/creative/ai-ggbond-article-writer/.env`
- **用户级**：`~/.ai-ggbond-skills/.env`
- **Hermes全局**：`~/.hermes/config.yaml` 的 `image_gen` 段

配置内容：
```
YUNWU_API_KEY=sk-xxxxx
YUNWU_BASE_URL=https://api.openlux.ai
YUNWU_DEFAULT_MODEL=gpt-image-2
```

**调用方式**：写脚本到 `/tmp/gen_xxx.py`，用 `terminal` 命令执行。不要在 `execute_code` 里直接读取 API key（会被掩码导致 SyntaxError）。

## 注意事项

1. **不要扩展成全量日报**：用户指定哪条就处理哪条，不要把整篇日报都转成贴图
2. **深挖比直接转更重要**：一条推文的信息量有限，必须搜索补充背景
3. **场景化是核心**：新闻稿式的冷冰冰转述没人看，要用场景让读者"看到"
4. **配图围绕内容**：不要默认加女性角色，配图主题必须与新闻内容相关
5. **迭代是正常的**：飞哥可能会纠正3-4轮才找到正确的风格，不要急着定稿
