# 微信贴图生成器

将本文件目录解析为 `{baseDir}`，脚本统一使用 `{baseDir}/scripts/*.py`：

| Script | Purpose |
|--------|---------|
| `scripts/sticker_manager.py` | 创建标准目录与 Markdown |
| `scripts/generate_sticker_images_v2.py` | 生成贴图配图（推荐） |
| `scripts/generate_images.py` | 兼容版配图脚本 |
| `scripts/config_loader.py` | 配置加载工具（用户级/项目级） |

## 核心工作流程（⭐严格按照以下步骤执行）

**⚠️ 重要：必须严格按照以下6个步骤顺序执行，不能跳过任何步骤**

```
步骤1: 确认内容来源 → 步骤2: 内容审核优化 → 步骤3: 生成标题
    ↓
步骤4: 创建文件结构 → 步骤5: 选择风格+确认比例 → 步骤6: 生成配图
```

### 步骤 1：确认内容来源

当用户说"转换微信贴图"时，首先判断用户是否已经提供了贴图内容：

**如果用户已提供标题+内容**（如"贴图1 ← 《标题》→ 数据点 → 根据这个写贴图"），跳过模式询问，直接进入步骤2（内容审核优化）。

**⚠️ 拦截红线：如果用户说"方案A"/"你提供信息我来写"等选择性回复，必须等待用户实际提供内容后再进入步骤2。绝对不能在用户未确认内容来源时就输出完整草稿。**

**如果用户未提供内容**，则询问：

> **是否需要总结前序对话内容？**
> 
> 1. **总结模式**：我将总结我们之前的对话，提炼核心要点
> 2. **直接模式**：使用你接下来输入的内容作为贴图文案

**用户选择总结模式时**：
- 全面总结用户与AI的沟通内容
- 提供 **2-3个不同风格** 的总结方案
- 每个风格都要 **分条陈述**，快速抓住眼球
- **关键原则**：该强调的地方一定要强调，该扩写的地方一定要扩写，不要简单罗列
- 等待用户确认选用哪个风格

**用户选择直接模式时**：
- 等待用户输入贴图文案内容
- 直接进入步骤2

**⚠️ 内容完整性检查**：
当用户提供的主题涉及多人物/多机构（如活动嘉宾、会议参与者、公司名单等），必须进行多轮搜索确保信息完整：
1. 第一轮搜索：获取核心信息框架
2. 第二轮搜索：补充遗漏的人物/机构
3. 第三轮搜索：验证信息准确性
4. 用户确认：展示完整名单，询问是否需要补充

**示例**：用户说"介绍一下今晚晚宴都有哪些嘉宾"→ 需要搜索"完整名单"、"出席嘉宾"、"企业家名单"等多个关键词，确保不遗漏。

### 步骤 2：内容审核与优化（强制去AI味）

对最终内容进行两遍审核：

#### 第一遍：基础审核
- [ ] 检查语句是否通顺
- [ ] 检查是否有错别字
- [ ] 检查标点符号使用
- [ ] 确保段落清晰易读

#### 第二遍：强制去AI味（核心步骤，必须执行）

**AI味特征识别**：
- ❌ "在快速发展的..."
- ❌ "深入探讨/深入研究"
- ❌ "赋能、助力、优化"
- ❌ "总而言之、综上所述"
- ❌ "值得注意的是"
- ❌ 句子长度过于平均
- ❌ 缺乏个人观点
- ❌ 过于正式的学术腔调
- ❌ "首先...其次...最后..."的机械结构
- ❌ "不是X，而是Y"的机械对比（直接说Y）
- ❌ "说实话"开头的清嗓子
- ❌ 让无生命物体做人类动作（"市场奖励了..."、"数据告诉我们..."）
- ❌ 浮在场景上方的旁观者腔（"没人设计过这个"、"人们倾向于..."）

**⭐ 贴图终稿五维评分门禁（吸收自 stop-slope，v2.4.0 新增）**：

贴图文案定稿前必须做五维评分，总分 < 35/50 不可发布。

**🔴 stop-slop 精修（v2.5.1 新增）**：

七步法粗洗完成后，调用 stop-slop 技能做第二遍精修。详见 `references/stop-slop-workflow.md`。
用户说"去AI味"时，优先走 stop-slop 流程，不要只用七步法。

| 维度 | 问什么 | 评分标准 |
|------|--------|----------|
| **直接性** | 第一句就给干货还是在清嗓子？ | 1=绕弯子，10=开门见山 |
| **节奏感** | 长短句交替还是节拍器式？ | 1=每句一样长，10=呼吸感强 |
| **信任感** | 尊重读者智商吗？ | 1=反复解释，10=信任读者 |
| **真实感** | 像人说的话吗？ | 1=标准AI腔，10=像朋友在聊 |
| **密度** | 有没有废话？ | 1=注水，10=每句都有信息 |

**输出格式**：
```
【贴图评分】
直接性：X/10 | 节奏感：X/10 | 信任感：X/10 | 真实感：X/10 | 密度：X/10
总分：XX/50 → [通过/回炉]
```

**强制去AI味七步法**：

1. **负向词表清洗（必须替换）**
   - "深入探讨" → "聊聊"
   - "赋能" → "帮助"
   - "总而言之" → [直接删除]
   - "此外" → "而且"
   - "值得注意的是" → "说实话"
   - "首先/其次/最后" → 直接删除或改为自然过渡
   - "通过...实现..." → "用...来..."
   - "有助于" → "能帮"
   - "进行" → [删除，如"进行练习"→"练习"]

2. **节奏感注入（强制执行）**
   - 混合短句（3-10字）和长句（20-40字）
   - 允许使用句子片段
   - 不要每句都用连接词开头
   - 直接用主语或动词开始句子
   - **关键**：长短句比例要达到3:7，不能全是长句

3. **观点极化（必须选择立场）**
   - 不要平衡论点（"有利有弊"）
   - 选择一边，坚定辩护
   - 使用强动词："这证明了..."、"真相是..."、"本质就是..."
   - 使用第一人称增加主观性："我觉得..."、"我发现..."

4. **口语化叙事（强制转换）**
   - 使用简单、口语化的表达
   - 自然使用语气词（"嗯"、"说实话"、"其实"、"真的"）
   - 用日常生活的比喻
   - 直接称呼（"你"、"你的"）
   - 加入口语停顿："..."、"——"

5. **添加人味元素（必须包含）**
   - 短句（3-10字）
   - 句子片段
   - 个人经历/观点
   - 情感词汇（"爽"、"崩溃"、"真香"、"焦虑"）
   - 自嘲或幽默

6. **强调与扩写（关键步骤）**
   - **识别核心观点**：找出内容中最有价值的1-3个观点
   - **强制扩写**：每个核心观点必须扩写到3-5句话，不能一句话带过
   - **强调标记**：使用加粗、emoji、重复来强调重点
   - **对比手法**：用"以前...现在..."、"不是...而是..."来强化对比
   - **数据支撑**：如果有数字，一定要突出显示

7. **口语化检查清单（最终审核）**
   - [ ] 是否使用了第一人称
   - [ ] 是否有3个以上的短句（≤10字）
   - [ ] 是否有语气词
   - [ ] 是否有情感词汇
   - [ ] 是否删除了所有"首先/其次/最后"
   - [ ] 是否避免了"通过...实现..."结构
   - [ ] 核心观点是否扩写充分

### 步骤 3：生成小红书风格标题

根据优化后的内容，生成 **3-5个小红书风格标题**：

**标题要求**：
- 必须包含emoji
- 使用小红书热门标题公式
- 突出痛点或利益点
- 制造好奇或共鸣

**小红书标题公式**：

| 公式类型 | 示例 |
|---------|------|
| 数字法 | 🔥3个技巧让你XX |
| 痛点法 | 😭为什么你XX总是失败？ |
| 对比法 | 💡从XX到XX，我只用了30天 |
| 悬念法 | 🤫关于XX，没人告诉你的真相 |
| 共鸣法 | 💔是不是你也觉得XX很难？ |
| 干货法 | 📚XX最全攻略，建议收藏 |
| 反常识 | ⚠️别再XX了！这才是正确做法 |

**标题风格梯度选择**：
当用户需要争议性标题时，提供从震撼到深度的梯度选择：
1. **震撼型**："别再做游戏了，这行已经完了"（慎用，可能过于夸张）
2. **争议型**："AI游戏来了，传统开发者该焦虑吗？"（贴合事实但有争议）
3. **深度型**："当AI接管游戏创作，开发者还剩什么价值？"（引发思考）
4. **短平快**："视频变成可玩的了！AI实时生成剧情"（快速吸引）

**示例输出**：
```
基于你的内容，我为你准备了5个小红书风格标题：

1. 🔥3个技巧让你XX效率翻倍｜亲测有效
2. 😭为什么你XX总是失败？原因找到了
3. 💡从XX小白到高手，我只用了30天
4. 🤫关于XX，没人告诉你的3个真相
5. ⚠️别再XX了！这才是正确打开方式

请告诉我你最喜欢哪个标题？或者你有其他想法？
```

### 步骤 4：生成Markdown文件和文件夹结构

**⚠️ 调用 StickerManager 注意事项**：
- `generate_sticker()` 的 `folder_path` 参数接受字符串，会自动转为 Path
- `save_image_prompts()` 的 `folder_path` 参数**必须传入 `Path` 对象**，传入字符串会报 `TypeError: unsupported operand type(s) for /: 'str' and 'str'`
- 正确写法：`manager.save_image_prompts(folder_path=Path("/path/to/folder"), ...)`

**2026-05-25 格式红线（飞哥纠偏）**：

贴图内容必须做到以下三点，否则会被判定为"排版越来越不行"：

1. **必须加粗关键概念**：每个项目名、核心判断、行动短语都要用 `**` 包裹。不是"偶尔加粗"，是"该加粗的每个地方都加"。检查标准：正文中 `**` 出现不少于 20 对。
2. **必须有清晰的视觉层次**：emoji 分段标题 + 加粗关键句 + 自然段落。不能全部平铺一行带过。每个课至少 2-3 行。
3. **结尾必须有行动号召和标签**：最后一段加粗收束 + `#标签1 #标签2` 格式。

反面案例（2026-05-25，被飞哥批评）：
- 六门课各一行、没有加粗、结尾干巴巴 → "排版越来越不行了...又没有加粗，又没有重点"

正确示例：
```markdown
## 📖 代码理解课

**codegraph** + **Understand-Anything**

不是读文件，是**建心智地图**。看懂代码不是看文件名，是看背后的业务关系。
```

### 步骤 5：配图建议与生成（⭐优化版）

#### 5.0 信息图风格选择（⭐新增步骤）

在生成配图前，必须先选择信息图风格，确保视觉风格与贴图内容、目标受众高度匹配。

**📚 风格库参考**：`{baseDir}/assets/风格信息图检索.md`

**可选风格**（6种）：
1. **高密度信息大图** - 实验室精密手册感 + 波普实验风格，适合干货/数据内容

#### 5.3 生成配图提示词（必须与文章内容强相关）

**核心原则**：提示词内容必须直接来源于文章，并严格遵循选定的信息图风格

**🔴 贴图配图是内容图，不是人物写真（2026-06-09 血泪教训）**：

飞哥反复纠正：贴图配图必须**围绕贴图内容**来设计，不是拍女性写真照。

- ❌ 错误：围绕"女性角色"构建场景 → 生成的是写真照，跟贴图内容无关
- ✅ 正确：围绕"贴图主题"设计信息图 → 女性角色可以作为点缀元素出现，但主角是内容本身
- ❌ 错误：加载 poster-portrait 技能来生成贴图配图 → 会把思路带偏到人物摄影
- ✅ 正确：先理解贴图讲什么，再设计能**可视化表达内容**的配图

**判断标准**：如果把配图单独拿出来，看图的人能猜到贴图在讲什么主题吗？能 → 内容图。不能 → 你在拍写真。

**关键要求**：
1. **图片数量严格匹配**：用户要求几张图，就只生成几张图的提示词，不能多也不能少
2. **比例强制约束**：必须在提示词中反复强调比例要求，确保AI按约定比例输出
3. **风格一致性**：所有图片必须使用选定的 **[风格名称]** 风格
4. **信息图密度要求**：根据风格要求调整（高密度6-7模块，中等密度4-5模块）
5. **生成后自检**：每张图生成后必须检查文字是否正常，特别是中文
6. **敏感词规避（⚠️重要）**：提示词中避免中国政治人物姓名，用英文名或职位代替。如"Trump"而非"特朗普"，"President"而非"国家主席"。云雾API会检测敏感词并返回HTTP 500。
7. **多图拆分策略**：超过15个信息点的对比类内容，拆为4张聚焦图（封面+分组A+分组B+洞察），而非1张巨型图。
8. **🔴 图文一致性验证（新增）**：生成后必须核对图片文字与贴图文案是否一致。vision_analyze 优先；若 502 不可用，用 PaddleOCR 提取图片文字对照原文。若不一致 → 图文不符，直接用 API 重新生成（绕过脚本），详见 `references/direct-api-call-workaround.md`。

**⭐ gpt-image-2 中文文字策略（2026-06-09 更新）**：

gpt-image-2 生成中文文字**容易乱码**，但通过结构化策略可以大幅改善。

**中文高密度信息图成功策略（2026-06-09 实测有效）**：
1. **结构化网格布局 > 叙述性段落**：用显式表格/网格/单元格描述布局（"左侧30%上下两个卡片，半透明底板+霓虹蓝边框"），不用自由排版叙述。网格模式中文成功率达 80%+。
2. **短标签策略**：每个中文标签控制在 **2-4个字**（「发现」「分配」「执行」「手动提示」「人工瓶颈」），不要长句。字越短越不容易乱码。
3. **字间距强调**：prompt 中明确要求"每个字独立清晰，字与字之间有明显间距，字体粗"。
4. **模块有边框分隔**：每个信息模块用明确的边框/卡片分隔，让模型按格子渲染文字。
5. **英文做辅助标签**：主要标签用中文，辅助说明可用英文（如节点下的英文名）。

**失败策略（已验证不可行）**：
- ❌ 叙述性段落 prompt（"画面展示一个关于...的场景"）→ 模型自由发挥，文字全乱
- ❌ 密集长句中文（超过5个连续汉字）→ 粘连、缺字

- ❌ 低密度极简图 —— 用户嫌太简单，"内容太少了"

### ⚠️ Python API 调用注意事项

**`generate_sticker()` 不接受 `output_dir` 参数**。`base_dir` 必须在构造函数中传入：

```python
# ❌ 错误：TypeError: StickerManager.generate_sticker() got an unexpected keyword argument 'output_dir'
manager = StickerManager()
result = manager.generate_sticker(title=..., content=..., output_dir="/custom/path")

# ✅ 正确
manager = StickerManager(base_dir="/custom/path")
result = manager.generate_sticker(title=..., content=...)
```

CLI 方式（`--output-dir`）不受影响。

### ⚠️ macOS 命令注意事项

在 macOS 上默认没有 `python` 命令，必须使用 `python3`：

```bash
# ❌ 错误：会报 command not found (exit 127)
python generate_sticker_images_v2.py ...

# ✅ 正确
python3 generate_sticker_images_v2.py ...
```

### 🔴 配图内容方向必须先确认（2026-06-09 血泪教训）

**铁律**：生图前必须确认配图的**内容方向**，不是风格。飞哥会反复纠正方向。

**典型翻车链路**：

| 默认陷阱 | 问题 | 打破方式 |
| -------- | ---- | -------- |

**铁律**：先读懂内容特征，再选视觉语言。不要让AI的默认审美替你做决定。

### 批量生成策略（2026-05-15 实测有效）

脚本 `generate_sticker_images_v2.py` 会从 Markdown 章节自动生成多张图，但当 API 负载高时，连续请求全部 429。

**有效降级方案**：用 Python 直接调用 API，逐张生成，每张之间等待 20 秒：

```python
import requests, os, base64, time

api_key = "..."  # 从 ~/.ai-ggbond-skills/.env 读取
endpoint = "https://api.openlux.ai/v1/images/generations"
headers = {"Authorization": f"Bearer {api_key}", "Content-Type": "application/json"}

prompts = [
    {"name": "01-封面", "prompt": "..."},
    {"name": "02-美方", "prompt": "..."},
    {"name": "03-中方", "prompt": "..."},
    {"name": "04-对比", "prompt": "..."},
]

for i, p in enumerate(prompts):
    data = {"model": "gpt-image-1", "prompt": p["prompt"], "n": 1, "size": "1024x1024"}
    for attempt in range(3):
        response = requests.post(endpoint, headers=headers, json=data, timeout=180)
        if response.status_code == 200:
            # 保存图片...
            break
        elif response.status_code == 429:
            time.sleep(15 * (attempt + 1))
    if i < len(prompts) - 1:
        time.sleep(20)  # 关键：图片间等待20秒
```

**实测结果**：4张图全部成功，总耗时约 4.5 分钟。无间隔则全部 429。

**支持的模型列表**：
- `gpt-image-2` ⭐（默认，推荐）
- `gpt-image-1`（上一代，稳定）
- `gpt-image-2`（高质量）
- `gemini-2.5-flash-image`（快速）
- `qwen-image-edit-2509`（阿里万相，中文优化）
- `dall-e-3`（OpenAI）
- `flux-1.1-pro`（高质量快速）
- `ideogram-3.0`（文字渲染优秀）
- `doubao-seedream-5-0-260128`（豆包，中文支持好）

**铁律**：贴图不是新闻稿，不是产品说明书，不是价值判断文。是一个普通人发现了好玩意儿，兴致勃勃地分享给朋友。

### 三种错误写法 vs 正确写法

| ❌ 错误风格 | 问题 | ✅ 正确风格 |
|------------|------|------------|
| 新闻稿："Anthropic发布了Claude Fable 5，具备以下能力..." | 冷冰冰，没感情 | "一家公司说'我们做的东西太危险了'，然后还是放出来了" |
| 罗列参数："SWE-Bench 80.3%，FrontierCode 29.3%..." | 数据堆砌，普通人看不懂 | "Stripe拿它迁移了5000万行代码，一天搞定了。人类团队至少两个月" |
| 说教判断："Anthropic在赌...6月22日见分晓" | 读者不需要你告诉他该怎么想 | 删除。让读者自己感受 |

### 写作手法：场景化 > 参数化

**核心原则**：用具体场景让读者"看到"这个东西有多牛，不是用评测分数"告诉"他。

**正确示例**（飞哥确认通过）：
- "看截图就能写代码。你给它一张网页截图，它能直接把前端源码重建出来"
- "打游戏打通关了。拿《口袋妖怪火红》的原始画面给它看，纯看屏幕截图就通关了"
- "自己干完会检查一遍。花36小时干完了GPT-5.5要4天才能出的结果"

**错误示例**（被飞哥退回）：
- "在软件工程、知识工作和视觉任务上表现最佳"
- "任务越复杂，差距越大"
- "Anthropic在赌：用户愿为'够强+够安全'买单"

### 结尾红线：不要说教

- ❌ "Anthropic在赌一件事..." — 你在替读者下判断
- ❌ "6月22日见分晓" — 你在做预测
- ❌ "到时候谁在裸泳，一目了然" — 你在摆姿态
- ✅ 直接结束，不需要总结性判断。数据和场景已经说明一切
- ✅ 如果一定要收尾，用事实（"6月22日前免费，之后付费"），不用观点

### 去AI味：优先用stop-slop技能

飞哥会主动要求"去AI味"时加载stop-slop技能。贴图技能内置的七步法是简化版，stop-slop规则更系统。

**stop-slop核心检查清单**（贴图场景适用）：
1. 有没有副词（-ly、真的、其实、确实）？砍
2. 有没有em-dash（——）？改逗号或句号
3. 有没有"不是X，而是Y"的机械对比？直接说Y
4. 有没有pull-quote感的金句（"安全没有满分"）？砍
5. 有没有模糊声明（"Anthropic在赌..."）？说具体动作
6. 有没有旁观者腔（"Nobody designed this"）？改成"你"
7. 句子长度太均匀？长短交替
8. 三连短句堆叠？打断节奏

**4. 比例控制技巧**
