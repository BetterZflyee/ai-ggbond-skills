# 微信贴图生成器

将任意内容转换为适合微信朋友圈/小红书传播的贴图文案，包含完整的文案优化、标题生成和配图建议。

## Script Directory

将本文件目录解析为 `{baseDir}`，脚本统一使用 `{baseDir}/scripts/*.py`：

| Script | Purpose |
|--------|---------|
| `scripts/sticker_manager.py` | 创建标准目录与 Markdown |
| `scripts/generate_sticker_images_v2.py` | 生成贴图配图（推荐） |
| `scripts/generate_images.py` | 兼容版配图脚本 |
| `scripts/config_loader.py` | 配置加载工具（用户级/项目级） |

## 核心工作流程（⭐严格按照以下步骤执行）

**⚠️ 重要：必须严格按照以下6个步骤顺序执行，不能跳过任何步骤**

```
步骤1: 确认内容来源 → 步骤2: 内容审核优化 → 步骤3: 生成标题
    ↓
步骤4: 创建文件结构 → 步骤5: 选择风格+确认比例 → 步骤6: 生成配图
```

### 步骤 1：确认内容来源

当用户说"转换微信贴图"时，首先询问：

> **是否需要总结前序对话内容？**
> 
> 1. **总结模式**：我将总结我们之前的对话，提炼核心要点
> 2. **直接模式**：使用你接下来输入的内容作为贴图文案

**用户选择总结模式时**：
- 全面总结用户与AI的沟通内容
- 提供 **2-3个不同风格** 的总结方案
- 每个风格都要 **分条陈述**，快速抓住眼球
- **关键原则**：该强调的地方一定要强调，该扩写的地方一定要扩写，不要简单罗列
- 等待用户确认选用哪个风格

**用户选择直接模式时**：
- 等待用户输入贴图文案内容
- 直接进入步骤2

**⚠️ 内容完整性检查**：
当用户提供的主题涉及多人物/多机构（如活动嘉宾、会议参与者、公司名单等），必须进行多轮搜索确保信息完整：
1. 第一轮搜索：获取核心信息框架
2. 第二轮搜索：补充遗漏的人物/机构
3. 第三轮搜索：验证信息准确性
4. 用户确认：展示完整名单，询问是否需要补充

**示例**：用户说"介绍一下今晚晚宴都有哪些嘉宾"→ 需要搜索"完整名单"、"出席嘉宾"、"企业家名单"等多个关键词，确保不遗漏。

### 步骤 2：内容审核与优化（强制去AI味）

对最终内容进行两遍审核：

#### 第一遍：基础审核
- [ ] 检查语句是否通顺
- [ ] 检查是否有错别字
- [ ] 检查标点符号使用
- [ ] 确保段落清晰易读

#### 第二遍：强制去AI味（核心步骤，必须执行）

**AI味特征识别**：
- ❌ "在快速发展的..."
- ❌ "深入探讨/深入研究"
- ❌ "赋能、助力、优化"
- ❌ "总而言之、综上所述"
- ❌ "值得注意的是"
- ❌ 句子长度过于平均
- ❌ 缺乏个人观点
- ❌ 过于正式的学术腔调
- ❌ "首先...其次...最后..."的机械结构

**强制去AI味七步法**：

1. **负向词表清洗（必须替换）**
   - "深入探讨" → "聊聊"
   - "赋能" → "帮助"
   - "总而言之" → [直接删除]
   - "此外" → "而且"
   - "值得注意的是" → "说实话"
   - "首先/其次/最后" → 直接删除或改为自然过渡
   - "通过...实现..." → "用...来..."
   - "有助于" → "能帮"
   - "进行" → [删除，如"进行练习"→"练习"]

2. **节奏感注入（强制执行）**
   - 混合短句（3-10字）和长句（20-40字）
   - 允许使用句子片段
   - 不要每句都用连接词开头
   - 直接用主语或动词开始句子
   - **关键**：长短句比例要达到3:7，不能全是长句

3. **观点极化（必须选择立场）**
   - 不要平衡论点（"有利有弊"）
   - 选择一边，坚定辩护
   - 使用强动词："这证明了..."、"真相是..."、"本质就是..."
   - 使用第一人称增加主观性："我觉得..."、"我发现..."

4. **口语化叙事（强制转换）**
   - 使用简单、口语化的表达
   - 自然使用语气词（"嗯"、"说实话"、"其实"、"真的"）
   - 用日常生活的比喻
   - 直接称呼（"你"、"你的"）
   - 加入口语停顿："..."、"——"

5. **添加人味元素（必须包含）**
   - 短句（3-10字）
   - 句子片段
   - 个人经历/观点
   - 情感词汇（"爽"、"崩溃"、"真香"、"焦虑"）
   - 自嘲或幽默

6. **强调与扩写（关键步骤）**
   - **识别核心观点**：找出内容中最有价值的1-3个观点
   - **强制扩写**：每个核心观点必须扩写到3-5句话，不能一句话带过
   - **强调标记**：使用加粗、emoji、重复来强调重点
   - **对比手法**：用"以前...现在..."、"不是...而是..."来强化对比
   - **数据支撑**：如果有数字，一定要突出显示

7. **口语化检查清单（最终审核）**
   - [ ] 是否使用了第一人称
   - [ ] 是否有3个以上的短句（≤10字）
   - [ ] 是否有语气词
   - [ ] 是否有情感词汇
   - [ ] 是否删除了所有"首先/其次/最后"
   - [ ] 是否避免了"通过...实现..."结构
   - [ ] 核心观点是否扩写充分

### 步骤 3：生成小红书风格标题

根据优化后的内容，生成 **3-5个小红书风格标题**：

**标题要求**：
- 必须包含emoji
- 使用小红书热门标题公式
- 突出痛点或利益点
- 制造好奇或共鸣

**小红书标题公式**：

| 公式类型 | 示例 |
|---------|------|
| 数字法 | 🔥3个技巧让你XX |
| 痛点法 | 😭为什么你XX总是失败？ |
| 对比法 | 💡从XX到XX，我只用了30天 |
| 悬念法 | 🤫关于XX，没人告诉你的真相 |
| 共鸣法 | 💔是不是你也觉得XX很难？ |
| 干货法 | 📚XX最全攻略，建议收藏 |
| 反常识 | ⚠️别再XX了！这才是正确做法 |

**标题风格梯度选择**：
当用户需要争议性标题时，提供从震撼到深度的梯度选择：
1. **震撼型**："别再做游戏了，这行已经完了"（慎用，可能过于夸张）
2. **争议型**："AI游戏来了，传统开发者该焦虑吗？"（贴合事实但有争议）
3. **深度型**："当AI接管游戏创作，开发者还剩什么价值？"（引发思考）
4. **短平快**："视频变成可玩的了！AI实时生成剧情"（快速吸引）

**示例输出**：
```
基于你的内容，我为你准备了5个小红书风格标题：

1. 🔥3个技巧让你XX效率翻倍｜亲测有效
2. 😭为什么你XX总是失败？原因找到了
3. 💡从XX小白到高手，我只用了30天
4. 🤫关于XX，没人告诉你的3个真相
5. ⚠️别再XX了！这才是正确打开方式

请告诉我你最喜欢哪个标题？或者你有其他想法？
```

### 步骤 5：配图建议与生成（⭐优化版）

#### 5.0 信息图风格选择（⭐新增步骤）

在生成配图前，必须先选择信息图风格，确保视觉风格与贴图内容、目标受众高度匹配。

**📚 风格库参考**：`{baseDir}/assets/风格信息图检索.md`

**可选风格**（6种）：
1. **高密度信息大图** - 实验室精密手册感 + 波普实验风格，适合干货/数据内容
2. **复古波普网格** - 70年代复古波普艺术 + 瑞士网格系统，适合对比/清单内容
3. **文件夹/档案风格** - 新拟物化文具风格，适合方法论/流程内容
4. **打印热敏纸风格** - 现代票据美学，适合步骤/清单内容
5. **复古手帐风格** - 复古剪贴簿美学，适合经验分享/温馨内容
6. **矢量插图风格** - 扁平化矢量插画，适合概念解释/教育内容

**风格选择流程**：
```
分析贴图内容特征（主题、受众、调性）
    ↓
自动匹配推荐2-3款合适风格
    ↓
展示推荐风格及理由
    ↓
用户确认或要求重新推荐
    ↓
所有配图统一使用选定风格
```

**风格推荐规则**：

| 贴图类型 | 推荐风格 | 理由 |
|---------|---------|------|
| **干货清单** | 高密度信息大图、复古波普网格 | 信息密度高，适合展示要点 |
| **效率工具** | 复古波普网格、文件夹风格 | 对比清晰，适合工具评测 |
| **经验分享** | 复古手帐、打印热敏纸 | 亲切温暖，适合个人故事 |
| **入门教程** | 打印热敏纸、矢量插图 | 清晰易懂，适合新手 |
| **数据报告** | 高密度信息大图、矢量插图 | 专业感强，适合数据可视化 |

#### 5.2 确认配图方案（⭐必须确认图片比例）

**⚠️ 关键步骤：必须向用户确认图片比例**

询问用户：
- 确认配图张数
- 确认每张图的类型（信息图/插图）
- **已确认风格**：[显示选定的风格名称]
- **⭐关键：确认图片比例**

**默认比例：16:9横版**（适合信息密度高的内容）

**可选比例**：
- **16:9横版**（默认）- 适合信息密度高的内容、数据展示
- **1:1正方形** - 适合小红书/朋友圈，视觉聚焦
- **3:4竖版** - 适合详细展示、长内容

**询问话术**：
```

🎨 **风格**：[已选风格]
📐 **比例**：默认16:9横版

是否需要调整？
- 输入"1:1"改为正方形
- 输入"3:4"改为竖版

```

- 如需更换风格，可输入"更换风格"重新选择

#### 5.3 生成配图提示词（必须与文章内容强相关）

**核心原则**：提示词内容必须直接来源于文章，并严格遵循选定的信息图风格

**关键要求**：
1. **图片数量严格匹配**：用户要求几张图，就只生成几张图的提示词，不能多也不能少
2. **比例强制约束**：必须在提示词中反复强调比例要求，确保AI按约定比例输出
3. **风格一致性**：所有图片必须使用选定的 **[风格名称]** 风格
4. **信息图密度要求**：根据风格要求调整（高密度6-7模块，中等密度4-5模块）
5. **生成后自检**：每张图生成后必须检查文字是否正常，特别是中文
6. **敏感词规避（⚠️重要）**：提示词中避免中国政治人物姓名，用英文名或职位代替。如"Trump"而非"特朗普"，"President"而非"国家主席"。云雾API会检测敏感词并返回HTTP 500。
7. **多图拆分策略**：超过15个信息点的对比类内容，拆为4张聚焦图（封面+分组A+分组B+洞察），而非1张巨型图。

为每张图片生成详细的提示词，保存到 `images/prompt.md`：

```markdown
# 配图提示词

## 图片1：[标题]
```

### 批量生成策略（2026-05-15 实测有效）

脚本 `generate_sticker_images_v2.py` 会从 Markdown 章节自动生成多张图，但当 API 负载高时，连续请求全部 429。

**有效降级方案**：用 Python 直接调用 API，逐张生成，每张之间等待 20 秒：

```python
import requests, os, base64, time

api_key = "..."  # 从 ~/.ai-ggbond-skills/.env 读取
endpoint = "https://yunwu.ai/v1/images/generations"
headers = {"Authorization": f"Bearer {api_key}", "Content-Type": "application/json"}

prompts = [
    {"name": "01-封面", "prompt": "..."},
    {"name": "02-美方", "prompt": "..."},
    {"name": "03-中方", "prompt": "..."},
    {"name": "04-对比", "prompt": "..."},
]

for i, p in enumerate(prompts):
    data = {"model": "gpt-image-1", "prompt": p["prompt"], "n": 1, "size": "1024x1024"}
    for attempt in range(3):
        response = requests.post(endpoint, headers=headers, json=data, timeout=180)
        if response.status_code == 200:
            # 保存图片...
            break
        elif response.status_code == 429:
            time.sleep(15 * (attempt + 1))
    if i < len(prompts) - 1:
        time.sleep(20)  # 关键：图片间等待20秒
```

**实测结果**：4张图全部成功，总耗时约 4.5 分钟。无间隔则全部 429。

## 🔴 生图链路与模型选择红线（最高优先级）

### 链路路由策略

当云雾 API 生图失败（尤其 429 上游饱和）或用户提供新的中转链路时，先参考 `references/yunwu-image-routing.md`。关键原则：
- 不应默认强制禁用系统代理/VPN；只有用户明确要求或设置 `YUNWU_DISABLE_PROXY=1` 时才禁用代理。
- 生图链路应支持三线路：`https://yunwu.ai`、`https://api.apiplus.org`、`https://api3.wlai.vip`。
- 当前贴图生成端点为 `/v1/images/generations`；图片编辑为 `/v1/images/edits`。
- Markdown 章节多于用户确认张数时，必须限制生成数量（如 `--max-images 4`），不要自动按所有章节超量生成。
- 429 时应切换 base_url、拉长间隔、逐张生成；不要连续硬冲同一上游。

### 模型选择红线

**绝对禁止擅自更换模型。** 遇到API/模型问题时：
1. **立即停止生成**
2. **向用户报告具体问题**（429、超时、敏感词等）
3. **等待用户决定**用什么模型、是否重试、是否降级

❌ 错误做法：遇到 gpt-image-2 的 429 错误后，自作主张切换到 gpt-image-1
✅ 正确做法：停下来告诉用户"gpt-image-2 当前负载饱和（429），你想等一会儿重试，还是换其他模型？"

## User-Learned Best Practices & Constraints

**7. 提示词语言规范**
- 用户要求：**所有文字必须是简体中文**，包括人名、公司名、职位
- 人名翻译：马斯克（Musk）、库克（Cook）、黄仁勋（Huang）、雷军（Lei Jun）等统一用中文
- 公司名翻译：特斯拉（Tesla）、苹果（Apple）、英伟达（Nvidia）、小米（Xiaomi）等统一用中文
- ❌ 错误：`Musk: Tesla / SpaceX CEO`
- ✅ 正确：`马斯克：特斯拉 / 太空探索 首席执行官`

**8. 图片数量策略**
- 用户偏好**多张分图**而非1张大图（信息密度更可控）
- 推荐：封面1张 + 内容模块2-3张 + 总结/洞察1张 = 通常4张
- 提示词中每张图独立生成，不要合并为一张

**9. 云雾API常见问题**
| 问题 | 表现 | 处理方式（必须告知用户） |
|------|------|------------------------|
| 429 负载饱和 | "当前分组上游负载已饱和" | 停止，告知用户，建议等待或换端点 |
| 500 敏感词 | "sensitive words detected" | 停止，告知用户，可能需要调整提示词 |
| 超时 | 连接超时 >180s | 停止，告知用户，可能是网络或API问题 |

### 从实际使用中学习的经验

**1. 标题设计梯度**
- 用户偏好有争议性但能引发讨论的标题
- 提供梯度选择：震撼型→争议型→深度型→短平快型
- 避免过于夸张（如"行业已死"），应贴合事实但有争议

**2. 信息图密度控制**
- 高密度信息图控制在6-10个模块，确保可读性
- 平衡信息密度与视觉呼吸感，避免过度拥挤
- 图文并茂时图像占比不低于40%

**3. 中文内容生成最佳实践**
- 优先使用 `qwen-image-edit-2509` 模型生成中文内容
- 该模型中文支持最佳，无乱码，字形准确
- 提示词中必须强调"所有文字必须是简体中文，无乱码"

**4. 比例控制技巧**
- **默认16:9横版**，必须向用户确认后再生成
- 在提示词开头和结尾都强调比例要求
- 使用标准尺寸：**16:9=1792x1024（默认）**, 1:1=1024x1024, 3:4=1024x1365
- 生成后必须验证比例是否正确

**5. 文件输出标准化**
- 默认使用 `/Users/admin/SuperIp/stickers/`，支持自定义输出目录
- 文件夹命名必须包含时间戳和标题
- Markdown文件与文件夹同名，便于管理和查找
- images子文件夹结构统一

**6. 视觉冲击力设计**
- 使用对比鲜明的配色（电光蓝、热粉、亮黄、霓虹绿）
- 粗黑线描边（4-5px）增强复古波普感
- 添加动态元素：运动线、星爆效果、放射状背景
- 层级化字体：标题48px+、数字40px+、正文24px

**7. 常见问题解决**
| 问题 | 解决方案 |
|-----|---------|
| 标题过于夸张或平淡 | 提供梯度选择，让用户决定争议程度 |
| 信息图拥挤 | 控制模块数量，确保15-20%留白 |
| 中文乱码 | 使用qwen-image-edit-2509模型 |
| 比例不符 | **默认16:9，必须向用户确认后再生成**，提示词中反复强调比例要求 |
| 视觉冲击力不足 | 增加图像占比，使用对比色，添加动态元素 |
| 文件路径混乱 | 使用标准化命名格式和时间戳 |
