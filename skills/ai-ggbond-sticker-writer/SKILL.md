# 公众号贴图与信息卡

把已有内容做成可阅读、可核对、可复用的图文交付。当前指令优先；用户已给主题、张数、风格或比例时直接执行，不重复询问已确定的事项。仅升级技能时改进能力与样稿，不擅自发布内容。

## 先选交付场景

| 场景 | 输出与衔接 |
|---|---|
| 公众号原生贴图／图文帖 | 短标题、纯文本正文、有顺序的图片；`newspic-bundle.json` 交现有发布器 |
| 公众号长文中的信息卡 | 已有正文保持完整；图片和适用的步骤、对比、时间线、数据交给 `ai-ggbond-wechat-layout`，输出内联样式 HTML |
| 一篇内容拆为连续多图 | 每页承担一个阅读任务，标题、事实、顺序共用一个计划；可作为原生贴图或长文插图 |
| 完整长图 | 复用 `ai-ggbond-long-image-generator` 的布局参考和可用生成方式，检查手机可读性；不自动切为另一模型 |

原生贴图的第一张图片承担封面；长文的封面放元信息，不自动重复到正文。两类内容不混用 HTML 和纯文本；500 字是用户的短贴图编辑预算，非所有公众号内容的统一平台上限。详细范围见 [能力与场景](references/capabilities-and-scenes.md)。

## 内容与信源

从用户提供的文本、链接、对话或指定资料开始。新闻、产品参数和人物经历查原始来源，记录日期、数字、引用和不确定项；不可把历史案例中的数字当新事实。非官方实录区分事件发生、主题可信和逐字准确。见 [贴图写作与信源](references/editorial.md)。

默认用普通人分享发现的语气，先说具体场景和事实。保留用户的判断，不虚构“我用过”“我现场看过”。多事件以真实关联或递进问题组织，无证据时不制造因果。给标题候选和推荐理由；用户已选标题就沿用。选题/标题候选不作为额外批准关卡。

短贴图默认标题、正文、标签合计不超过 500 个 Unicode 字符，并单列正文长度和 UTF-16 长度供核对。标签留在正文，图片文本清单不含标签。原生正文不发送 `##`、`**` 等 Markdown 标记；内部编辑稿可以保留结构标注。用户指定篇幅、平台或仅要文案时按其要求调整。

## 视觉与图片

先读 `/Users/admin/SuperIp/design-kb/05-usage/长期设计要求.md`。沿用 2026-11-16 已确认的默认：商业杂志编辑风，米白纸感、黑字、单一强调色、大留白；科技风和高密度保留为用户点选方案，不因题材是 AI 自动启用。按内容判断需要多少页，张数已定则严格遵守。信息超载优先调整分组，不靠缩小图中文字塞入更多模块。见 [商业杂志默认规范](references/editorial-magazine-sticker-spec.md)。

保留 AI朱朱侠角色和主题精灵／女性角色能力，用户要求角色时再使用，角色要解释主题，不能变成无关写真。保留用户指定的英文产品名或双语需求，不机械翻译品牌。默认中文提示词，简短说明构图，另附精确上图文字。新视觉方向先做一张样图核对；已确定的方向与整套生成授权直接沿用，不重复设批准关卡。见 [视觉与组件](references/visual-system.md)。

调用当前环境可用的生图工具：Codex 使用内置 image_gen；Hermes 使用当前 Profile 已配置且获授权的图像链路。用户指定工具/模型优先，不自动换服务、模型或代理。外部兼容脚本保留给已配置的环境；不把外部 API 设为 Codex 默认。编辑图片用当前环境的图像编辑工具，不能用本地占位图冒充模型成图。见 [生图与素材处理](references/image-production.md)。

## 计划、构建与复用

维护一份 `plan.json`：正文、来源、图片顺序、每页任务、精确文字、风格、比例和已生成素材路径。结构见 [计划格式](references/bundle-schema.md)。项目沿用 `/Users/admin/SuperIp/stickers/时间戳-标题/`，已有项目原位新增版本目录，保留原稿和原图。

```bash
python3 "<skill-dir>/scripts/sticker_pack.py" build \
  --input "/path/to/plan.json" --out "/path/to/_delivery/v1"
python3 "<skill-dir>/scripts/sticker_pack.py" audit "/path/to/_delivery/v1"
```

构建器离线执行，不生成图片、不访问账号；产出正文、逐页提示词、图片顺序、质量报告、手机预览、原生交接包及可选长文输入。缺图保留“待生成”，比例不符、文字过小或未核对会提示，不能报告贴图已经完成。图片以哈希绑定核对记录，换图后不能沿用旧检查。

长文复用采用 `layout-input.json`，交同级 `ai-ggbond-wechat-layout/scripts/layout.py`。人物时间线、流程、比较和准确数据优先用可编辑组件；情景、角色和视觉叙事保留图片。原生贴图需要图片时仍生成对应图片，不能以 HTML 替代成图。

## 交付与验收

逐张查看原图和 320/375px 下的显示，核对中文、品牌名、数字、单位、页序、比例与封面裁切。图内字号估计与 OCR 仅辅助检查；未知则记录未测，不能写成全部通过。自动报告、视觉核对、草稿读回、手机微信分别记录。

用户说“做成贴图”且已授权生图时，完成文案后接着生成图片。最终提供可见的成图、可复制的纯文本、资料来源、预览和文件入口；Codex 用绝对路径 Markdown 图片展示，Hermes 按当前通道支持的媒体方式交付，不能只给磁盘路径。

用户要求推送时才调用现有 `ai-ggbond-post-to-wechat`。原生贴图用本模块的 JSON，长文用精排 `article.html`；先检查元信息和图片顺序，沿既有授权写入并读回。不把历史 45166 或菜单失效推断为当前账号必然不可用，也不把本地 dry-run 称为上传成功。见 [发布交接](references/platform-handoff.md)。
