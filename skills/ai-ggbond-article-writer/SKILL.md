## 内容创作方法论升级（2026-05-19，v2.2.0，参考朱朱侠内部分享）

这部分来自对公众号文章《内容创作方法论总结（朱朱侠内部分享）》的学习吸收，已转化为 AI朱朱侠写作规则。核心不是照搬对方内容，而是把方法论内化成飞哥公众号文章的生产标准。

### 总公式

```text
好内容 = 信息获取 × 角度选择 × 节奏化创作 × 正向价值观
```

其中权重排序：
- **找角度最重要**：约占内容成败 60%。
- **信息获取是底盘**：决定素材广度和认知厚度。
- **创作呈现是放大器**：决定读者能否读完、记住、转发。
- **正向价值观是生死线**：决定账号长期安全和信任资产。

### 1）信息获取：不要只看 AI 圈

- 获取信息不等于追热点，也包括想法、日常观察、跨领域知识、生活里的细节。
- 如果只看 AI 新闻，文章容易干巴巴、没灵魂、角度单一。
- 需要像投资组合一样配置信息源：AI/技术只是主仓，喜剧、电影、历史、商业、心理学、日常生活观察是卫星仓。
- 写 AI 文章时，要主动引入跨领域类比：喜剧节奏、电影叙事、历史周期、商业结构、人性观察、建筑空间感等。

实操要求：每篇深度文在写作前，除了技术/行业资料，至少补充 2 类跨领域素材或类比来源。

### 2）找角度：拒绝第一直觉，寻找反差与陌生化

- 角度的关键词是：**反差**。
- 对 AI朱朱侠公众号趋势文，标题要优先突出“我”的判断，不要写成冷冰冰的新闻标题或行业报告标题。优秀公式：`我越来越确定：[对象]的下一站，不是[A]，而是[B]`；副标题再用“从[事件]，看懂[本质转折]”承接事实锚点。详见 `references/2026-05-21-antigravity-title-and-image-workflow.md`。
- 好角度要做到：**情理之中，预料之外**。
- “陌生化”的本质：不是让读者认识一个新东西，而是让读者对熟悉事物产生新感知。
- 拿到选题后，不要急着写。先列出所有人都会写的常规角度，再主动排除，去找那个“别人没想到，但合情合理”的方向。

实操要求：正式写作前必须做“角度排除表”：
```text
常规角度 1：为什么普通？为什么不用？
常规角度 2：为什么普通？为什么不用？
常规角度 3：为什么普通？为什么不用？
最终选择的陌生化角度：一句话说明反差在哪里。
```

### 3）创作：要有故事感和升番，不要写成说明书

- 内容的本质不是信息搬运，而是把信息加工成能直接端给读者的“成品”。
- 不能把资料像“菜市场买来的鱼”直接扔给读者，要把它做成一道菜。
- 好文章要有故事弧线：起、承、转、升，而不是平铺直叙。
- 学喜剧里的“升番”：第一层给判断，第二层给反差，第三层给更大的认知跃迁。
- 每 800-1200 字应出现一次“认知升级”：不是重复论点，而是把读者带到更高一层理解。

实操要求：大纲阶段必须标出 3 个以上“升番点”：
```text
升番 1：从现象到判断
升番 2：从判断到机制
升番 3：从机制到行动/资产/商业结果
```

### 4）正向价值观：不懂不说，不碰敏感，保持弱者思维

- 不懂的东西不要硬讲，不要为了显得懂而造假。
- 不碰政治、社会对立、攻击性人群标签等高风险敏感话题。
- 保持“弱者思维”：少装、少秀、少居高临下，多承认局限，多用“我观察到/我踩过坑/我现在的判断是”。
- 老子说：“天下莫柔弱于水，而攻坚强者莫之能胜。” 飞哥文章应有锋利判断，但姿态不要傲慢。

### 5）运营指标：写完要问它凭什么被转发

公众号内容不只看阅读量，更看：
- 常读用户数
- 赞阅比
- 转阅比
- 完读率

写完初稿后必须自问：
```text
读者为什么要看完？
读者为什么要点赞？
读者为什么要转发给别人？
这篇文章提供的是信息，还是一个能被复述的故事/判断？
```

## 飞哥配图信息密度偏好（2026-05-27确认，2026-05-28补充学术高密度例外）

### 默认风格：图形优先

适用于：观点类、方法论、个人故事、行业观察类文章。

- **图形优先，文字辅助**：信息图默认目标为 **85% 图形 + 15% 文字**。用图标、箭头、前后对比图形、视觉隐喻讲故事，文字退到关键标签和微标注。
- **每张图应可"一眼看懂"**：读者扫一眼就能理解核心对比或流程，不需要一行行读文字。
- **禁止文字墙**：不要在信息图里放超过 3 行连续文字。用视觉元素（图标对比、流程图、环形辐射图、前后对照）替代文字叙述。

### 例外风格：学术高密度信息图（2026-05-28确认）

**触发条件**：文章属于**技术技能展示**（如开源工具介绍、技术原理讲解）、**架构拆解**、**引擎分层**、**管线流程对比**类内容时，使用学术风高密度信息图。

适用：技术拆解、技能展示、开源工具介绍、架构对比类文章。

- **高密度文字+技术参数**：图形:文字约 40:60 ~ 50:50。每张图需包含公式/伪代码、性能指标（如 0.05s CPU）、输入/输出规格、具体模型名。
- **学术论文Figure风格**：白底黑字、严谨排版、技术标注、分级信息架构。
- **读者需"细读"**：不是扫一眼的图，而是停下来看的技术参考图。

**识别信号**：用户说"太简单了"、"换成实际讲解示意图"、"学术风"、"高密度信息图"、"像论文Figure那样"时，立即切换到此风格。

- **不要插入阅读元信息行**：禁止生成 `📊 约 xxxx 字 · 建议阅读 x 分钟 · 点击右上角🎧可听阅`。飞哥不需要这种模板化公众号提示，它会暴露工具痕迹，破坏文章开场气质。
- **不要给正文图片加图注**：禁止在每张图下方显示 `全文核心信息图：...`、`配图：...`、`图片说明：...` 这类 figcaption。图片只作为视觉断点和理解辅助，不能在正文里反复解释自己。
- **不要把 alt 文本渲染成可见文字**：Markdown/HTML 中可以保留 alt 方便上传和可访问性，但发布版 HTML 必须隐藏图注，不得把 alt 原样显示到图片下面。

### P0 洁净度原则：卡片不要叠卡片

- **引用卡片和独立金句卡片不要连续出现**。如果一个观点后面已经紧跟引用卡片，就不要再把前一句做成独立金句卡片。
- **同一个语义落点只能选择一种视觉强调**：正文加粗、独立金句卡片、引用卡片三选一，最多二选一但必须有足够文本缓冲；不要“金句卡片 + 引用卡片 + 加粗解释”三连。
- **引用卡片优先承载有出处的话**，独立金句卡片优先承载本文原创核心判断；两者相邻时，默认取消独立金句卡片，改成正文自然加粗。

错误示例：
```text
[独立金句卡片]
真正改变行业的工具，往往不是一开始最完美的那个，而是第一个把旧流程压缩掉的那个。

[引用卡片]
《创新者的窘境》作者克莱顿·克里斯坦森提醒我们：破坏性创新往往从“不够完美”的边缘开始。
```

正确处理：
```text
真正改变行业的工具，往往不是一开始最完美的那个，而是第一个把旧流程压缩掉的那个。

[引用卡片]
**《创新者的窘境》作者克莱顿·克里斯坦森提醒我们：破坏性创新往往从“不够完美”的边缘开始。**
```

### 发布前强制自检

发布前必须检查 HTML：
- `建议阅读`、`点击右上角`、`全文核心信息图`、`配图：`、`图片说明`、`figcaption` 不得出现在正文可见区域。
- 独立金句卡片数量不超过 3 个；若文章引用卡片多于 2 个，独立金句卡片最多 1 个。
- 任意两个视觉重组件之间至少间隔 2 个自然段：图片、引用卡片、独立金句卡片、CTA 卡片都算重组件。
- 若不确定干不干净，优先删除装饰，保留正文。**公众号排版不是展示技能的地方，而是降低读者理解摩擦的地方。**

## 核心原则

### 必须严格遵守的 7 个要点

1. **第一人称叙述**
   - 用「我和专家大佬轻松聊天」的视角写作：分享真实的交流经历、踩坑故事、实战心得
   - 这是Native超级个体的个人分享，不是官方文档
   - 基于真实经历写作，不编造不真实的场景
2. **观点鲜明但有理有据**
   - 敢于表达立场：「我认为 A 比 B 更适合这个场景」
   - 但必须给出理由和依据，不能空口说
3. **实战导向**
   - 要先讲自己的认知，以及在大佬沟通过程中达成共识后的独到见解
   - 尽量用互联网上最近发生的事情，用真实案例和场景说话
   - **必须有真实的使用场景**:不要堆数据、列参数，而是用"振聋发聩的看法和认知"来展示价值
   - 展示具体的使用过程和结果，包括成功和失败的案例
   - 如果是问题或者建议，最好能和大佬一起给出应对问题的策略，然后告诉普通人要怎么做
4. **个人IP自然融入**
   - **不要刻意**：不在文章开头或结尾生硬地自我介绍，而是在内容中自然带出
   - **场景化呈现**：
     - 分享踩坑经历：「我在折腾这个项目的时候，踩过一个坑...」
     - 展示工作流：「我自己平时用这套工作流处理类似的需求...」
     - 提及圈内交流：「上周和圈子里的大佬聊到这个话题...」
     - 表达个人偏好：「我自己更喜欢用A而不是B，因为...」
   - **价值先行**：先提供有价值的内容，IP形象通过内容质量自然建立
   - **保持一致性**：用「AI朱朱侠」的口吻贯穿全文，但不用刻意强调这个名字
- **文章配图是强制要求**：
   - **主题封面图**：每篇文章必须生成一张主题封面图，比例2.35:1（2350x1000px）；风格按文章内容选择，不要一刀切
   - **深度信息图**：每篇文章必须生成一张深度信息图，比例**16:9横版**（1792x1024px），放在文章开头，必须包含文章完整核心内容
   - **主体内容配图**：推荐5-8张，长文可提升到10-12张；比例**统一16:9横版**（1792x1024px），从36种信息图类型中选择
   - **飞哥配图偏好（重要）**：公众号文章和内容配图通常偏好根据内容选择**手绘图或信息图**；不要默认拒绝手绘，也不要固定只用科技蓝扁平矢量。技术/商业/架构类可用科技蓝结构图，但如果飞哥反馈科技蓝“不讨喜”，优先改用 **Anthropic/Claude 官网气质的暖色科技风**：暖米白/羊皮纸底色、深炭黑文字、陶土橙/赭石棕/鼠尾草绿/暖灰辅助色，高留白、克制、学术感、可信感。观点/方法论/个人工作流类可用手绘信息图；一篇文章可混合“手绘信息图 + 专业结构图”。
   - 图片文字使用简体中文，必须保证清晰、不变形、无重影、无乱码
   - Pillow 仅用于轻量水印叠加，禁止用 Pillow 主生成配图内容
   - 封面图与章节配图默认使用中低信息密度，保持干净整洁；信息图可高密度但必须结构清晰且不重复
   - **文件大小限制**：所有配图不超过5MB（确保快速加载）
6. **链接使用纯文本格式**
   - ❌ 错误：`[官网](https://example.com/)`
   - ✅ 正确：`官方网站：https://example.com/`

## 完整工作流程

### 步骤 1：保存需求Brief

保存创作需求到 `_briefs/[项目名]-需求brief.md`，明确以下信息：

- 目标受众
- 核心信息
- 字数要求
- 特殊要求（如有）

### 步骤 2：信息搜索（⭐必须优先执行）

**强制规则**：当用户提出新的产品/技术/概念时，必须先完成信息搜索，然后才能进行选题讨论。

- 对于新产品/新技术，必须进行信息搜索
- 搜索内容包括：官方文档、产品介绍、技术特性、用户评价、竞品对比
- 保存搜索结果到 `_knowledge_base/[主题]-[时间].md`
- 分类存储：技术工具/行业人物/产品发布/报告资料/方法论
- 搜索完成确认：向用户确认搜索结果后再进入选题讨论

### 步骤 3：判断内容类型（⭐必须）

**强制规则**：

- 当用户输入一个主题时，**必须先判断内容类型**
- **必须明确告知用户该主题属于哪类内容**
- **必须等待用户确认内容类型后才能进入选题策划**

根据主题特征，判断属于哪类内容：

- **AI 产品拆解**：聚焦某个具体AI产品/工具的功能、设计、体验分析
- **场景解决方案**：针对特定场景/问题的完整解决方案
- **效率提升实战**：分享提效技巧、工作流、工具组合
- **产品方法论**：总结提炼的方法、框架、最佳实践
- **行业观察**：行业趋势、现象分析、未来预测
- **个人品牌故事**：飞哥的个人叙事/品牌故事/成长路径。触发条件：用户要求写"我的故事""品牌故事""个人介绍""成长故事"等。核心约束：**禁止行业标签**、**禁止能力标签**、必须写**成长路径**而非职业履历。推荐框架："影响力半径""能力外化""自我退后"等隐喻驱动叙事。详见 `references/personal-brand-story-pattern.md`

**内容类型判断输出格式**：

```text
基于对 [主题] 的分析，我判断该主题属于以下类型：

【内容类型】：[AI产品拆解/场景解决方案/效率提升实战/产品方法论/行业观察]

【判断理由】：
- [理由1]
- [理由2]
- [理由3]

【适合的写作角度】：
- [角度1]
- [角度2]
- [角度3]

请确认这个内容类型判断是否准确？如果同意，我将基于这个类型进行选题策划。
如果不同意，请告诉我您认为应该属于哪种类型，以及原因。

⚠️ 注意：在您确认之前，我不会开始选题策划。
```

### 步骤 3.5：HKR 选题质检（⭐必须，在内容类型判断之后、选题策划之前）

**强制规则**：每个选题必须通过 HKR 三项质检，才能进入选题策划。

| 检查项 | 含义 | 通过标准 |
|--------|------|----------|
| **H (Happy)** | 足够有趣、有悬念？标题和开头能让人好奇想点开？ | 标题有反差/悬念/利益点 |
| **K (Knowledge)** | 有信息量？读完能学到新东西？ | 有具体数据/案例/框架/方法 |
| **R (Resonance)** | 能戳中情绪？让人"对对对，我也这么想"？ | 切中读者痛点/焦虑/好奇/爽点 |

**评级标准**：
- **S 级选题**：三项兼备 → 直接进入选题策划
- **及格选题**：至少两项 → 可以进入，但需补强缺失项
- **不及格**：仅一项或零项 → 主动与用户沟通调整方向，不要硬写

**输出格式**：
```text
**【HKR 质检结果】**

H（有趣度）：✅/❌ [理由]
K（信息量）：✅/❌ [理由]
R（共鸣度）：✅/❌ [理由]

综合评级：[S级/及格/不及格]
建议：[直接进入选题策划 / 需要补强XXX / 建议调整方向]

**⚠️ 共识话题陷阱（2026-06-05 补充）**：

当一个话题已经是行业共识时，K（信息量）应直接判 ❌。判断标准：
- 该观点/方法论在目标读者群体中是否已经被广泛接受？
- 写出来后读者会不会觉得"这我知道啊"？
- 是否有信息增量（新数据、新角度、新案例）？

示例：用户原话"这篇文章写作的意义不大，Skill来讲，大家都是一个共识"——当 Skills 系统设计已经是行业共识时，再写"Skills 很重要"就没有信息增量。

**处理方式**：在 HKR 质检阶段就主动告知用户"这个话题可能缺乏信息增量"，不要等到文章写完才说。节省双方时间。
```

### 步骤 4：选题策划（⭐强制执行，不可跳过）

**强制规则**：

- 当用户输入一个主题时，**必须先进行选题策划**
- **必须提供 3-5 个不同的选题方向供用户选择**
- **禁止直接生成文章**，必须等待用户选择选题后才能继续
- 用户未选择前，不得进入后续写作步骤

**选题交集模型（⭐核心框架）**：

好选题 = 你的专业领域 × 读者的普遍兴趣 × 当下的时间节点

- 光是专业 → 曲高和寡
- 光是读者兴趣 → 流于肤浅
- 光是蹭热点 → 昙花一现
- 三者结合 → 最精准的引爆点

**选题来源清单**：
- X（Twitter）：AI博主、公司动态、一手资讯
- Reddit：r/artificial、r/ChatGPT、r/singularity、r/ClaudeAI（100+ upvote 算火）
- 小红书：大众舆论场的AI话题焦点，重点看评论区
- 即刻：AI博主、产品创意、行业洞察
- 读者社群/群聊：群友的难点、痛点、高频需求

**选题策划输出格式**：

```text
我已完成对 [主题] 的调研。基于搜索到的丰富资料，我提供以下 [3-5] 个选题方向：

## 选题二: 《[主标题]:[副标题]》
...

---

## 选题三: 《[主标题]:[副标题]》
...

---

## 选题四: 《[主标题]:[副标题]》（可选）

**请告诉我您想选择哪个选题？或者如果您有其他想法，请告诉我。**

⚠️ 注意：在您选择之前，我不会开始撰写文章。
```

**标题用词偏好（飞哥确认）**：标题优先用覆盖面更广的词。例如"商业分析"比"数据分析"更优（前者包含后者，受众更广）。选题阶段确定标题用词时，主动选更通用的表述。

**选题策划原则**（⚠️ 选题阶段常见陷阱详见 `references/topic-planning-pitfalls.md`）：

1. **差异化**：每个选题的切入点必须不同（如：实战踩坑 vs 行业分析 vs 小白体验 vs 产品拆解 vs 方法论）
2. **具体化**：大纲必须包含具体的坑、数据或案例，不能空泛
3. **诚实评估**：如实告知工作量和是否需要真实测试
4. **数量要求**：必须提供3-5个选题，不得少于3个
5. **共识检测（⭐2026-06-05 新增）**：如果某个技术点已经是行业共识（如"Skills 是 AI Agent 的核心"），写出来没有信息增量，不应该作为选题。判断标准：目标读者看到标题后的反应是"这我知道"还是"这我不知道"？如果是前者，换角度或换选题。
6. **用词普及面**：标题用词优先选择普及面更广的表达（如"商业分析">"数据分析"），让非技术读者也能理解。飞哥原话："商业分析普及面更广一些。"

**已确认选题的快车道例外**：

如果用户已经在前文明确选择了选题/标题方向，并直接要求"完整写出公众号文章内容""就按这个标题写"，不要再机械重复"内容类型确认→3-5 个选题→等待选择"的慢流程。此时应进入写作快车道：先核实必要事实来源，保存 brief 与 knowledge base，创建标准文章目录，然后直接输出完整正文。写完后做洁净度自检，并只向用户汇报路径、标题建议、核心金句，不要把全文重复贴回聊天窗口。案例见 `references/antigravity-agent-workflow-article-case.md`。

**大纲逐层讨论模式（2026-06-14 补充）**：当用户说"把每一层都打开讨论"或类似表述时，他们不想要一个完整的大纲然后确认/拒绝，而是想**逐层展开讨论**——每层提出问题、给出倾向、等待用户反馈后再进入下一层。这是飞哥的苏格拉底式思考方式，通过讨论自己推导出结论。正确做法：把大纲拆成独立的层，每层列出"当前素材 + 需要确认的问题 + 我的倾向"，等用户逐层确认后再汇总成最终大纲。不要一次性把所有层都铺开。

⚠️ **快车道 pitfall**：即使进入快车道，`_briefs/` 和 `_knowledge_base/` 也不能跳过。它们是文章的可追溯性基础——未来复盘、修订、迭代时需要知道"这篇文章基于什么资料写的"。快车道省的是确认流程，不是记录流程。

**飞哥文章结构偏好（2026-05-27 纠偏，含行动与冷思考顺序铁律）**：

- **主线优先于案例堆叠**：多方信息（多个公司案例、多条推文）不能平行罗列，必须有**一条贯穿全文的递进主线**。每个案例只服务一个论点，不能"ClickUp一段、SO一段、合规一段"各自独立。正确做法：主线（如"现象→机制→权力→行动→边界→升华"）贯穿所有案例，每个案例是主线上的一环而非独立章节。
- **冷思考优先于行动建议（铁律）**：文章后半段结构必须是"冷思考/边界 → 行动建议 → 升华"。绝不能"行动建议 → 冷思考 → 升华"。先踩刹车去幻想（Agent不是什么），再给清醒的行动建议（你现在就该做的事），最后升华收尾。读者不会在看完行动建议后被冷思考浇冷水，而是在清醒认知边界后再决定怎么动。
- **"冷思考"必须在"行动建议"之前**：飞哥明确要求"冷静边界 → 你的三个行动 → 判断力是唯一护城河"的顺序。不要先给行动建议再踩刹车——先让读者清醒认识边界，再给基于清醒认知的行动建议。最后一节做升华收尾。
- **拒绝"新闻摘要感"**：多个来源的信息不能平铺成"X说了A、Y说了B、Z说了C"。必须用自己的判断把它们串成一条逻辑链。

**技能展示/工具介绍类文章强制约束（2026-05-28 纠偏，2026-05-29 补充双模式）**：

当文章主题是**自己做的工具/技能/开源项目**时，极易写出"产品手册"而不是"故事"。此类文章是最高风险类型——Agent 天然倾向"技术文档思维"，不加硬性阻断就会写出教科书式文章。

**🔴 第一步：选择模式（不可跳过）**

技能展示类文章有两种模式，必须先选一种再动笔。详见 `references/skill-showcase-two-modes.md`。

| 模式 | 一句话 | 叙事弧 | 适用场景 |
|------|--------|--------|----------|
| **A：调查实验型** | "我替你做了这个实验" | 发现问题→困惑→实验→踩坑→解法→卧槽→开源 | 有真实踩坑经历、探索过程有戏剧性 |
| **B：歸藏模式** | "我做了个东西，给你看看" | 故事引入→产物体验→能做什么→怎么用→效果→开源 | 产物已成熟、直接展示价值、分享欲驱动 |

**选择依据**：问自己"这个技能/工具，我有没有一段真实的探索踩坑经历？"有→模式A；没有或经历不重要→模式B。拿不准就问飞哥。

**🔴 第二步：写作前强制阻断（不可跳过）**

```text
□ 模式确认：已选定模式A还是模式B？
□ [模式A] 叙事弧确认：是否遵循 发现问题→困惑→实验→踩坑→解法→卧槽结果？
□ [模式A] 主角确认：文章主角是人（的实验和发现）还是工具（的技术原理）？→ 必须是人
□ [模式B] 分享欲确认：全文底层情绪是"我发现好东西忍不住分享"还是"我来系统讲解"？→ 必须是前者
□ [模式B] 设计决策砍掉：有没有讲"为什么做成这样"？→ 有就删
□ [模式B] 行业科普砍掉：有没有单独的行业背景/技术原理章节？→ 有就删，并入功能介绍
□ [模式B] Hermes Skill CLI 禁令：文章是否展示了命令行代码？→ 有则改为自然语言（"帮我清除这张图的AI水印"），详见 references/skill-showcase-article-pattern.md
□ 技术原理占比：技术细节是否作为补充而非主干？→ 必须 ≤30% 篇幅
□ 开头确认：是否从一个具体的、当下的个人事件切入？→ 禁止"科普式开头"
```

此检查在「步骤 4：选题策划」确认后、动笔前强制执行。任何一项未通过，禁止进入写作阶段。

**铁律（两种模式通用）**：

- **禁止以技术原理为主干**：读者不是来看公式和架构图的。技术细节只能作为补充，不能是文章主角。
- **禁止"先定义→再分类→再讲解→再开源"的教科书结构**：无论哪种模式，开头必须是故事或场景，不是定义。
- **禁止"设计决策分析"章节**（模式B特别严格）：不要讲"为什么选A不选B"，读者只需要知道A好用。
- **禁止独立行业科普章节**：背景信息穿插在功能介绍里自然带出，不要单独开一节"你该知道的"。
- **分享欲 > 科普专家**：全文的底层姿态是"朋友分享好东西"，不是"专家给你讲课"。
- **强制L4活人感检查**：此类文章必须通过ai-ggbond-writer L4 活人感检查后才能发布。"读完像有见识的普通人在认真聊一件打动他的事，还是AI在输出技术文档？" 详见 `references/ai-ggbond-writer-full-methodology.md`。
- **失败信号识别**：如果文章读起来像"产品说明书""技术文档""教科书""行业报告"，立即判定为不合格，推倒重写，不是修改。
- **配图必须匹配叙事类型**：模式A配**调查手记风**（软木板证据板、终端截图感、手绘笔记）；模式B按产物特性选手绘/信息图/截图混搭。详见 `references/investigation-notebook-image-style.md`。
- **标题必须直接有冲击力**：工具介绍类标题不能绕弯子。公式：`开源我的X：我把Y撕了` 或 `我做了X，结果Y翻了Z倍`。
- **字数控制**：模式A舒适区 6000-10000字；模式B舒适区 5000-8000字。模式B超过8000大概率在注水。
- **实战案例参考**：
  - 模式A成功案例：remove-ai-marks v2 → `references/skill-showcase-v1-v2-rewrite-case-2026-05-28.md`
| 模式B参考文章：歸藏 PPT Skill（https://mp.weixin.qq.com/s/GXjjlxpIJ604HVCCZJkUBA）、花叔达尔文.skill（https://mp.weixin.qq.com/s/4ICQJGwa2MD616_oFmJb4w） |
   - 模式B五条铁律（自然语言不露代码、不暴露上游依赖、结尾锚定痛点、分享欲非科普、标题前缀公式）：详见 `references/skill-showcase-guizang-pattern.md`

**苏格拉底对话模式（飞哥偏好）**：飞哥在探索复杂问题（商业模式、产品策略、行业洞察）时偏好苏格拉底式对话——不想要直接答案，希望通过提问和讨论自己推导出结论。这是他的深度思考方式，AI应扮演追问者而非解答者。详见 `references/feigo-socratic-dialogue-preference.md`。

**已确认素材/优先级的趋势文章快车道**：

当用户已经要求“根据 GitHub Trending / 热榜项目 / 刚才给的 P0 优先级写公众号文章”，且前文已经完成热榜抓取和 P0 项目筛选时，视为选题已确认。不要再要求用户确认内容类型或选题方向；直接调用趋势发现 Skill/现有资料，保存 brief 与 knowledge base，创建 `/Users/admin/SuperIp/article/YYYYMMDDHHMM-主题/`，写 Markdown 初稿并做洁净度自检。此类文章的重点不是复读项目列表，而是把 P0 项目抽象成一个可传播判断和认知框架。

### 步骤 6.5：写作技巧速查（⭐动笔前必读）

在正式写作前，回顾以下技巧清单。这些是让文章从"AI输出"变成"人在聊天"的核心武器。

#### 节奏技巧

| 技巧 | 用法 | 示例 |
|------|------|------|
| **句式断裂** | 关键节点用极短句独立成段，制造停顿和重量感 | "黑暗森林。""大时代啊，朋友们。""安全，安全，还是他妈的安全。" |
| **疑问句刹车** | 用疑问句让读者停下来思考，准备接收核心信息 | "为啥复制一遍会有效果呢？" → "听着很难理解对吧。" → "我还是用大白话举个例子。" |
| **扣主线句** | 偏出去聊了一圈后，一句话拉回主线（频率要高） | "说回正题。""但核心问题其实是这个。""回到我们最开始聊的。" |
| **长短句交替** | 混合短句（3-10字）和长句（20-40字），AI文本最缺这个 | 短："项目死了。" → 长："团队熬了三个月，钱烧完了，产品上线那天服务器崩了。" |

#### 叙事技巧

| 技巧 | 用法 | 适用场景 |
|------|------|----------|
| **英雄之旅叙事弧** | 具体困境/好奇 → 一步步做 → 踩坑 → "卧槽"结果 | 技能展示、工具介绍、调查实验类 |
| **反向论证** | 先满足读者期待，再打破，制造认知冲击 | "你以为Prompt技巧要很复杂？结果就是复制粘贴。" |
| **层层剥开** | 现象 → 表面解释 → 更深追问 → 核心洞察 | 现象解读、深度分析类 |
| **逐一展示法** | 多个案例不一次性罗列，逐一展示带吐槽，按"升番"排列（最弱在前，最炸在后） | 产品对比、模型评测、工具横评 |
| **回环呼应** | 前面埋的细节后面必须响，结尾callback开头意象 | 所有文章（契诃夫之枪） |

#### 人物与情感技巧

| 技巧 | 用法 | 示例 |
|------|------|------|
| **人物画像法** | 从数据点出发，3-5句话构建具体人物（触发→代入→多维堆砌→情感锚定→细节具象化） | "他可能是一个刚毕业的学生...白天被老板PUA...想学点新东西改变命运。" |
| **读者直呼法** | 关键节点直接对话读者 | "屏幕前的你""你相信我""你也可以回想一下" |
| **谦逊铺垫法** | 观点前先自谦，降低读者防御 | "我也不知道行不行""不成熟的经验""愚钝如我" |
| **亲自下场** | 真的去做那件事，不是隔空评论——这是建立信任感的核武器 | 买9.9的DeepSeek、亲手给AI投毒、花5000找人装OpenClaw |

#### 知识输出技巧

| 技巧 | 用法 | 错误示范 |
|------|------|----------|
| **知识随手掏** | "聊着聊着顺手掏出来"，像突然想起来 | ❌ "下面我来简单介绍一下格式塔心理学..." |
| **文化升维** | 聊完具体事后自然联想到更大参照物（历史/哲学/文化） | 9.9元DeepSeek → 《北京折叠》的"信息折叠" |
| **对立面理解** | 先站在对方立场具体化，承认合理性，再切入自己视角 | ❌ 只说对方错 → ✅ 先说"站在XX角度，这么想确实有道理" |

### 步骤 7：写作

**AI 角色边界（⭐动笔前必读）**：

在写作前，明确哪些内容必须由飞哥提供，哪些可以由 AI 完成：

| AI 擅长做（放心交给 AI） | AI 做了会暴露的（必须飞哥来） |
|--------------------------|------------------------------|
| 找证据和佐证（历史、学术、文化论据） | 第一手观察和真实经历 |
| 找类比和比喻（如"AI 像全能实习生"） | 核心创意角度（从淘宝卖 DeepSeek 联想到《北京折叠》等） |
| 按确定的角度扩写 | 情绪的真实表达（"我愣住了"而非"我很震撼"） |
| 补充学科背景知识 | 数据到人物的同理心转换 |
| 梳理逻辑和结构建议 | 亲身下场的实验和发现 |

**理想协作流程**：
```
飞哥：素材 + 核心观点 + 个人经历 + 情绪节点
↓
AI：补充背景知识 + 找证据类比 + 结构建议 + 按角度扩写
↓
飞哥：二次改写（加入自己的声音、打破节奏、补充真实细节）
↓
AI：四层自检 → 输出修改建议
↓
飞哥：终审定稿
```

**写作原则**：

- **拒绝注水**：不要为了凑字数而重复废话
- **单源改写扩充铁律**：当从单篇外部文章（如博客、报道、YouTube 视频）改写时，初稿通常只有目标字数的 30-40%（如目标 8000 字，初稿仅 4000-5000 字）。这是因为单源信息密度有限。必须做 2-3 轮主动扩充：

1. **第一轮**：写完框架和核心内容（~4000 字）
2. **第二轮**：补充跨领域类比（控制论、信息论、博弈论等科学理论骨架）+ 展开案例细节（具体步骤、动机背景、数据结果、落地建议）（+2000 字）
3. **第三轮**：增加"你想想你自己的公司"段落（拉回读者具体场景）+ 数学/数据推演（具体数字让趋势可感知）+ 冷思考边界分析 + 细化行动建议（+2000 字）

每轮扩写后检查：是否有重复内容？是否有注水？节奏是否流畅？

> 口诀：单源文章不是"缩写"，是"借题发挥"。来源是药引子，你的判断、类比、推演才是主菜。
- **自然段落结构**：采用散文式自然段落，避免使用01、02、03等连续编号形式
- **故事感**：用一条主线故事串联起所有的技术点
- **多案例文章必须用递进论证结构**：当文章引用多个真实案例时，严禁"平行案例陷阱"（每个案例独立一节，像新闻摘要）。必须让每个案例服务递进论点链中的一环——现象钩子→范式框架→机制解剖→资产重定义→权力法则→行动建议→冷思考→升华。详见 `references/multi-case-progressive-thesis-structure.md`。
- **行动建议必须在冷思考之前**：当文章同时包含"怎么做"和"边界/风险"时，行动在前、冷思考在后。读者最后带走的是掌控感和力量感，不是焦虑感。详见 `references/multi-case-progressive-thesis-structure.md`。
- **金句频出**：每隔 500-800 字，需要有一个能够被读者划线转发的金句/洞察

**开头五种必杀技（选一种）**：

| 模式 | 用法 | 示例 |
|------|------|------|
| **叙事启动** | 从一件具体小事讲起 | "故事是这样的。""事情是这样的。" |
| **荒诞事实** | 直接抛出一个让人"？？？"的事实 | "我可能，刚刚成为了哈基米的儿子。""淘宝上居然有人卖9块9的DeepSeek。" |
| **热点破题** | 从热点事件直接切入 | "最近这两天，被一个三宫格AI图片给刷屏了。" |
| **好奇心驱动** | 抛出钩子，制造疑问 | "这两天在网上刷到了一张图，很有意思。" |
| **感性事件** | 从个人感受和具体事件入手 | "大周末的，起床第一件事，就看到飞书开源CLI了。。。" |

**结尾五种模式（选一种）**：

| 模式 | 用法 | 适用场景 |
|------|------|----------|
| **引用收尾** | 引用他人名言，升华主题 | 深度分析、行业观察 |
| **哲思余韵** | 留下富有诗意的哲学思考 | 现象解读、认知升级 |
| **行动呼吁** | 鼓励读者亲自实践 | 教程、工具推荐 |
| **信念宣言** | 表达个人坚定的信念 | 趋势判断、行业预测 |
| **回环呼应** | 回到开头的主题/意象，形成闭环 | 所有文章（契诃夫之枪） |
- **⚠️ 图片引用必须内联到 Markdown**：每张配图必须在正文中用 `![图片说明](images/xxx.png)` 语法引用，否则推送到公众号时脚本检测不到图片（`Placeholder images: 0`），正文图片全部丢失。**这是最常见的坑——图片文件存在但文章里没有引用。**

**段落组织规范**：

❌ **避免的编号形式**：

```markdown
## 01. 什么是超级个体

内容...

## 02. 为什么超级个体是个坑

内容...

## 03. 普通人该怎么走

内容...
```

✅ **推荐的自然段落形式**：

```markdown
## 什么是"超级个体"

说起来，"超级个体"这个概念最近火得不行...

## 为什么我说这是个坑

说实话，我一开始也被这个概念吸引了...

## 普通人到底该怎么走

折腾了大半年，我有些想法想分享...
```

**自然过渡技巧**：

1. **用问题过渡**：「那问题来了，普通人该怎么办？」
2. **用转折过渡**：「不过，事情没那么简单。」
3. **用故事过渡**：「这让我想起之前的一次经历...」
4. **用金句过渡**：「说到底，工具是为人服务的。」

**小标题设计原则**：

- 使用完整句子或短语，不要用编号
- 标题本身带有情感或观点
- 标题之间有逻辑递进关系
- 每个小标题下2-4个自然段落

**段落长度控制**：

- 每段3-5行（手机屏幕1-1.5屏）
- 段落之间空一行
- 避免大段文字墙

### 步骤 8：三遍审校

#### 第一遍：基础检查

- 错别字、标点符号、格式规范
- 链接格式（纯文本，不用Markdown链接）
- 图片标注是否完整
- **重复金句检查**：当同一句话被插入到文章多处时，必须逐处确认是否需要保留。金句原则上只在最有展开空间的位置出现一次，避免"同一句话说了两遍"的廉价感。

#### 第二遍：去AI味，优化表达和逻辑（⭐核心步骤）

**为什么AI写的东西有"塑料味"？**

1. **陈词滥调的结构**：开头"在快速发展的..."，结尾"总而言之..."
2. **滥用"大词"**：明明是"研究"，非要说"深入探讨"；明明是"使用"，非要说"赋能"
3. **缺乏观点的中立**：总是用"值得注意的是"对冲观点

**去AI味五步法**：

> ⚠️ **适用范围**：以下五步适用于**所有**写作任务——公众号长文、社交推荐文案（朋友圈/群聊/X Thread）、微信贴图、以及其他AI朱朱侠出品的文字内容。社交推荐文案有额外铁律（禁止操控型引导、禁止AI模板句），详见 `references/social-media-recommendation-writing.md`。

**⭐ 终稿五维评分门禁（吸收自 stop-slope，v2.4.0 新增）**：

文章定稿前必须做五维评分，总分 < 35/50 不可发布，必须回炉：


**⭐ 虚假代理全杀（吸收自 stop-slope，v2.4.0 新增）**：

| "一个投诉变成了修复" | 投诉不会变成修复 | "工程师收到投诉后修了" |

| -------- | ---- | -------- |

**铁律**：把读者放进场景里。"你"比"人们"强。具体的比抽象的强。

**Step 2：节奏感注入（Burstiness）**

AI生成文本句子长度很平均。人类写作是"长短句交替"。

```
节奏感要求：
1. 混合短句（3-10字）和长句（20-40字）
2. 允许使用句子片段制造效果
   例："真的吗？至少今天不是。"
3. 不要每句都用"此外"、"然而"开头
4. 直接用主语或动词开始句子
5. 段落长度变化（1-3句一段）

好例子：
"项目失败了。没钱了。团队熬了三个月，实在撑不下去了。"

坏例子（AI味）：
"此外，项目失败的主要原因是资金短缺。另外，团队在长时间工作后也出现了疲劳问题。"
```

**Step 3：观点极化**

强制选边站，禁止当"理中客"。

```
观点极化规则：
1. 不要平衡论点（"有利有弊"、"因人而异"）
2. 选择一边，坚定地辩护
3. 禁止使用：
   - "有利有弊"
   - "这取决于..."
   - "另一方面..."
   - "有人可能会说..."
4. 使用强动词：
   - "这证明了..."（不是"这可能表明..."）
   - "这就是..."（不是"这可能是..."）
5. 使用第一人称（"我"、"我的"）增加主观性

示例：
❌ AI味：AI对社会既有好处也有挑战。
✅ 人味：AI会重塑社会，不管你喜不喜欢。好处太大了，根本没法忽视。
```

**Step 4：口语化叙事（自然对话测试）**

这句话你在和朋友聊天时会说吗？

```
口语化要求：
1. 使用简单、口语化的表达
2. 语法可以稍微松散
3. 自然使用语气词（"嗯"、"说实话"、"怎么说呢"）
4. 用日常生活的比喻
5. 如果概念太无聊，跳过它
6. 不要用企业黑话
7. 直接称呼（"你"、"你的"）
8. 偶尔打断自己（然后自我纠正）

示例：
"所以基本上，LLM这东西...它不是真的在思考，对吧？它只是在预测下一个词是什么。就像我说'花生酱'，你就知道'果冻'要来了。就这样。这就是全部把戏。"
```

**Step 5：添加人味元素**

```
加入元素清单：
□ 短句（3-10字）
□ 句子片段
□ 口语化表达
□ 个人经历/观点
□ 不完美的语法
□ 情感词汇
□ 具体例子（不是抽象概念）
□ 自嘲或幽默
```

**Step 6：主动注入人格瑕疵（⭐AI最缺的一步）**

去AI味只是"清洗"——去掉机器痕迹。但真正有灵魂的文字还需要**主动注入人格瑕疵**。AI 默认写出的文本是流畅、完整、逻辑自洽的——但真人聊天恰恰不是这样。真人会重复、会打断自己、会突然岔开再拉回来。

| 技巧 | 用法 | 示例 |
|------|------|------|
| **重复强调** | 同一个词连续说两遍，制造执着感 | "就是这个意思，就是这个。""不对不对，我重新说。" |
| **中途打断自己** | 说到一半突然改口或加括号式吐槽 | "我试了三天——不对，两天半，第三天下午我放弃了" |
| **省略主语** | 跳过"我/你/他"，直接开说 | "想想就觉得兴奋。""太离谱了。" |
| **刻意的模糊** | 不把话说死，留白 | "我就不说是谁了。""具体数字不方便讲，但大概就是那个量级。" |
| **情绪标点系统** | 用非标准标点传递真实情绪 | "。。。"表示拖长/震惊，"？？？"表示极度惊讶，"= ="表示无语 |
| **口癖和语气词** | 加入个人化的口头表达 | "这玩意""不是哥们""我寻思了一下""太牛逼了""比较骚的事" |

**核心区别**：Step 1-5 是"去AI味"（减法，去掉机器痕迹），Step 6 是"加人味"（加法，注入人格瑕疵）。两步都做，文章才不像AI。

**去AI味检查清单**：

```
□ 是否有"在快速发展的背景下"类开头？
□ 是否有"深入探讨"、"赋能"、"优化"？
□ 是否有"此外"、"另外"、"综上所述"？
□ 句子长度是否太均匀？
□ 是否缺乏个人观点？
□ 是否过于正式/学术？
□ 读起来像AI朱朱侠在说话吗？
```

#### 第三遍：风格检查和内容升华

- 检查是否符合AI朱朱侠风格（口语化、心路历程、具体细节）
- 确保个人IP自然融入
- 金句提炼和内容升华
- 开头是否抓人、结尾是否有行动引导

#### 第四遍：L4 活人感检查（⭐强制，2026-05-28 新增）

**此检查在第三遍之后强制执行，特别针对技能展示/工具介绍类文章。**

核心问题：**"读完像有见识的普通人在认真聊一件打动他的事，还是AI在输出信息？"**

检查清单：
- □ **温度感**：情绪是体感记忆（"我当时就愣住了"）还是知识描述（"这让人感到震撼"）？
- □ **独特性**：只有飞哥/AI朱朱侠才能写出的角度？还是任何AI都能生成的内容？
- □ **姿态**：聊天而非教书/做营销？有没有居高临下的"科普感"？
- □ **心流**：从头到尾有没有注意力断掉的地方？读起来会不会像跳章节？
- □ **亲自下场感**：有没有真实的第一手经历？还是全是二手资料？
- □ **情绪注入**：≥3处真实情绪表达（愣住了/太离谱了/气笑了/不敢相信）？
- □ **自嘲**：≥1处承认局限或自嘲？
- □ **读者直呼**：≥3次"你""你可以""你想想"？

**不通过标准**：上述8条中任意3条不满足 → 判定为"AI味文章"，必须二次改写（加入飞哥真实声音、打破教科书节奏、补充个人经历），不可直接发布。

**工具介绍类文章特别检查**：文章主角是人还是工具？如果读完后读者记住的是"这个工具有三层引擎"而不是"这个人做了件有意思的事"，必须推倒重写。

详见 `references/ai-ggbond-writer-full-methodology.md`。

### 步骤 9：爆款结构优化

**5种爆文公式**：

1. 问题-原因-方案-升华（教程类）

#### 10.4 使用云雾API生成图片（⭐强制要求 - V4最终版）

**⚠️ 重要说明**：生图功能**默认使用** **`gpt-image-2`** **模型**，通过 OpenAI Images API (`/v1/images/generations`) 调用，中文渲染效果最佳。

##### 🔴 模型与故障处理铁律（必须严格遵守）

**铁律一：模型不可擅改**
- 用户指定的模型（如 gpt-image-2）**必须严格使用**，不得因限流、报错等原因自行切换到其他模型（如 gpt-image-1、dall-e-3 等）
- 不同模型的出图风格、中文渲染质量、分辨率支持差异巨大，擅自换模型 = 出图全部作废
- 如果指定模型不可用（429/503/限流），**必须立即暂停，通知用户**，等待用户指示
- 通知格式：`"⚠️ 生图模型 {model} 当前不可用（错误：{error}），已暂停。请确认：1）等待恢复后重试 2）更换模型（请指定）"`

**铁律二：API 问题找用户，不自作主张**
- API Key 无效、额度耗尽、账户异常等问题，**不要自行尝试其他端点、其他 Key、或重试其他模型**
- 立即通知用户：`"⚠️ API 遇到问题（{error}），请检查 API Key 和账户额度。已暂停，等您确认后继续。"`
- 用户会自行解决 API 问题，Agent 只需等待确认，**绝不自作主张**

**铁律三：重试策略（仅限同一模型临时限流）**
- 同一模型遇到临时限流（429），可等待 15-30 秒后重试，最多 3 次
- 3 次仍失败 → **立即暂停，通知用户**，不得继续
- 不得在重试过程中更换模型或切换 API 端点
- 重试间隔建议：15s → 30s → 60s（递增）

#### 10.4.0 图片生成常见问题与解决方案（⭐重要）

在实际使用中，我们发现以下常见问题及对应的解决方案：

##### 问题1：图片内容全是英文，而非中文 / 模型自由发挥偏离内容（2026-05-28 补充）

**问题表现**：

- 生成的图片标题、标签、说明文字都是英文
- 即使提示词用中文描述，模型仍输出英文内容

**根本原因**：

- 部分图像模型（如Gemini系列）对中文的支持不够稳定
- 复杂提示词结构下，模型倾向于使用英文输出
- 提示词中没有**强制要求**必须使用中文

**解决方案**：

1. **使用稳定模型**（推荐）
   ```python
   model="gpt-image-2"
   ```
2. **结构化网格布局 > 叙述性段落（2026-05-28 铁律）**：
   长叙述性段落prompt会导致gpt-image-2"自由发挥"——输出与prompt要求完全无关的内容（如要求"三层清除引擎技术架构"却生成"C2PA provenance disclosure overview"）。成功策略：用结构化表格/网格/四象限布局（如"三行表格每行固定单元格""2x2四象限网格每块灰色边框+标题+三条列表"），不用叙述性段落。口诀：**结构化网格 > 自由排版**。OCR验证后再替换。详见 `references/gpt-image-2-grid-vs-narrative-pitfall.md`。
3. **极简中文 + 英文标签（2026-06-08 新增，流程图/架构图专用）**：
   当配图是流程图、架构图、对比图时，结构化网格不适用。改用极简策略：**中文只留1个标题（3-5字），节点标签全用英文，强调"Minimal text, maximum visual"**。中文太密必乱码，英文标签更可靠。成功案例："手册重建流程"（中文标题）+ Audio → Classify → Manual → Update → Agent（英文节点）。详见 `references/gpt-image-2-grid-vs-narrative-pitfall.md` 的"策略二"。
3. **在提示词中强制要求中文**
   ```
   【强制要求】
   - 所有文字必须使用简体中文，绝对禁止出现英文
   - 标题："中文标题"
   - 标签："中文标签"
   - 任何文字都必须是中文
   ```
3. **使用引号明确标注中文内容**
   ```
   标题必须显示为："从AI工具到AI团队的进化"
   副标题必须显示为："多Agent协作网络"
   ```
4. **添加负面约束**
   ```
   【禁止事项】
   - 绝对禁止出现英文文字
   - 绝对禁止出现乱码或无法识别的字符
   - 绝对禁止出现拼音代替中文
   ```

##### 问题2：图片结构与章节内容无关

**问题表现**：

- 生成的图片虽然美观，但与文章具体内容的契合度不够
- 图片展示的是通用概念，而非文章中的具体观点、案例或流程
- 读者无法从图片中获得文章的核心信息

**根本原因**：

- 提示词过于**通用和模板化**，没有紧密结合文章的具体内容
- 提示词设计时更多关注了视觉风格，而忽略了内容的准确性
- 没有从文章中提取**核心观点、关键案例、具体流程**来指导图片生成

**解决方案**：

1. **从文章提取具体内容生成提示词**

   ```python
   with open("文章.md", 'r', encoding='utf-8') as f:

   - 案例：{case_example}
   - 数据：{specific_data}

   【视觉元素要求】
   - 必须包含：{specific_visual_elements}
   - 必须展示：{article_specific_content}
   """
   ```
2. **提示词结构模板（内容导向）**

##### 飞哥图片中文质检与水印规则（2026-05-21）

- 生成图片后优先用 **PaddleOCR** 做中文文字识别质检，再结合肉眼判断；不要只依赖视觉分析工具。
- OCR 识别出的图标噪声（如 `</>`、`O`、零散符号）不能直接判为图片错误；标题、关键标签、金句出现错字才是硬伤。
- 飞哥不想让模型在图里额外画水印。提示词必须明确：**禁止生成任何水印、署名、Logo、角标、作者名、“AI朱朱侠”文字；品牌水印只由后期代码统一添加。**
- 代码水印当前默认：右上角；封面字号约图片高度 **3.25%**，正文图约 **2.75%**；文字透明度约 **50%**（alpha=128）；**不画圆角底框**，只叠加低存在感半透明文字。此前“6.5%/5.5% + 圆角底框”被用户反馈过大、像黑体字抢主体，已降级为历史方案。详见 `references/2026-05-21-anthropic-style-image-watermark-ocr.md`。

##### 问题3.5：gpt-image-2 中文渲染的终极降级方案（2026-06-08 实战）

**问题**：gpt-image-2 在高密度信息图场景下，中文文字渲染极不稳定——乱码、缺字、粘连、字形扭曲。用户先后否定了以下所有绕行方案：

| 尝试方案 | 用户反馈 | 结论 |
|---------|---------|------|
| 简化中文 + 英文标签 | "除了专业词语，其他不能用英文" | ❌ 不可接受 |
| matplotlib/Pillow 代码绘图 | "效果非常差，明令禁止" | ❌ 绝对禁区 |
| Pillow 叠加文字层 | "文字和图分离开，很丑" | ❌ 后贴膏药不行 |
| HTML/CSS + Playwright 截图 | "生成的图非常差劲" | ❌ 分层合成也不行 |
| 纯英文标注 + 中文图注 | 用户未回复 | ⚠️ 备用方案 |

**最终解法（用户决策）**：当 gpt-image-2 无法满足中文信息图需求时，**告知用户用 ChatGPT/DALL-E 3 自行生成配图**，Agent 只负责文章排版和推送。不要反复尝试各种绕行方案浪费时间。

**铁律**：代码绘图（matplotlib、Pillow、HTML截图）是飞哥的绝对禁区。任何时候都不要用代码生成配图内容，只能用于轻量水印叠加。

   ```
   【文字质量要求】
   ```

3. **gpt-image-2 短标题吞字修复**：在提示词中要求汉字间距
   ```
   标题：不是作弊 四个汉字 每个字之间有明显间距 字体清晰无重叠无变形
   ```
   详见 `references/generated-image-ocr-quality-check.md` 的"gpt-image-2 Chinese Character Dropping & Spacing Fix"节。
4. **生成后验证**
   - 生成图片后立即用 PaddleOCR 验证文字准确性（不要只依赖视觉工具）
   - OCR 发现核心标题缺字 → 添加间距指令后单张重生，不要整批返工
   - 接受两行渲染（如"不是"换行"作弊"），只要所有字完整即可

##### 🔴 代码绘图与文字叠加方案已禁止（2026-06-08 确认）

以下方案已被飞哥明确否决，**禁止再次尝试**：
- ❌ matplotlib / PIL / 代码绘图生成信息图
- ❌ Pillow 在图片上叠加中文文字
- ❌ gpt-image-2 纯视觉背景 + HTML/CSS/Playwright 截图叠加文字
- ❌ 为规避乱码而将图内文字全部改为英文

当 gpt-image-2 中文乱码严重时，正确做法是**告知用户并让用户自行用其他工具生成图片**，或征得授权后换模型。详见 `references/gpt-image-2-chinese-garbled-text-fallback-2026-06-08.md`。

```bash
export http_proxy=http://127.0.0.1:7897

  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{

    "size": "1536x1024",
    "n": 1
```

**⭐ gpt-image-2 中文信息图生成策略（2026-06-09 实战）**：

文章配图的中文渲染，按以下策略优先级尝试：

1. **结构化网格布局**（首选）：用表格/网格/单元格描述布局，每个中文标签2-4个字短词，字间距大。口诀：**结构化网格 > 自由排版**。
2. **极简中文+英文标签**：中文只留1个大标题（3-5字），节点标签全英文。适合流程图/架构图。
3. **低密度大字封面**：少量中文，字体大，留白多。适合封面图，不适合信息图。
4. **让用户生图**：连续3次中文乱码 → 停止，告知用户用 ChatGPT/DALL-E 3 生成。**不要反复尝试各种绕行方案。**

**关键经验**：gpt-image-2 在以下情况中文渲染更稳定：
- 中文字数少（< 10个字）
- 每个字独立，有明显间距
- 字体粗大
- 网格化布局（每个模块有边框分隔）
- 反之，长段落中文、密集小字、叙述性排版 → 大概率乱码

**长耗时生图进度汇报规则（2026-05-25 飞哥反馈）**：生图任务 >3 张时属于长耗时操作（gpt-image-2 约 3-5 分钟/张，10 张全量约 30-40 分钟），中间用户询问进度时不能只回复"还在跑"这种一句话反馈。必须汇报：（1）已完成数/总数；（2）每张文件名、大小、尺寸；（3）预估剩余时间；（4）进程状态。如果进程被会话重启杀死，不要傻等，立即检查已落地文件，写续跑脚本跳过已完成图片继续生成。续跑方案和本次落地案例见 `references/github-trending-agent-article-image-workflow-2026-05-25.md`。

#### 11.1 排版核心原则与目的驱动设计

**飞哥长文语义节奏纠偏（强制）**：给飞哥做公众号长文精排时，分段要遵循“等这一口逻辑说完，再分段”，不是按句号机械切，也不是为了避免碎而合成大段。详见 `references/wechat-semantic-rhythm-typesetting.md`。金句断点是编辑策略，禁止把“金句断点”四个字写进正文；引用原文必须加粗，引用卡片可少量保留；独立金句卡片默认不超过 3 个；若引用卡片多于 2 个，独立金句卡片最多 1 个。若需全文重排，先做 800-1000 字语义节奏样稿给飞哥确认，再生成 HTML 精排预览，确认后才推公众号草稿。内容节奏不只看段落，还要看故事弧线和“升番点”：每 800-1200 字至少有一次认知升级，避免平铺说明书。详见 `references/ai-ggbond-content-methodology.md`。

**排版三大核心功能**：

1. **拯救碎片化注意力**：读者只有3秒注意力（地铁、卫生间、工作间隙），清晰布局实现"无痛阅读"
2. **视觉导航系统**：层级标题如同路标，关键词高亮实现3秒信息抓取
3. **视觉品牌识别**：一致排版 = 可识别的品牌签名，坚持3个月建立品牌印记

**风格一致性公式**：

```
风格 = 标题格式 + 主色调 + 正文格式 + 图片风格 + 头尾引导
```

**关键规则**：坚持一种风格至少3个月。频繁切换风格（今天文艺风，明天赛博朋克）会导致粉丝流失。

#### 11.3 字体排版规范

**字体族（兼容全平台）**：

```
-apple-system, BlinkMacSystemFont, 'Segoe UI', 'PingFang SC', 'Hiragino Sans GB', 'Microsoft YaHei', sans-serif
```

**字号指南**：

| 字号   | 用途       | 说明           |
| ---- | -------- | ------------ |
| 24px | 主标题（H1）  | 居中，加粗，视觉焦点   |
| 17px | 章节标题（H2） | 左对齐，加粗，高对比度  |
| 15px | 正文       | 安全默认选择，永不出错  |
| 14px | 紧凑优雅风格   | 文艺类账号，更精致    |
| 13px | 说明文字     | 图片说明、注释来源    |
| 12px | 元数据      | 日期、阅读时长等弱化信息 |

**文章元数据行排版规范（飞哥发布版禁用）**：

飞哥公众号发布版禁止在正文标题下插入阅读元信息行。不要生成 `📊 约 xxxx 字 · 建议阅读 x 分钟 · 点击右上角🎧可听阅`，也不要生成任何类似“阅读时长/听阅提示”的模板化提示。

原因：这类元信息会把文章从“观点内容”拉回“模板产物”，暴露工具痕迹，破坏开场的干净度。若确实需要统计字数或阅读时长，只能放在内部审校报告里，不得进入发布版正文。

**标签行排版规范**：

`#Harness #HarnessEngineering ...` 标签行：
1. **居中对齐**
2. **字号 10px**
3. **颜色 #999**

**HTML 模板**：
```html
<p style="font-size: 10px; color: #999; text-align: center; margin: -15px 0 25px 0;">
  #Harness #HarnessEngineering ...
</p>
```

**注意**：面向老年读者时增加+2px

**行高与间距**：

| 类型     | 规范        | 说明            |
| ------ | --------- | ------------- |
| 字间距    | 0.5px     | 正文标准，避免二维码压缩  |
| 标题行高   | 1.3-1.4   | 标题不宜太松        |
| 正文行高   | 1.75      | 亲密但不拥挤，最佳阅读体验 |
| 说明文字行高 | 1.5       | 紧凑但清晰         |
| 段落间距   | 段落间1空行    | 视觉分隔清晰        |
| 章节间距   | 上2行 + 下1行 | 大标题前空两行       |
| 两侧边距   | 8-16px    | 边缘留白减轻阅读压力    |

**对齐原则**：

- **正文** → 两端对齐（避免右边缘参差不齐）
- **短文本/注释** → 居中对齐（瞬间提升高级感）
- **标题** → 主标题居中，章节标题左对齐

#### 11.4 配色策略与色彩心理学

**黄金法则**：1个主色 + ≤2个辅助色

**色彩心理学应用**：

| 情感目标  | 推荐颜色        | 适用场景        |
| ----- | ----------- | ----------- |
| 专业与可信 | 蓝色、灰色       | 科技、商务、企业内容  |
| 活力与积极 | 橙色、黄色       | 励志、正能量、营销内容 |
| 清新与文艺 | 莫兰迪色系（低饱和度） | 生活方式、美学、文艺  |
| 知识与教育 | 青绿色         | 教程、知识分享     |
| 奢华与高端 | 紫色、金色       | 高端品牌、奢侈品    |
| 健康与自然 | 绿色          | 养生、健康、环保    |

**按内容类型的专业配色方案**：

| 内容类型        | PRIMARY\_COLOR（主色） | ACCENT\_COLOR（辅助色） | 说明        |
| ----------- | ------------------ | ------------------ | --------- |
| **科技/商务**   | #1E88E5（企业蓝）       | #E3F2FD（浅蓝背景）      | 专业、可信、冷静  |
| **生活方式/美食** | #A8DADC（莫兰迪粉蓝）     | #F1FAEE（奶白背景）      | 清新、文艺、柔和  |
| **励志/能量**   | #FF6B35（活力橙）       | #FFF3E0（暖黄背景）      | 积极、热情、有活力 |
| **教育/知识**   | #00897B（青绿）        | #E0F2F1（浅绿背景）      | 智慧、成长、学习  |
| **奢华/高端**   | #7B1FA2（紫）         | #F3E5F5（浅紫背景）      | 优雅、高端、神秘  |
| **健康/养生**   | #43A047（绿）         | #E8F5E9（浅绿背景）      | 自然、健康、生机  |

**正文字色标准**：

- 推荐正文：#3f3f3f（比纯黑#000000更柔和）或 #595959（更柔和，适合长文）
- 强调文字：使用品牌主色 + 加粗
- 注释/元数据：#999999 或 #AAAAAA（浅灰，弱化显示）

**关键强调规则**：每屏高亮项目≤3个。全部高亮 = 没有重点！

#### 11.7 图片放置指南

**图片放置位置（⭐强制规则）**：

**配图必须紧跟在每个章节标题的下方**，不要放在章节内容的末尾。

❌ 错误放置（图片在文末）：
```markdown
## Notion 的野心

正文内容第一段...

正文内容第二段...

![配图](images/02-notion.png)
```

✅ 正确放置（图片在标题下方）：
```markdown
## Notion 的野心

![配图](images/02-notion.png)

正文内容第一段...

正文内容第二段...
```

**信息图放置位置**：信息图放在文章标题和正文之间（引言之前），作为全文概览。

**章节配图放置位置**：每张章节配图放在该章节 `##` 标题的正下方、正文内容的正上方。读者先看到标题，再看到配图，再进入正文——视觉节奏更流畅。

**最佳图片数量**：每篇文章 5-8 张（含信息图）

**图片规格标准**：

- **宽度**：100%（响应式）
- **最大宽度**：桌面端750px
- **格式**：JPG或PNG
- **文件大小**：< 500KB以快速加载
- **宽高比**：推荐16:9或4:3
- **圆角**：8px呈现现代感
- **阴影**：微妙的阴影增加层次

**图片占位符格式**：

```html
[IMAGE_PLACEHOLDER_1: 展示产品使用场景的高清照片]
[IMAGE_PLACEHOLDER_2: 数据图表或信息图]
[IMAGE_PLACEHOLDER_3: 团队合影或活动现场]
```

#### 11.10 常见排版错误避免清单

| 错误     | 说明            | 后果          |
| ------ | ------------- | ----------- |
| 彩虹乱色   | 使用5种以上颜色破坏整体感 | 视觉混乱、品牌识别丧失 |
| 文字墙    | 无间距 = 瞬间阅读疲劳  | 完读率骤降、用户跳出  |
| 强调过载   | 太多强调 = 无强调    | 重点不突出、信息无效  |
| 风格不一致  | 文章中间切换字体/颜色   | 品牌印象混乱      |
| 字号过大   | 18px以上正文缺乏精致感 | 视觉上不够专业     |
| 缺少视觉断点 | 无图片或章节分隔线     | 阅读压力大       |
| 正文居中对齐 | 手机端难以阅读       | 阅读体验差       |
| 忽略手机预览 | 发布前不检查手机显示    | 实际效果与预期不符   |
| 标点符号滥用 | 过多的感叹号、省略号    | 不专业、显得浮夸    |
| 段落过长   | 手机屏幕超过2屏      | 阅读疲劳        |

#### 11.11 移动端优化检查清单

- [ ] 最大宽度设为750px并居中

- [ ] 除容器外无固定宽度
