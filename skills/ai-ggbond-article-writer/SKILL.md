## 飞哥文章深度偏好（2026-05-18确认）

- **最低字数**：8000字（不是技能默认的2000字），理想区间8000-12000字
- **结构原则**：由浅入深——事件引入→概念纠偏→本质揭示→技术深挖→产业分析→冷思考→升华
- **热点使用方式**：热点事件（如Figure AI直播）只是**切入点和药引子**，不是文章主体。文章的核心是帮读者建立对某个领域的**完整认知框架**。不要写"XX事件怎么样"，要写"通过XX这件事，我们该怎么理解这个赛道"
- **认知框架优先**：每篇文章应让读者读完后能"跟别人聊明白"这个领域——建立概念体系、理清技术路线、知道谁在做什么、理解底层逻辑
- **科学理论贯穿**：善用数理理论（凯利公式、贝叶斯、幂律分布）、心理学（锚定效应、损失厌恶）、博弈论（纳什均衡、囚徒困境）、进化论、热力学、控制论等辅助表达。让观点有科学骨架支撑
- **选题确认流程**：当用户给一个主题时，先判断该主题的深度层级，提供3-5个由浅入深的选题方向，每个方向标注深度星级（⭐~⭐⭐⭐⭐⭐）和预估字数

## 飞哥配图风格偏好（2026-05-19纠偏）

- **不要把某一种风格当成硬性唯一风格**：飞哥纠正过，公众号文章/内容配图通常根据内容选择**手绘图或信息图**，不是固定科技蓝扁平矢量，也不是拒绝手绘。
- **按场景选图**：观点类/方法论类优先手绘信息图、概念图；技术架构/工具链/工作流类优先信息图、流程图、系统架构图，可用科技蓝；个人经历/认知复盘类优先手绘插画或漫画感场景图；企业AI落地/解决方案类优先专业信息图、流程图、对比图。
- **推荐混合策略**：长文可采用“手绘信息图 + 专业结构图”混合风格——核心认知用手绘信息图承载人味，系统架构/流程链路用科技蓝或专业信息图保证清晰度。
- **禁止错误表达**：不要再写“拒绝手绘”“只能科技蓝扁平矢量”之类绝对化描述；如需生成配图方案，先基于文章主题说明每张图为什么选择手绘/信息图/结构图。

## 飞哥公众号精排版硬性禁令（2026-05-19 发飙复盘，v2.1.0）

这次《AI工具的下半场》发布暴露了排版洁净度问题，必须作为 P0 规则写入技能。以后给飞哥做公众号文章，只要进入 HTML 精排/发布阶段，先执行这些禁令，再谈美化。

### P0 删除项：这些内容不要出现在正文

- **不要插入阅读元信息行**：禁止生成 `📊 约 xxxx 字 · 建议阅读 x 分钟 · 点击右上角🎧可听阅`。飞哥不需要这种模板化公众号提示，它会暴露工具痕迹，破坏文章开场气质。
- **不要给正文图片加图注**：禁止在每张图下方显示 `全文核心信息图：...`、`配图：...`、`图片说明：...` 这类 figcaption。图片只作为视觉断点和理解辅助，不能在正文里反复解释自己。
- **不要把 alt 文本渲染成可见文字**：Markdown/HTML 中可以保留 alt 方便上传和可访问性，但发布版 HTML 必须隐藏图注，不得把 alt 原样显示到图片下面。

### P0 洁净度原则：卡片不要叠卡片

- **引用卡片和独立金句卡片不要连续出现**。如果一个观点后面已经紧跟引用卡片，就不要再把前一句做成独立金句卡片。
- **同一个语义落点只能选择一种视觉强调**：正文加粗、独立金句卡片、引用卡片三选一，最多二选一但必须有足够文本缓冲；不要“金句卡片 + 引用卡片 + 加粗解释”三连。
- **引用卡片优先承载有出处的话**，独立金句卡片优先承载本文原创核心判断；两者相邻时，默认取消独立金句卡片，改成正文自然加粗。

错误示例：
```text
[独立金句卡片]
真正改变行业的工具，往往不是一开始最完美的那个，而是第一个把旧流程压缩掉的那个。

[引用卡片]
《创新者的窘境》作者克莱顿·克里斯坦森提醒我们：破坏性创新往往从“不够完美”的边缘开始。
```

正确处理：
```text
真正改变行业的工具，往往不是一开始最完美的那个，而是第一个把旧流程压缩掉的那个。

[引用卡片]
**《创新者的窘境》作者克莱顿·克里斯坦森提醒我们：破坏性创新往往从“不够完美”的边缘开始。**
```

### 发布前强制自检

发布前必须检查 HTML：
- `建议阅读`、`点击右上角`、`全文核心信息图`、`配图：`、`图片说明`、`figcaption` 不得出现在正文可见区域。
- 独立金句卡片数量不超过 3 个；若文章引用卡片多于 2 个，独立金句卡片最多 1 个。
- 任意两个视觉重组件之间至少间隔 2 个自然段：图片、引用卡片、独立金句卡片、CTA 卡片都算重组件。
- 若不确定干不干净，优先删除装饰，保留正文。**公众号排版不是展示技能的地方，而是降低读者理解摩擦的地方。**

## 核心原则

### 必须严格遵守的 7 个要点

1. **第一人称叙述**
   - 用「我和专家大佬轻松聊天」的视角写作：分享真实的交流经历、踩坑故事、实战心得
   - 这是Native超级个体的个人分享，不是官方文档
   - 基于真实经历写作，不编造不真实的场景
2. **观点鲜明但有理有据**
   - 敢于表达立场：「我认为 A 比 B 更适合这个场景」
   - 但必须给出理由和依据，不能空口说
3. **实战导向**
   - 要先讲自己的认知，以及在大佬沟通过程中达成共识后的独到见解
   - 尽量用互联网上最近发生的事情，用真实案例和场景说话
   - **必须有真实的使用场景**:不要堆数据、列参数，而是用"振聋发聩的看法和认知"来展示价值
   - 展示具体的使用过程和结果，包括成功和失败的案例
   - 如果是问题或者建议，最好能和大佬一起给出应对问题的策略，然后告诉普通人要怎么做
4. **个人IP自然融入**
   - **不要刻意**：不在文章开头或结尾生硬地自我介绍，而是在内容中自然带出
   - **场景化呈现**：
     - 分享踩坑经历：「我在折腾这个项目的时候，踩过一个坑...」
     - 展示工作流：「我自己平时用这套工作流处理类似的需求...」
     - 提及圈内交流：「上周和圈子里的大佬聊到这个话题...」
     - 表达个人偏好：「我自己更喜欢用A而不是B，因为...」
   - **价值先行**：先提供有价值的内容，IP形象通过内容质量自然建立
   - **保持一致性**：用「AI朱朱侠」的口吻贯穿全文，但不用刻意强调这个名字
- **文章配图是强制要求**：
   - **主题封面图**：每篇文章必须生成一张主题封面图，比例2.35:1（2350x1000px）；风格按文章内容选择，不要一刀切
   - **深度信息图**：每篇文章必须生成一张深度信息图，比例**16:9横版**（1792x1024px），放在文章开头，必须包含文章完整核心内容
   - **主体内容配图**：推荐5-8张，长文可提升到10-12张；比例**统一16:9横版**（1792x1024px），从36种信息图类型中选择
   - **飞哥配图偏好（重要）**：公众号文章和内容配图通常偏好根据内容选择**手绘图或信息图**；不要默认拒绝手绘，也不要固定只用科技蓝扁平矢量。技术/商业/架构类可用科技蓝结构图；观点/方法论/个人工作流类可用手绘信息图；一篇文章可混合“手绘信息图 + 科技蓝结构图”。
   - 图片文字使用简体中文，必须保证清晰、不变形、无重影、无乱码
   - Pillow 仅用于轻量水印叠加，禁止用 Pillow 主生成配图内容
   - 封面图与章节配图默认使用中低信息密度，保持干净整洁；信息图可高密度但必须结构清晰且不重复
   - **文件大小限制**：所有配图不超过5MB（确保快速加载）
6. **链接使用纯文本格式**
   - ❌ 错误：`[官网](https://example.com/)`
   - ✅ 正确：`官方网站：https://example.com/`

### 步骤 3：判断内容类型（⭐必须）

**强制规则**：

- 当用户输入一个主题时，**必须先判断内容类型**
- **必须明确告知用户该主题属于哪类内容**
- **必须等待用户确认内容类型后才能进入选题策划**

根据主题特征，判断属于哪类内容：

- **AI 产品拆解**：聚焦某个具体AI产品/工具的功能、设计、体验分析
- **场景解决方案**：针对特定场景/问题的完整解决方案
- **效率提升实战**：分享提效技巧、工作流、工具组合
- **产品方法论**：总结提炼的方法、框架、最佳实践
- **行业观察**：行业趋势、现象分析、未来预测

**内容类型判断输出格式**：

```text

【判断理由】：
- [理由1]
- [理由2]
- [理由3]

【适合的写作角度】：
- [角度1]
- [角度2]
- [角度3]

请确认这个内容类型判断是否准确？如果同意，我将基于这个类型进行选题策划。
如果不同意，请告诉我您认为应该属于哪种类型，以及原因。
```

### 步骤 7：写作

**写作原则**：

- **拒绝注水**：不要为了凑字数而重复废话
- **自然段落结构**：采用散文式自然段落，避免使用01、02、03等连续编号形式
- **故事感**：用一条主线故事串联起所有的技术点
- **金句频出**：每隔 500-800 字，需要有一个能够被读者划线转发的金句/洞察
- **⚠️ 图片引用必须内联到 Markdown**：每张配图必须在正文中用 `![图片说明](images/xxx.png)` 语法引用，否则推送到公众号时脚本检测不到图片（`Placeholder images: 0`），正文图片全部丢失。**这是最常见的坑——图片文件存在但文章里没有引用。**

**段落组织规范**：

❌ **避免的编号形式**：

```markdown
## 01. 什么是超级个体

内容...

## 02. 为什么超级个体是个坑

内容...

## 03. 普通人该怎么走

内容...
```

✅ **推荐的自然段落形式**：

```markdown
## 什么是"超级个体"

说起来，"超级个体"这个概念最近火得不行...

## 为什么我说这是个坑

说实话，我一开始也被这个概念吸引了...

## 普通人到底该怎么走

折腾了大半年，我有些想法想分享...
```

**自然过渡技巧**：

1. **用问题过渡**：「那问题来了，普通人该怎么办？」
2. **用转折过渡**：「不过，事情没那么简单。」
3. **用故事过渡**：「这让我想起之前的一次经历...」
4. **用金句过渡**：「说到底，工具是为人服务的。」

**小标题设计原则**：

- 使用完整句子或短语，不要用编号
- 标题本身带有情感或观点
- 标题之间有逻辑递进关系
- 每个小标题下2-4个自然段落

**段落长度控制**：

- 每段3-5行（手机屏幕1-1.5屏）
- 段落之间空一行
- 避免大段文字墙

### 步骤 8：三遍审校

#### 第一遍：基础检查

- 错别字、标点符号、格式规范
- 链接格式（纯文本，不用Markdown链接）
- 图片标注是否完整

#### 第二遍：去AI味，优化表达和逻辑（⭐核心步骤）

**为什么AI写的东西有"塑料味"？**

1. **陈词滥调的结构**：开头"在快速发展的..."，结尾"总而言之..."
2. **滥用"大词"**：明明是"研究"，非要说"深入探讨"；明明是"使用"，非要说"赋能"
3. **缺乏观点的中立**：总是用"值得注意的是"对冲观点

**去AI味五步法**：

**Step 1：负向词表清洗**

| AI词（禁止使用） | 人类词（替换使用）          |
| --------- | ------------------ |
| 深入探讨/深入研究 | 研究、看、聊             |
| 赋能、助力     | 帮助、让               |
| 优化、提升     | 改进、变好              |
| 总而言之、综上所述 | \[直接停止] / 简短有力句子   |
| 此外、另外     | 而且、还有 / \[直接开始新句子] |
| 值得注意的是    | 说实话、有意思的是          |
| 在...背景下   | \[直接开始]            |
| 多维度的、全方位的 | 多方面的、各种            |
| 生态系统      | 系统、圈子              |
| 颠覆性的      | 大的、重要的             |
| 核心竞争力     | 优势、强项              |
| 深度融合      | 结合、混在一起            |
| 落地场景      | 实际用法               |

**Step 2：节奏感注入（Burstiness）**

AI生成文本句子长度很平均。人类写作是"长短句交替"。

```
节奏感要求：
1. 混合短句（3-10字）和长句（20-40字）
2. 允许使用句子片段制造效果
   例："真的吗？至少今天不是。"
3. 不要每句都用"此外"、"然而"开头
4. 直接用主语或动词开始句子
5. 段落长度变化（1-3句一段）

好例子：
"项目失败了。没钱了。团队熬了三个月，实在撑不下去了。"

坏例子（AI味）：
"此外，项目失败的主要原因是资金短缺。另外，团队在长时间工作后也出现了疲劳问题。"
```

**Step 3：观点极化**

强制选边站，禁止当"理中客"。

```
观点极化规则：
1. 不要平衡论点（"有利有弊"、"因人而异"）
2. 选择一边，坚定地辩护
3. 禁止使用：
   - "有利有弊"
   - "这取决于..."
   - "另一方面..."
   - "有人可能会说..."
4. 使用强动词：
   - "这证明了..."（不是"这可能表明..."）
   - "这就是..."（不是"这可能是..."）
5. 使用第一人称（"我"、"我的"）增加主观性

示例：
❌ AI味：AI对社会既有好处也有挑战。
✅ 人味：AI会重塑社会，不管你喜不喜欢。好处太大了，根本没法忽视。
```

**Step 4：口语化叙事（自然对话测试）**

这句话你在和朋友聊天时会说吗？

```
口语化要求：
1. 使用简单、口语化的表达
2. 语法可以稍微松散
3. 自然使用语气词（"嗯"、"说实话"、"怎么说呢"）
4. 用日常生活的比喻
5. 如果概念太无聊，跳过它
6. 不要用企业黑话
7. 直接称呼（"你"、"你的"）
8. 偶尔打断自己（然后自我纠正）

示例：
"所以基本上，LLM这东西...它不是真的在思考，对吧？它只是在预测下一个词是什么。就像我说'花生酱'，你就知道'果冻'要来了。就这样。这就是全部把戏。"
```

**Step 5：添加人味元素**

```
加入元素清单：
□ 短句（3-10字）
□ 句子片段
□ 口语化表达
□ 个人经历/观点
□ 不完美的语法
□ 情感词汇
□ 具体例子（不是抽象概念）
□ 自嘲或幽默
```

**去AI味检查清单**：

```
□ 是否有"在快速发展的背景下"类开头？
□ 是否有"深入探讨"、"赋能"、"优化"？
□ 是否有"此外"、"另外"、"综上所述"？
□ 句子长度是否太均匀？
□ 是否缺乏个人观点？
□ 是否过于正式/学术？
□ 读起来像AI朱朱侠在说话吗？
```

#### 第三遍：风格检查和内容升华

- 检查是否符合AI朱朱侠风格（口语化、心路历程、具体细节）
- 确保个人IP自然融入
- 金句提炼和内容升华
- 开头是否抓人、结尾是否有行动引导

#### 10.4 使用云雾API生成图片（⭐强制要求 - V4最终版）

**⚠️ 重要说明**：生图功能**默认使用** **`gpt-image-2`** **模型**，通过 OpenAI Images API (`/v1/images/generations`) 调用，中文渲染效果最佳。

##### 🔴 模型与故障处理铁律（必须严格遵守）

**铁律一：模型不可擅改**
- 用户指定的模型（如 gpt-image-2）**必须严格使用**，不得因限流、报错等原因自行切换到其他模型（如 gpt-image-1、dall-e-3 等）
- 不同模型的出图风格、中文渲染质量、分辨率支持差异巨大，擅自换模型 = 出图全部作废
- 如果指定模型不可用（429/503/限流），**必须立即暂停，通知用户**，等待用户指示
- 通知格式：`"⚠️ 生图模型 {model} 当前不可用（错误：{error}），已暂停。请确认：1）等待恢复后重试 2）更换模型（请指定）"`

**铁律二：API 问题找用户，不自作主张**
- API Key 无效、额度耗尽、账户异常等问题，**不要自行尝试其他端点、其他 Key、或重试其他模型**
- 立即通知用户：`"⚠️ API 遇到问题（{error}），请检查 API Key 和账户额度。已暂停，等您确认后继续。"`
- 用户会自行解决 API 问题，Agent 只需等待确认，**绝不自作主张**

**铁律三：重试策略（仅限同一模型临时限流）**
- 同一模型遇到临时限流（429），可等待 15-30 秒后重试，最多 3 次
- 3 次仍失败 → **立即暂停，通知用户**，不得继续
- 不得在重试过程中更换模型或切换 API 端点
- 重试间隔建议：15s → 30s → 60s（递增）

#### 10.4.0 图片生成常见问题与解决方案（⭐重要）

在实际使用中，我们发现以下常见问题及对应的解决方案：

##### 问题1：图片内容全是英文，而非中文

**问题表现**：

- 生成的图片标题、标签、说明文字都是英文
- 即使提示词用中文描述，模型仍输出英文内容

**根本原因**：

- 部分图像模型（如Gemini系列）对中文的支持不够稳定
- 复杂提示词结构下，模型倾向于使用英文输出
- 提示词中没有**强制要求**必须使用中文

**解决方案**：

1. **使用稳定模型**（推荐）
   ```python
   model="gpt-image-2"
   ```
2. **在提示词中强制要求中文**
   ```
   【强制要求】
   - 所有文字必须使用简体中文，绝对禁止出现英文
   - 标题："中文标题"
   - 标签："中文标签"
   - 任何文字都必须是中文
   ```
3. **使用引号明确标注中文内容**
   ```
   标题必须显示为："从AI工具到AI团队的进化"
   副标题必须显示为："多Agent协作网络"
   ```
4. **添加负面约束**
   ```
   【禁止事项】
   - 绝对禁止出现英文文字
   - 绝对禁止出现乱码或无法识别的字符
   - 绝对禁止出现拼音代替中文
   ```

##### 问题2：图片结构与章节内容无关

**问题表现**：

- 生成的图片虽然美观，但与文章具体内容的契合度不够
- 图片展示的是通用概念，而非文章中的具体观点、案例或流程
- 读者无法从图片中获得文章的核心信息

**根本原因**：

- 提示词过于**通用和模板化**，没有紧密结合文章的具体内容
- 提示词设计时更多关注了视觉风格，而忽略了内容的准确性
- 没有从文章中提取**核心观点、关键案例、具体流程**来指导图片生成

**解决方案**：

1. **从文章提取具体内容生成提示词**
   ```python
   # 1. 读取文章并提取关键信息
   with open("文章.md", 'r', encoding='utf-8') as f:
       content = f.read()

   # 2. 提取章节标题和核心要点
   sections = extract_sections(content)  # 提取章节结构
   key_points = extract_key_points(content)  # 提取核心观点

   # 3. 基于具体内容构建提示词
   prompt = f"""
   创建章节配图，主题是：{section_title}

   【必须展示的具体内容】
   - 核心观点1：{key_points[0]}
   - 核心观点2：{key_points[1]}
   - 案例：{case_example}
   - 数据：{specific_data}

   【视觉元素要求】
   - 必须包含：{specific_visual_elements}
   - 必须展示：{article_specific_content}
   """
   ```
2. **提示词结构模板（内容导向）**
   ```
   创建一张微信公众号章节配图，16:9横版。

   【文章章节主题】
   {章节标题}

   【必须展示的核心内容】（基于文章实际内容）
   1. {核心观点1 - 直接引用文章}
   2. {核心观点2 - 直接引用文章}
   3. {具体案例 - 文章中的实例}
   4. {关键数据 - 文章中的数字}

   【视觉元素要求】
   ```

### 步骤 11：文章排版优化（⭐专业排版）

将 Markdown 文章转换为适合微信公众号的专业 HTML 格式，确保移动端阅读体验、视觉吸引力和信息传达效率。

**重要纠偏：金句断点与 HTML 精排版**

当用户要求“金句断点”时，这是阅读节奏设计，不是正文标题。严禁把“金句断点”四个字写进正文。应以正文自然加粗短句为主，少量独立金句卡片，少量引用块点缀。公众号长文不要每句话都换行，要大量合并段落，形成长短交替的节奏。若用户对 `ai-ggbond-post-to-wechat` 默认主题不满意，应先生成自定义 HTML 精排预览版，用户确认后再推送草稿；不要直接重推。

详见：`references/wechat-html-precision-typesetting.md`

***

#### 11.1 排版核心原则与目的驱动设计

**飞哥长文语义节奏纠偏（强制）**：给飞哥做公众号长文精排时，分段要遵循“等这一口逻辑说完，再分段”，不是按句号机械切，也不是为了避免碎而合成大段。详见 `references/wechat-semantic-rhythm-typesetting.md`。金句断点是编辑策略，禁止把“金句断点”四个字写进正文；引用原文必须加粗，引用卡片可少量保留；独立金句卡片控制在 4 个以内。若需全文重排，先做 800-1000 字语义节奏样稿给飞哥确认，再生成 HTML 精排预览，确认后才推公众号草稿。

**排版三大核心功能**：

1. **拯救碎片化注意力**：读者只有3秒注意力（地铁、卫生间、工作间隙），清晰布局实现"无痛阅读"
2. **视觉导航系统**：层级标题如同路标，关键词高亮实现3秒信息抓取
3. **视觉品牌识别**：一致排版 = 可识别的品牌签名，坚持3个月建立品牌印记

**风格一致性公式**：

```
风格 = 标题格式 + 主色调 + 正文格式 + 图片风格 + 头尾引导
```

**关键规则**：坚持一种风格至少3个月。频繁切换风格（今天文艺风，明天赛博朋克）会导致粉丝流失。

#### 11.3 字体排版规范

**字体族（兼容全平台）**：

```
-apple-system, BlinkMacSystemFont, 'Segoe UI', 'PingFang SC', 'Hiragino Sans GB', 'Microsoft YaHei', sans-serif
```

**字号指南**：

| 字号   | 用途       | 说明           |
| ---- | -------- | ------------ |
| 24px | 主标题（H1）  | 居中，加粗，视觉焦点   |
| 17px | 章节标题（H2） | 左对齐，加粗，高对比度  |
| 15px | 正文       | 安全默认选择，永不出错  |
| 14px | 紧凑优雅风格   | 文艺类账号，更精致    |
| 13px | 说明文字     | 图片说明、注释来源    |
| 12px | 元数据      | 日期、阅读时长等弱化信息 |

**文章元数据行排版规范（飞哥发布版禁用）**：

飞哥公众号发布版禁止在正文标题下插入阅读元信息行。不要生成 `📊 约 xxxx 字 · 建议阅读 x 分钟 · 点击右上角🎧可听阅`，也不要生成任何类似“阅读时长/听阅提示”的模板化提示。

原因：这类元信息会把文章从“观点内容”拉回“模板产物”，暴露工具痕迹，破坏开场的干净度。若确实需要统计字数或阅读时长，只能放在内部审校报告里，不得进入发布版正文。

**标签行排版规范**：

`#Harness #HarnessEngineering ...` 标签行：
1. **居中对齐**
2. **字号 10px**
3. **颜色 #999**

**HTML 模板**：
```html
<p style="font-size: 10px; color: #999; text-align: center; margin: -15px 0 25px 0;">
  #Harness #HarnessEngineering ...
</p>
```

**注意**：面向老年读者时增加+2px

**行高与间距**：

| 类型     | 规范        | 说明            |
| ------ | --------- | ------------- |
| 字间距    | 0.5px     | 正文标准，避免二维码压缩  |
| 标题行高   | 1.3-1.4   | 标题不宜太松        |
| 正文行高   | 1.75      | 亲密但不拥挤，最佳阅读体验 |
| 说明文字行高 | 1.5       | 紧凑但清晰         |
| 段落间距   | 段落间1空行    | 视觉分隔清晰        |
| 章节间距   | 上2行 + 下1行 | 大标题前空两行       |
| 两侧边距   | 8-16px    | 边缘留白减轻阅读压力    |

**对齐原则**：

- **正文** → 两端对齐（避免右边缘参差不齐）
- **短文本/注释** → 居中对齐（瞬间提升高级感）
- **标题** → 主标题居中，章节标题左对齐

#### 11.7 图片放置指南

**图片放置位置（⭐强制规则）**：

**配图必须紧跟在每个章节标题的下方**，不要放在章节内容的末尾。

❌ 错误放置（图片在文末）：
```markdown
## Notion 的野心

正文内容第一段...

正文内容第二段...

![配图](images/02-notion.png)
```

✅ 正确放置（图片在标题下方）：
```markdown
## Notion 的野心

![配图](images/02-notion.png)

正文内容第一段...

正文内容第二段...
```

**信息图放置位置**：信息图放在文章标题和正文之间（引言之前），作为全文概览。

**章节配图放置位置**：每张章节配图放在该章节 `##` 标题的正下方、正文内容的正上方。读者先看到标题，再看到配图，再进入正文——视觉节奏更流畅。

**最佳图片数量**：每篇文章 5-8 张（含信息图）

**图片规格标准**：

- **宽度**：100%（响应式）
- **最大宽度**：桌面端750px
- **格式**：JPG或PNG
- **文件大小**：< 500KB以快速加载
- **宽高比**：推荐16:9或4:3
- **圆角**：8px呈现现代感
- **阴影**：微妙的阴影增加层次

**图片占位符格式**：

```html
[IMAGE_PLACEHOLDER_1: 展示产品使用场景的高清照片]
[IMAGE_PLACEHOLDER_2: 数据图表或信息图]
[IMAGE_PLACEHOLDER_3: 团队合影或活动现场]
```

**❌ 改造前 - 常见错误示例**：

```
今天给大家分享一个超级厉害的AI工具,就是DeepSeek,这个工具真的是太好用了,我用了之后发现它可以做很多事情,比如说写代码,写文章,做翻译,还可以生成图片,真的是太强大了!而且最重要的是它还是免费的!!!你们一定要去试试!!!
```

- ❌ 过度强调（所有内容都"重要"）
- ❌ 无间距，阅读体验拥挤
- ❌ 无图片或视觉分隔

#### 11.12 质量检查三问与发布前验证

**发布前灵魂拷问**：

1. **读者能在3秒内找到重点吗？**
2. **在手机屏幕上看会累眼吗？**
3. **整体风格是否统一，像一个人写的？**

**终极原则**：排版服务于读者，而非自我满足！

**复制粘贴工作流程**：

1. 按照此模板生成完整HTML代码

4. 粘贴HTML
5. 切换回可视化模式

7. 发布前在手机上预览
