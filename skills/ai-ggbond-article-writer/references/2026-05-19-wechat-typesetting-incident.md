# 2026-05-19 公众号精排事故复盘：AI工具的下半场

## 背景

文章《AI工具的下半场：从回答权，到执行权》内容重写通过后，进入 HTML 精排并推送到微信公众号草稿箱。发布版暴露出明显“排版工具痕迹”和“视觉组件过度设计”问题，飞哥手动修正后要求把问题沉淀进 `ai-ggbond-article-writer` skill。

## 具体问题

### 1. 模板化元信息污染开场

错误输出：

```text
📊 约 8000 字 · 建议阅读 18 分钟 · 点击右上角🎧可听阅
```

问题本质：这类信息属于内部编辑/排版辅助，不属于文章正文。它让读者第一眼看到的不是观点，而是模板组件，削弱文章气质，也暴露 AI/自动化工具痕迹。

修正规则：飞哥公众号发布版一律不要在正文标题下插入阅读时长、字数统计、听阅提示等元信息。若需要统计，只能放在内部审校报告，不能进入正文。

### 2. 图片 alt/说明被渲染成可见图注

错误输出：

```text
全文核心信息图：AI工具从聊天工具走向执行系统
配图：从聊天框到工作流系统的迁移
```

问题本质：图片在公众号长文里是视觉断点和理解辅助，不是二次标题。章节标题已经承担导航功能，图片下方再加图注会造成噪音，使页面看起来像报告或 PPT，而不是一篇干净的公众号文章。

修正规则：Markdown/HTML 可以保留 `alt` 用于上传识别和可访问性，但发布版不要生成 `<figcaption>`，也不要把 `alt` 渲染成可见文字。

### 3. 引用卡片与独立金句卡片连续出现，视觉过重

错误结构：

```text
[独立金句卡片]
真正改变行业的工具，往往不是一开始最完美的那个，而是第一个把旧流程压缩掉的那个。

[引用卡片]
《创新者的窘境》作者克莱顿·克里斯坦森提醒我们：破坏性创新往往从“不够完美”的边缘开始。
```

问题本质：两者都属于“重组件”。连续出现会让页面显得不干净，像在堆设计元素，而不是服务阅读。一个语义落点被反复强调，读者会感觉作者在“用力过猛”。

修正规则：同一语义落点只能选择一种视觉强调。若原创判断后面紧跟有出处的引用，默认保留引用卡片，把原创判断放回正文并自然加粗，不做独立金句卡片。

### 4. 排版目标偏离：把“美化”误当成“阅读体验”

这次问题的深层原因不是某一个组件错了，而是排版目标错了：把 HTML 精排理解成“加组件、加卡片、加说明”，而不是“减少理解摩擦”。

飞哥要的是：

- 白底黑字，高留白
- 少量技术蓝点缀
- 语义节奏自然
- 图片只做视觉断点
- 引用和金句克制使用
- 页面干净，不暴露工具痕迹

公众号排版不是展示技能的地方，而是让读者更顺畅地读完文章。

## 新增硬规则

1. 禁止发布版正文出现：`建议阅读`、`点击右上角`、`全文核心信息图`、`配图：`、`图片说明`、`figcaption`。
2. 独立金句卡片默认不超过 3 个；如果引用卡片超过 2 个，独立金句卡片最多 1 个。
3. 引用卡片和独立金句卡片不得连续出现。
4. 任意两个视觉重组件之间至少间隔 2 个自然段。
5. 不确定是否该加组件时，优先删除装饰，保留正文。

## 发布前检查命令示例

```bash
python3 - <<'PY'
from pathlib import Path
p = Path('发布版.html')
s = p.read_text(encoding='utf-8')
for bad in ['建议阅读', '点击右上角', '全文核心信息图', '配图：', '图片说明', '<figcaption']:
    if bad in s:
        print('BAD:', bad)
PY
```

## 一句话原则

**好排版不是让读者看到排版，而是让读者忘了排版。**
