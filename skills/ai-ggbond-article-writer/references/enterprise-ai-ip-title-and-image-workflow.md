# 企业 AI 个人 IP 文章：标题与配图工作流

## 适用场景

当文章来自大型复杂企业的一线观察，同时需要建立个人 IP，但不能暴露具体岗位、内部项目或公司官方立场时使用。

## 一、个人 IP 融入原则

### 把公司当作观察视角，不当作文章案例

正确：
- 「进入顺丰总部做 AI 后，我开始同时生活在技术与业务两种语言里。」
- 「从顺丰这样的复杂物流网络看，真正考验 Agent 的是异常。」

避免：
- 暴露具体职位名称，例如 FDE。
- 暗示「顺丰正在建设某系统」或披露内部架构、指标、客户、项目名。
- 反复写「在顺丰我看到」，把文章变成公司案例汇报。

公司只负责提供实践信用，真正要输出的是可迁移到其他复杂企业的方法论。

## 二、标题：身份锚点不能变成职业简历

### 失败模式

`我在顺丰总部做 AI 后，越来越确定：企业不缺 Agent，缺的是一套敢让它干活的能力体系`

问题：
- 同时塞入职业、公司、观点和内容摘要。
- 答案全部说完，没有悬念。
- 像履历加报告摘要，不像传播标题。

### 推荐模式

`从[实践视角]看[对象]：行业都在[A]，企业真正缺的是[B]`

要求：
- 实践锚点只留一个，例如「从顺丰看」。
- A 与 B 必须形成二极管冲突。
- A 是行业显性竞争，B 是企业真实缺口。
- B 尽量用具象隐喻，不要用长技术术语。

成功例：

> 从顺丰看 Agent：行业都在拼智商，企业真正缺的是手脚

标题不解释「手脚」是什么，正文再逐层揭示：系统接口、业务能力、权限、审计、回滚和人工接管。

## 三、正文中的隐喻对应

- 智商：模型理解、推理、规划能力。
- 手脚：订单、库存、工单、审批、沟通等可调用业务能力。
- 神经与制度：身份、权限、策略、审计、熔断和人工接管。

隐喻必须贯穿正文和配图，不能只在标题出现一次。

## 四、配图前置确认

生成前确认：
1. 模型，默认严格使用 gpt-image-2。
2. 风格与主色。
3. 数量和完整图片清单。
4. 封面上的准确短标题。

先保存：
- `images/prompts/image-plan.md`
- 每张图独立的 `images/prompts/NN-name.md`

封面标题应比文章标题更短。本案例封面短标题为：

> 拼智商，缺手脚

## 五、gpt-image-2 批量生成的可靠方式

### 内置工具读到旧配置时

先区分「内置工具配置未刷新」和「实际图片后端不可用」。不要反复调用同一路径。

如果本机已有 OpenAI 兼容代理，可先对 `/v1/images/generations` 做最小请求验证。验证成功后，用同一模型、同一尺寸和同一提示词批量生成。此举是 API 路由切换，不是更换模型。

批量脚本要求：
- 固定 `model: gpt-image-2`。
- 横版使用 `size: 1536x1024`。
- 返回 `b64_json` 时解码保存 PNG。
- 已存在且尺寸正常的文件自动跳过，支持断点续跑。
- 后台运行并启用完成通知。
- 每张图保存生成元数据 JSON，便于追踪。

## 六、逐张质检，而不是只检查文件存在

每张图检查：
- 尺寸、比例、文件大小。
- 主题表达是否准确。
- 中文标签是否逐字正确。
- 是否出现意外文字、品牌 Logo、水印和二维码。
- 信息图是否无需正文解释也能看懂。

如果图很美，但读者无法辨认逻辑关系，仍然判不通过。修复时只重生问题图，不返工整批。

本案例中「行动半径」初版只有同心圆和图标，无法明确表达风险递增、策略闸门和人工确认，因此重生时加入短标签：
- 只读
- 分析与沟通
- 高风险动作
- 策略校验
- 人工确认
- 风险递增

短标签 + 结构化分区比纯视觉隐喻更适合治理类信息图。

## 七、正文插图规则

- 封面单独保存，不插入正文。
- 总信息图放在引言后。
- 章节图放在对应 `##` 标题下方。
- Markdown 必须真实内联：`![说明](images/xxx.png)`。
- 发布版不显示图注，alt 只用于资源识别和可访问性。
