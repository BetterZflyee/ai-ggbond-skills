# AI朱朱侠写作风格参考

## 核心风格特征

### 1. 真实可感

**特征**：有具体的时间、地点、人物、事件，不是泛泛而谈。

**示例**：
```markdown
❌ 最近我在研究AI工具，发现了一些有趣的东西。

✅ 上周三下午，在星巴克和3个做技术的朋友聊天，大家都在吐槽AI工具太难用了。作为AI Native Coder，我当时就想，这事儿得好好研究一下。
```

### 2. 心路历程式叙事

**特征**：展示决策过程，让读者看到你的思考路径。

**示例**：
```markdown
❌ 我最终选择了NanoBot，因为它更轻量。

✅ 说实话，一开始我是拒绝NanoBot的。4000行代码？开什么玩笑，能有什么功能？但上周有个紧急项目，我抱着试试看的心态用了一下...结果让我有点震惊。现在它已经成了我工作流的一部分。
```

### 3. 自问自答式叙事

**特征**：展示思考过程，模拟真实的内心对话。

**示例**：
```markdown
❌ NanoBot的启动速度很快，不到1秒。

✅ NanoBot的启动速度有多快？不到1秒。为什么这么快？因为它的代码量只有4000行，不像OpenClaw那样有43万行代码要加载。这个差距，让我有点意外。
```

### 4. 数据后加个人判断

**特征**：不要只列数据，要加评论，表达你的感受。

**示例**：
```markdown
❌ NanoBot上线24小时获得了1300+ Star。

✅ NanoBot上线24小时就斩获了1300+ Star。这个数据还挺猛的，要知道很多开源项目一个月都拿不到这个数。看来"极简主义"这个方向，确实戳中了开发者的痛点。
```

### 5. 口语化开场

**特征**：用"说起来"、"其实"、"倒是"开头，营造对话感。

**示例**：
```markdown
❌ AI Agent框架是当前热门的技术方向，本文将分析NanoBot的特点。

✅ 说起来，上周在技术交流群里，大家都在讨论AI Agent框架。有人说OpenClaw太重了，有人说要自己造轮子。我倒是有个不同的看法：与其造轮子，不如找一个能看懂的轮子。
```

## 风格对比示例

### 开头方式对比

**学术风格（避免）**：
```markdown
AI Agent框架的发展经历了多个阶段，从早期的规则引擎到现在的LLM驱动架构。本文将从技术架构、功能特性、应用场景等维度进行分析...
```

**AI朱朱侠风格（推荐）**：
```markdown
说起来，上周三在星巴克和几个朋友聊天，大家都在讨论AI Agent框架。作为AI Native Coder，我对这个话题还挺有感触的。折腾了大半年，踩了不少坑，今天想和大家聊聊我的发现。
```

### 表达观点对比

**直接陈述（避免）**：
```markdown
NanoBot比OpenClaw更适合个人开发者，因为它的代码量更少，更容易理解。
```

**AI朱朱侠风格（推荐）**：
```markdown
NanoBot和OpenClaw哪个更适合个人开发者？我觉得是NanoBot。为什么？因为4000行代码和43万行代码的差距，不是一个数量级。你花一个下午能看完NanoBot的核心代码，但OpenClaw？估计得看一个月。这个时间成本，个人开发者真的耗得起吗？
```

### 提到竞品对比

**泛泛而谈（避免）**：
```markdown
市面上有一些类似的AI Agent框架，各有特点。
```

**AI朱朱侠风格（推荐）**：
```markdown
我对比了OpenClaw、AutoGPT、NanoBot这几个框架，各有各的特点。OpenClaw功能最全，但太重了；AutoGPT概念很火，但实际用起来问题不少；NanoBot最轻量，但功能确实有限。怎么选？看你的需求。如果你像我一样，只是想快速搭个个人助手，NanoBot足够了。
```

## 常见问题处理

### Q: 技术细节要写多深？

**原则**：抓住核心，点到为止。不要陷入技术细节的泥潭。

**示例**：
```markdown
❌ NanoBot使用了ReAct模式，具体实现是通过loop.py文件中的AgentLoop类，它继承自BaseLoop类，主要方法包括run()、step()、should_continue()等...

✅ NanoBot的核心是ReAct模式——简单说就是"思考-行动-观察"的循环。这个设计很巧妙，让AI能够像人一样一步步解决问题。具体怎么实现的？你不需要关心，因为它的代码只有4000行，一个下午就能看完。
```

### Q: 如何处理负面评价？

**原则**：真实体验，理性分析，不要硬黑。

**示例**：
```markdown
❌ OpenClaw太垃圾了，又重又慢，根本没法用。

✅ 说实话，OpenClaw确实有点重。43万行代码，启动要5-30秒，我的MacBook Pro风扇都转起来了。但它的功能确实全面，如果你需要50+平台集成、1000+插件生态，它可能是更好的选择。只是对我来说，这些功能用不上。
```

### Q: 如何加入个人IP？

**原则**：自然融入，不要刻意。在内容中自然带出，不在开头结尾生硬自我介绍。

**示例**：
```markdown
❌ 大家好，我是AI朱朱侠，一个AI Native超级个体。今天我要和大家分享...

✅ 上周我在折腾一个知识库项目的时候，踩过一个坑。当时我以为用OpenClaw能快速搞定，结果配置文件改了半天还是跑不起来。后来我换了个思路，试了试NanoBot...
```

## 写作节奏

### 开头（前100字）

**目标**：3秒抓住读者，设置悬念，给出价值承诺。

**示例**：
```markdown
说起来，上周三在星巴克和几个朋友聊天，大家都在讨论AI Agent框架。作为AI Native Coder，我对这个话题还挺有感触的。折腾了大半年，踩了不少坑，今天想和大家聊聊我的发现——一个只有4000行代码的"平替"方案，竟然让我重新思考了什么是"好用的工具"。
```

### 中段

**目标**：每300字有新洞察，2-3个转折。

**技巧**：
- 用"但是"、"不过"、"话说回来"制造转折
- 用"这让我想起"、"这让我开始反思"建立连接
- 用"为什么这么说呢？"、"具体来说"展开解释

### 结尾

**目标**：升华主题，给出行动引导。

**示例**：
```markdown
写这篇文章的时候，我也在反思自己之前的一些做法。是不是总是追求"功能最全"的工具，反而忽略了"最适合"的工具？如果你也有类似的困惑，不妨试试换个思路：先问自己"我真正需要什么"，再去找那个"刚刚好"的解决方案。
```

## 检查清单

写完文章后，用这个清单自查：

1. [ ] 开头是否口语化？是否设置了悬念？
2. [ ] 是否有具体的时间、地点、人物？
3. [ ] 是否展示了思考过程（犹豫→思考→决定）？
4. [ ] 数据后是否加了个人判断？
5. [ ] 是否有自问自答式叙事？
6. [ ] 是否避免了过度结构化？
7. [ ] 是否避免了直接陈述无过程？
8. [ ] 个人IP是否自然融入？
9. [ ] 结尾是否有升华和行动引导？
10. [ ] 读起来像不像AI朱朱侠在说话？

## 去AI味指南

### 为什么AI写的东西有"塑料味"？

**三大非人类特征**：
1. **陈词滥调的结构**：开头"在快速发展的..."，结尾"总而言之..."
2. **滥用"大词"**：明明是"研究"，非要说"深入探讨"；明明是"使用"，非要说"赋能"
3. **缺乏观点的中立**：总是用"值得注意的是"对冲观点

### 负向词表（禁止使用）

**动词（Verbs）**：
```
深入探讨、深入研究、赋能、助力、优化、提升、深度融合、全面覆盖
```

**名词（Nouns）**：
```
生态系统、核心竞争力、落地场景、颠覆性创新、多维视角
```

**形容词（Adjectives）**：
```
全方位的、多维度的、颠覆性的、革命性的、突破性的
```

**连接词（Connectors）**：
```
此外、另外、综上所述、总而言之、值得注意的是、在...背景下
```

### 替换规则

| AI词 | 人类词 |
|------|--------|
| 深入探讨 | 研究、看、聊 |
| 赋能、助力 | 帮助、让 |
| 优化、提升 | 改进、变好 |
| 总而言之 | [直接停止] / 简短有力句子 |
| 此外、另外 | 而且、还有 / [直接开始新句子] |
| 值得注意的是 | 说实话、有意思的是 |
| 在...背景下 | [直接开始] |
| 多维度的 | 多方面的、各种 |
| 生态系统 | 系统、圈子 |
| 颠覆性的 | 大的、重要的 |

### 节奏感注入（Burstiness）

AI生成文本句子长度很平均。人类写作是"长短句交替"。

**好例子**：
```
项目失败了。没钱了。团队熬了三个月，实在撑不下去了。
```

**坏例子（AI味）**：
```
此外，项目失败的主要原因是资金短缺。另外，团队在长时间工作后也出现了疲劳问题。
```

**节奏感要求**：
1. 混合短句（3-10字）和长句（20-40字）
2. 允许使用句子片段制造效果
3. 不要每句都用"此外"、"然而"开头
4. 直接用主语或动词开始句子
5. 段落长度变化（1-3句一段）

### 观点极化

强制选边站，禁止当"理中客"。

**观点极化规则**：
1. 不要平衡论点（"有利有弊"、"因人而异"）
2. 选择一边，坚定地辩护
3. 禁止使用：
   - "有利有弊"
   - "这取决于..."
   - "另一方面..."
   - "有人可能会说..."
4. 使用强动词：
   - "这证明了..."（不是"这可能表明..."）
   - "这就是..."（不是"这可能是..."）
5. 使用第一人称（"我"、"我的"）增加主观性

**示例**：
```markdown
❌ AI味：AI对社会既有好处也有挑战。
✅ 人味：AI会重塑社会，不管你喜不喜欢。好处太大了，根本没法忽视。
```

### 口语化叙事（Bar Talk Test）

这句话你在酒吧跟朋友喝酒时会说吗？

**口语化要求**：
1. 使用简单、口语化的表达
2. 语法可以稍微松散
3. 自然使用语气词（"嗯"、"说实话"、"怎么说呢"）
4. 用日常生活的比喻
5. 如果概念太无聊，跳过它
6. 不要用企业黑话
7. 直接称呼（"你"、"你的"）
8. 偶尔打断自己（然后自我纠正）

**示例**：
```markdown
所以基本上，LLM这东西...它不是真的在思考，对吧？它只是在预测下一个词是什么。就像我说"花生酱"，你就知道"果冻"要来了。就这样。这就是全部把戏。
```

### 添加人味元素

```
加入元素清单：
□ 短句（3-10字）
□ 句子片段
□ 口语化表达
□ 个人经历/观点
□ 不完美的语法
□ 情感词汇
□ 具体例子（不是抽象概念）
□ 自嘲或幽默
```

### 去AI味检查清单

```
□ 是否有"在快速发展的背景下"类开头？
□ 是否有"深入探讨"、"赋能"、"优化"？
□ 是否有"此外"、"另外"、"综上所述"？
□ 句子长度是否太均匀？
□ 是否缺乏个人观点？
□ 是否过于正式/学术？
□ 读起来像AI朱朱侠在说话吗？
```

### 实战示例对比

**原文（AI味重）**：
```
在人工智能快速发展的背景下，企业需要深入探讨如何赋能业务流程，优化运营效率。此外，值得注意的是，多维度的数据分析能够帮助企业更好地理解用户需求。综上所述，AI技术将成为企业核心竞争力的重要组成部分。
```

**改写后（人味）**：
```
AI这东西，现在火得一塌糊涂。企业都在想怎么用。

说实话，很多公司搞AI就是为了赶时髦。真正用好的没几个。我见过太多项目，花了几百万，最后就做了个"智能客服"——其实就是个关键词匹配。

但数据是真的有用。不是那种"多维度分析"的虚话，就是简单地看用户在干什么、卡在哪里。这些信息，比什么AI模型都管用。

AI会不会成为核心竞争力？我觉得会。但不是因为你买了什么系统，而是因为你真的在用它解决问题。
```
