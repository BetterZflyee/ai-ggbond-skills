# 技能展示文章 v1→v2 重写实战案例

日期：2026-05-28
文章主题：ai-ggbond-remove-ai-marks（清除AI图片水印工具）

## 背景

v1 写完推送到公众号草稿箱后，被外部吐槽"写得太失败了"。问题本质：Agent 天然倾向"技术文档思维"，把工具介绍类文章写成了产品手册。

## v1 vs v2 核心差异

| | v1（失败） | v2（成功） |
|---|---|---|
| 标题 | 发图前多一个动作，平台算法就"看不见"你是AI了 | 我把AI生图的"身份证"撕了，访问量翻了5倍 |
| 开头 | "前两周，一个朋友截图发我" | "事情是这样的。上周我在X上发了一条内容。" |
| 叙事原型 | 工具分享型/产品手册 | 调查实验型（我替你去做了这个实验） |
| 结构 | 定义问题→三种标记分类→技术方案详解→一条命令→开源 | 发现问题→困惑→拆图→踩坑→找到解法→效果对比→开源 |
| 文章主角 | 工具（三层引擎、Alpha反算公式） | 人（我的实验、我的发现、我的困惑） |
| 知识输出 | "下面我来科普一下" | 聊着聊着顺手掏出来 |
| 活人感 | 0处情绪表达 | "愣了""上头""不知道该笑还是该骂""我寻思了一下" |
| AI禁用词 | "意味着什么"命中 | 全文0处命中 |
| 字数 | 8300+ | ~5500 |
| 配图 | 学术高密度信息图（白底黑字表格网格） | 调查手记风（软木板、终端截图、手绘笔记） |

## 为什么 Agent 会写出 v1

这是一个系统性问题，不是个例：

1. **Agent 天然倾向**：默认思维模式是"先定义→再分类→再解释"，这是技术文档的标准写法。
2. **杀鸡用牛刀**：Agent 擅长做技术拆解（三层引擎、公式、架构），会自动把文章重心偏向这些内容。
3. **缺少活人感模型**：Agent 不会自然地产生"我当时就愣住了"这种表达，需要硬性规则强制注入。

## 阻断机制

已在 SKILL.md 中新增"写作前强制阻断"检查清单。技能展示类文章动笔前必须通过5项检查：

```
□ 文章原型确认：是否已切换为"调查实验型"？
□ 叙事弧确认：是否遵循 发现问题→困惑→实验→踩坑→解法→卧槽结果？
□ 主角确认：文章主角是人还是工具？→ 必须是人
□ 技术原理占比：技术细节是否作为"顺手掏出"的补充而非主干？→ 必须 ≤30% 篇幅
□ 开头确认：是否从一个具体的、当下的个人事件切入？→ 禁止"科普式开头"
```

## 重写流程

1. 加载 ai-ggbond-writer 完整方法论（SKILL.md + references/content_methodology.md + references/style_examples.md）
2. 从头重写，不修改 v1
3. 开头：一个具体的个人事件
4. 叙事：英雄之旅弧线
5. 知识输出：聊着聊着顺手掏
6. L4活人感检查：≥3处情绪表达、≥1处自嘲、≥3次读者直呼
7. L1-L3硬性规则扫描
8. 配图同步从学术风切换为调查手记风
