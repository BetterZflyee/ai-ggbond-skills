# 技能展示类文章的两种模式（2026-05-29 飞哥纠偏）

## 背景

飞哥要求写一篇介绍 ai-ggbond-remove-ai-marks 技能的公众号文章。我默认用了"调查实验型"叙事（v2 成功案例），飞哥纠正说不对——他要的是歸藏 PPT Skill 和花叔达尔文.skill 那种"故事引入 + 轻量科普"的结构。

## 两种模式对比

| | 模式A：调查实验型 | 模式B：轻量分享型 |
|---|---|---|
| **触发信号** | 飞哥说"实验""调查""拆解""我替你做了" | 飞哥说"介绍一下""科普一下""分享一下""开源" |
| **叙事弧** | 发现问题→困惑→实验→踩坑→解法→卧槽结果 | 故事引入→产物体验→能做什么→怎么用→开源 |
| **主角** | 人（的实验和发现） | 人（做了个东西给你看） |
| **技术细节占比** | ≤30%，顺手掏出 | ≤20%，点到为止 |
| **参考文章** | remove-ai-marks v1→v2 重写案例 | 歸藏 PPT Skill、花叔达尔文.skill |
| **调性** | 侦探/探险 | 朋友分享好东西 |

## 模式B 的具体结构（歸藏模式）

1. **开头故事**（~400字）：一个具体场景引入，自然引出"我做了个东西，开源了"
2. **它长什么样**（~500字）：直观感受，before/after
3. **它能做什么**（~1200字）：核心能力，白话讲
4. **怎么用**（~1500字）：常见场景，**用自然语言指令**，不展示命令行
5. **用着怎么样**（~1000字）：真实体验、踩坑
6. **写在最后**（~400字）：开源链接、金句收尾

## 模式B 的铁律

### 铁律一：站在普通人的分享欲上，不是科普专家
- ❌ "下面我来讲解这个工具的三层引擎架构"
- ✅ "先给你看效果""它能做什么""怎么用"
- 飞哥原话："我觉得你要站在普通人的分享欲上面，而不是一个科普专家，不用讲为什么做"

### 铁律二：面向普通用户的文章禁止展示命令行代码
- ❌ `python3 scripts/clean.py input.png -o clean.png`
- ✅ 「帮我清除这张图的AI水印：images/cover.png」
- 飞哥原话："用户看到这些就会退场的，应该告诉用户一些中文指令"
- 这是 Skill 产品的核心卖点：用户只需要说中文，不需要敲命令

### 铁律三：开源文章不暴露底层依赖来源
- ❌ "最后找到了 wiltodelta/remove-ai-watermarks 这个开源库"
- ✅ "折腾了一圈，我决定自己写一个专门干这件事的 Skill"
- 飞哥原话："这不是拆我台吗，暴露了技能不是我原创的"
- 技术原理可以讲（像素反算、扩散重生成），但不提具体库名

### 铁律四：结尾必须服务于推广目标
- 不是泛泛的科普总结，要讲清楚痛点 + 工具能解决
- 飞哥的痛点框架："平台把溯源信息变成了降权信号，塞进推荐算法里，从来没告诉过创作者"
- 创作者两难："用AI提效就被降权，不用AI跟不上节奏"

## 模式选择决策树

```
飞哥说"写一篇关于XX技能的文章"
  → 问：飞哥的意图是什么？
    → 如果是"我做了个实验/调查，给你看结果" → 模式A（调查实验型）
    → 如果是"我做了个东西，开源了/分享一下" → 模式B（轻量分享型）
    → 如果不确定 → 问飞哥
```
