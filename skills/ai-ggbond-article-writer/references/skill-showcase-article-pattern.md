# Skill Showcase Article Pattern / 技能展示文章写作模式

> 当文章主题是介绍你自己开发的某个 Skill/工具/项目时使用此模式。

## 与标准写作流程的区别

标准流程（步骤3-5）要求先判断内容类型再提供3-5个选题。技能展示文章的内容类型固定为**效率提升实战**，选题角度固定为**从痛点切入讲实战故事**，可以跳过内容类型判断，直接提供选题。

## 选题公式

技能展示文章的选题应遵循「痛点共鸣 + 解决方案暗示」结构：

```
《[痛点场景描述]？我做了一个[解决方案一句话]》
```

示例：
- 《关注了200个AI大佬，每天刷X刷到焦虑？我做了一个自动日报系统》
- 《每次写周报都要2小时？我做了一个自动生成工作流》
- 《面试前总不知道练什么？我做了一个模拟面试系统》

## 文章结构模板

技能展示文章推荐使用以下7段结构：

### 1. 痛点共鸣（300-400字）
- 用具体数字开场（关注了多少人、每天多少条信息、花了多少时间）
- 描述焦虑/低效的真实感受
- 核心：让读者觉得"这说的就是我"

### 2. 为什么现有方案不行（400-500字）
- 列举2-3个你试过但失败的方案
- 每个方案说清楚"为什么不行"（具体缺陷，不是笼统的"不好用"）
- 核心：为你的方案建立"存在的必要性"

### 3. 我的方案概览（500-600字）
- 用分层/分模块的方式讲清楚架构
- 每一层讲清楚"它解决什么问题"
- 适当暴露技术细节，但不要堆代码
- 核心：让读者理解方案的逻辑，不是要教会他实现

### 4. 实际效果展示（300-400字）
- 用真实数据说话（抓了多少条、分了几个类、省了多少时间）
- 列举2-3个具体的内容示例
- 核心：让读者看到"这东西真的能用"

### 5. 深层认知升华（300-400字）
- 从工具层面拔高到认知/方法论层面
- 提炼出1-2个"金句"级别的观点
- 核心：让文章有转发价值，不只是"又一个工具介绍"

### 6. 技术踩坑记录（300-400字）
- 列举3-5个你实际踩过的坑
- 每个坑说清楚"是什么"+"怎么解决"
- 核心：帮读者少走弯路，同时展示你的专业度

### 7. 开源引导+CTA（200-300字）
- 先给价值（"你只需要做三件事"），再给链接
- 说清楚仓库地址、技能目录、快速上手步骤
- 最后一句可以用"如果觉得有用，欢迎Star ⭐"
- 核心：降低行动门槛，让人真的去试


## 写作注意事项

1. **第一人称贯穿全文**：这是"我的实战故事"，不是产品文档
2. **失败案例必须真实**：不要编造"试过X但不行"，用你真正踩过的坑
3. **技术深度适中**：让小白看懂逻辑，让同行看到细节
4. **金句密度**：每800-1000字至少一个可以被划线转发的观点
5. **GitHub链接出现两次**：正文中自然提及一次，结尾CTA再正式列出
6. **不要过度推销**：80%讲价值和故事，20%引导行动
