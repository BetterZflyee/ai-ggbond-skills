# GitHub Trending / AI Agent 热榜文章修订要点（2026-05-25）

## 触发场景

用户要求基于 GitHub Trending / 热榜项目写公众号趋势文，尤其是 AI Agent、开源项目盘点、P0 项目串联型文章。

## 本次用户明确纠偏

1. **周一发布口径要改成“上周”**
   - 如果今天是周一，榜单内容应表述为“上周的 GitHub Trending”。
   - 标题、开头、结尾都要统一时间口径。
   - 写完后必须检查：如果用户要求“上周”，全文 `这周` 计数应为 0。

2. **先科普 GitHub Trending，再进入榜单内容**
   - 面向公众号普通读者时，不要默认所有人知道 GitHub Trending。
   - 开头应先用 2-4 段解释：GitHub 是开源平台，Trending 类似开源热榜，价值不是“最终赢家名单”，而是提前暴露开发者集体关注的问题。
   - 然后再转入“上周榜单里我看到的信号”。

3. **每个项目章节末尾附项目链接**
   - 热榜文章涉及不同 GitHub 来源时，每个章节末尾添加 `项目链接：`。
   - 链接用纯文本 URL，不用 Markdown 超链接。
   - 如果一节包含多个项目（如 codegraph + Understand-Anything），链接都列出。

4. **后半段要更有感召力，少啰嗦**
   - 后半段不要反复解释“系统重要”。
   - 改成号召型落点：例如“别再围观了，把 AI 接进你的系统”。
   - 给读者一个可立即自查/行动的清单：上下文、记忆、流程、工具链、生态。
   - 结尾可以用短句增强节奏：
     - `Agent 已经开始补课了。`
     - `现在，轮到我们了。`

## 推荐结构

1. GitHub Trending 是什么：先科普热榜机制与观察价值。
2. 上周热榜信号：AI Agent 正在集体补课。
3. 分章节讲项目，每章末尾附链接。
4. 汇总：这不是工具热闹，是 Agent 的成人礼。
5. 普通人行动：轮到我们补课。
6. 感召型结尾：别再围观，把 AI 接进工作系统。

## 自检脚本思路

写完后检查：

```python
from pathlib import Path
s = Path(article).read_text(encoding='utf-8')
assert s.count('这周') == 0  # 当用户要求上周口径时
for url in required_urls:
    assert url in s
for bad in ['建议阅读','点击右上角','全文核心信息图','配图：','图片说明','figcaption']:
    assert bad not in s
```

## 配图确认衔接

当用户说“可以了，和我确认一下风格和配图”时，不要直接生图。必须先确认：

1. 风格方案（推荐 3-4 个，明确推荐项）
2. 图片数量与用途清单
3. 封面准确标题文字
4. 模型：默认严格 `gpt-image-2`，不可擅自换模型

推荐这类文章优先方案：暖米白手绘信息图风，用“课程表 / 补课 / 黑板 / Agent 学习系统”作为视觉隐喻，兼顾技术感与公众号亲和力。
