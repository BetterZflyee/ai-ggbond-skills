# 技能展示类文章写作规则补充（2026-05-29）

来源：ai-ggbond-remove-ai-marks 公众号文章 + 微信贴图制作实战

## 飞哥纠正的 6 条铁律

### 1. 普通人分享欲，不是科普专家
- 错误角度：「我来给你讲解这个工具的技术原理」
- 正确角度：「我发现了一个好东西，忍不住分享给你」
- 不要讲"为什么做成这样"的设计决策分析，不要出现"设计决策背后的思考"章节
- 参考范式：歸藏的 PPT Skill 文章结构——故事引入→产物体验→能做什么→怎么用→开源

### 2. 禁止暴露底层依赖/第三方库
- 文章中绝对不能提及底层依赖的第三方开源库名称（如 wiltodelta/remove-ai-watermarks 等）
- 所有能力必须说"我写了一个 Skill"，不要说"我基于XX库封装了一层"
- 飞哥原话：「你这不是拆我台吗，暴露了技能不是我原创的」
- 暴露底层来源 = 拆自己的台

### 3. 禁止展示命令行/代码
- 面向普通用户的文章中不要出现 `python3 scripts/xxx.py --flag` 这类命令行
- 用户看到代码就会退场
- 用自然语言描述操作：「你只需要跟 AI 说一句『帮我清除这张图的AI水印』，它就自动帮你搞定」
- Skill 的核心价值就是"说句话就行"，不要把底层实现暴露给读者
- 飞哥原话：「用户看到这些就会退场的，应该告诉用户一些中文指令，比如给我删除xx文件夹里里面的ai水印」

### 4. 先讲痛点，再引技能
- 文章和贴图都不能上来就介绍技能
- 必须先讲用户的真实痛点（如"你的图在偷偷告密"），让读者产生共鸣
- 最后才说"后来有人做了个工具"
- "我"要弱化成"有人"，降低推销感
- 飞哥原话：「内容太ai味道了，你上来就介绍我的技能啊」

### 5. 结尾从痛点切入做推广
- 结尾不是"总结工具功能"，而是回到用户的真实痛点
- 讲清楚"平台/行业在你不知道的情况下做了什么"
- 然后自然引出"这个工具把选择权还给你"
- 参考结构：平台偷偷降权→创作者两难→这个 Skill 让你决定
- 飞哥原话：「这结尾讲的什么狗屁啊，我最终的目的是推广我的技能，痛点在于：平台把溯源信息变成了降权信号」

### 6. 贴图配图默认科技风
- 贴图配图的默认风格不是复古波普网格，是科技风
- 科技风特征：深色背景(深蓝#0A1628) + 霓虹蓝(#00D4FF) + 霓虹紫(#A855F7)
- 飞哥原话：「风格是科技风啊」

## 更新后的写作前阻断检查清单（v2）

```
□ 文章原型确认：是否已切换为"调查实验型"或"歸藏模式"（故事引入→产物体验→能做什么→怎么用→开源）？
□ 叙事弧确认：是否遵循英雄之旅弧线？
□ 主角确认：文章主角是人还是工具？→ 必须是人
□ 技术原理占比：技术细节是否作为"顺手掏出"的补充而非主干？→ 必须 ≤30% 篇幅
□ 开头确认：是否从一个具体的、当下的个人事件切入？→ 禁止"科普式开头"
□ 底层依赖检查：是否暴露了第三方库名称？→ 必须全部删除
□ 代码检查：是否出现了命令行/代码块？→ 面向普通用户的文章禁止代码
□ 角度检查：是"分享欲"还是"科普专家"？→ 必须是分享欲
□ 结尾检查：是否从痛点切入？→ 先讲平台/行业的隐秘行为，再引工具
□ 技能引入顺序：是否先讲痛点再引技能？→ 不能上来就介绍
```
