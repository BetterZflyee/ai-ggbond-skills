# 病毒式“会议实录/逐字稿”核验与写作工作流

## 触发场景

用户要求围绕突然刷屏的“会议实录、逐字稿、内部讲话、录音整理、投资人会议纪要”写文章，尤其当传播时间与会议发生时间可能不一致时。

## 核心原则

**先确认材料是什么，再分析它说了什么。**

传播标题里的“实录”“逐字稿”不等于来源真的是逐字转写。必须区分：

1. 官方录音/视频；
2. 官方逐字稿；
3. 经参会者确认的会议纪要；
4. 媒体依据有限素材整理的语录；
5. 二次转载或拼接摘要。

文章中的确定性不得高于信源等级。

主张—证据矩阵、版本数字冲突、播客再制作与匿名网盘鉴别示例见 `references/viral-transcript-evidence-matrix-case.md`。

## 标准流程

### 1. 校正两条时间线

分别记录：

- **事件发生时间**：会议真正举行的日期；
- **材料传播时间**：整理稿或爆款文章发布的日期。

禁止把“昨晚刷屏”写成“昨晚开会”。开头若借热点切入，应明确写清“昨晚刷屏的是整理稿，会议发生在更早时间”。

### 2. 追溯最原始公开来源

优先寻找：

- 发布者原页面及页面元数据；
- 原始录音、视频、附件或网盘文件；
- 发布者关于素材来源和编辑方式的声明；
- 早期报道中对会议时间、形式、参会者的说明；
- 当事人过去公开采访，用于核验观点是否长期一致。

搜索时同时使用：标题、核心引语、会议平台、月份、录音/录屏/附件/网盘等组合词。不要把多个转载站视为多个独立信源。

### 3. 建立信源标签与独立侧证矩阵

在本地知识库顶部固定写明：

- 会议时间与形式；
- 文本公开时间，包含页面显示时间、机器可读时间和时区换算；
- 发布者与URL；
- 信源等级；
- 发布者原始免责声明；
- 是否发现可验证的录音/视频；
- 哪些独立媒体只确认“会议存在/时长/对象/部分主题”，哪些来源负责提供具体措辞；
- 推荐引用口径。

建立一张“主张—证据”矩阵，禁止用一条侧证替整份稿件背书：

| 主张 | 可接受证据 | 能否升级全文可信度 |
|---|---|---|
| 会议确实存在 | 参会者、主流媒体、主办方 | 只能确认会议存在 |
| 约四小时、线上举行 | 两个独立来源或参会者信源 | 只能确认场景和时长 |
| 某个核心主题出现 | 更早报道、参会者复述 | 只能确认该主题 |
| 52条逐字准确 | 原始录音、官方稿、可核验转写 | 没有则不能确认 |

推荐表述：

- “据媒体整理稿显示……”
- “目前公开网络能核验的最完整版本为……”
- “原发布方注明，部分措辞可能与现场原话略有出入。”
- “独立媒体可以支持会议存在及部分主题，但不能逐句验证整理稿。”

禁止表述：

- “官方逐字稿显示……”（来源非官方时）
- “梁文锋52条原话……”（只是媒体整理时；标题也应用“52条会议发言/发言摘编”）
- “昨晚梁文锋召开会议……”（只是昨晚发布材料时）
- “多家媒体都报道了，所以52条属实”（转载数量不等于独立信源数量）

### 4. 保存证据，而不只保存摘要

至少落地三份材料：

1. 原始网页HTML或可下载原件；
2. 清洗后的完整公开文本；
3. 重要信息与信源限制说明。

对原始文件计算SHA-256，记录抓取日期。长文本有编号时，机械检查编号连续、无缺失、无重复。

### 5. 提炼时先串因果链

不要写成“金句盘点”或52条平行摘要。先找出：

**终极目标 → 因此放弃什么 → 用什么机制换取什么 → 最终保护哪项核心资产 → 对行业/企业意味着什么。**

每个案例或引语只服务论证链中的一环。信息重要性优先级：

1. 新路线图或明确优先级；
2. 与过往观点相比的新增信号；
3. 组织、商业、技术之间的因果关系；
4. 可被证伪的路线判断与矛盾点；
5. 适合传播但信息增量较低的金句。

### 6. 主动比对版本冲突

对同一场会议的早期报道、后续整理稿和转载版本做字段级对比，至少检查：

- 数字（比例、金额、人数、日期）；
- 会议平台、时长和对象；
- 引语中的绝对词与限定词；
- 条目是否经过主题重排、拆分或合并；
- 作者署名和素材来源说明是否变化。

发现冲突时，不要替来源“校正”成一个数字。建立冲突表并写明：

```text
版本A怎么写｜版本B怎么写｜能否由原始证据裁决｜正文采用方式
```

没有录音或官方稿时，正文应删除冲突数字，或并列说明“公开版本存在差异”。长期表达一致只能证明观点方向稳定，不能证明某句话逐字准确。

### 7. 必须保留冷思考

至少列出：

- 哪些是事实；
- 哪些是发布方转述；
- 哪些是作者推论；
- 哪些路线判断尚无行业共识；
- 哪些约束条件普通企业无法复制。

热点人物不能被供奉成管理圣经。文章应同时说明“值得学什么”和“不能照抄什么”。

## 交付物建议

```text
文章目录/
├── _raw/原始网页-抓取日期.html
├── _knowledge_base/会议-最完整公开文本-日期.md
├── _knowledge_base/会议-重要信息提炼-日期.md
└── 日期-主题-文章梳理版.md
```

## 发布前验证

- [ ] 事件时间与传播时间已分开；
- [ ] 没有把整理稿称为官方逐字稿；
- [ ] 发布者免责声明被保留；
- [ ] 编号材料完整、无缺失和重复；
- [ ] 原页面或原件已本地保全；
- [ ] 文章引用强度不超过信源等级；
- [ ] 标题未把“发言摘编”写成“原话/逐字稿”；
- [ ] 已区分独立媒体侧证与二次转载，未用转载数量替代证据质量；
- [ ] 同一信息的数字、日期、平台、措辞冲突已建立对照，未擅自统一；
- [ ] 页面机器时间已换算为用户时区，未混淆显示日期与精确发布时间；
- [ ] 文章不是平行金句堆叠，而是一条递进论证链；
- [ ] 有冷思考和可证伪问题；
- [ ] 去AI味词汇检查通过。

## 本次形成的关键经验

“会议实录”常是传播标签，不是文献类型。最危险的错误不是漏掉一条观点，而是把二手整理稿升级成一手逐字证据。事实校正应成为文章价值的一部分，而不是藏在文末免责声明里。
