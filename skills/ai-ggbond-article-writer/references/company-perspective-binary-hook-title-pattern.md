# 企业视角文章的二极管钩子标题模式

## 适用场景

用户从大企业、一线行业或复杂系统中形成个人判断，希望标题同时具备企业视角的可信度、行业问题和小红书式二极管钩子，又不暴露具体职位。

## 本次纠偏

### 被否决的标题

`我在顺丰总部做 AI 后，越来越确定：企业不缺 Agent，缺的是一套敢让它干活的能力体系`

问题：

1. 把职业经历和文章结论全部塞进标题，像履历加摘要。
2. 结论交代过满，读者不需要点开。
3. 缺少二极管冲突，没有强烈的两端对照。
4. “我在某公司做什么”抢走主题，个人 IP 变成身份展示。

### 用户确认的标题

`从顺丰看 Agent：行业都在拼智商，企业真正缺的是手脚`

成功原因：

- `从顺丰看`：公司是观察复杂系统的视角，不是职位介绍。
- `行业都在拼智商`：指出行业显性共识和集体动作。
- `企业真正缺的是手脚`：用反方向结论制造二极管冲突。
- `智商 / 手脚`：把模型与能力体系变成普通读者秒懂的视觉隐喻。
- 没把权限、审计、能力目录等答案全部说完，保留点击悬念。

## 核心公式

```text
从[高信用企业/复杂行业]看[热门对象]：
行业都在[显性共识/狂热动作]，企业真正缺的是[反方向隐喻]
```

可替换结构：

```text
从[企业]看[对象]：[大家都在做A]，[真正问题却在B]
从[行业]看[对象]：[表面能力越来越强]，[生产环境反而不敢用]
[企业]视角下的[对象]：[会做正常流程]，[异常才暴露真实水平]
```

## 二极管标题的正确理解

二极管不是无依据地夸张，而是把同一问题的两端拉开：

- 智商 vs 手脚
- Demo 很多 vs 敢上线很少
- 会走流程 vs 异常就失效
- Agent 越多 vs 可复用能力越少
- 模型越来越聪明 vs 企业仍然不敢放权

标题只负责制造冲突，正文负责补充条件、边界和证据。

## 公司视角的使用边界

### 应该做

- 把公司当作观察复杂业务和真实生产问题的镜头。
- 使用“从顺丰看”“在大型物流网络里我观察到”等个人观察表达。
- 正文可写“在顺丰总部做 AI”，但只用于交代观察来源。
- 将公司经验抽象为其他复杂企业也适用的行业规律。

### 不应该做

- 标题写具体职位、FDE、职级或职业履历。
- 把“我在公司做什么”与全部文章内容同时塞进标题。
- 暗示文章代表公司官方观点、披露内部规划或具体项目。
- 反复用公司名称做案例堆叠；公司应是视角，不是宣传主角。

## 标题与正文的分工

- 标题：公司视角 + 单一行业矛盾 + 隐喻或反差。
- 摘要：解释矛盾，但不要展开完整方案。
- 开头：交代一线观察来源，迅速进入冲突。
- 正文：用个人经验形成判断，再用权威资料验证判断。
- 结尾：沉淀可复述的方法论或个人主张。

## 标题生成自检

- [ ] 是否出现了具体职位或履历？出现就删。
- [ ] 是否同时塞入身份、背景、结论、方案？是则减到一个冲突。
- [ ] 去掉公司名后，标题是否仍有行业问题？
- [ ] 公司名是在提供观察视角，还是在抢主题？
- [ ] 是否存在清晰的两端冲突？
- [ ] 是否留下一部分答案，迫使读者点开？
- [ ] 隐喻是否能被普通读者秒懂？
- [ ] 冲突是否能被正文充分证明，而非纯标题党？
