# 多案例文章的递进论证结构

## 问题：平行案例陷阱

当文章引用多个真实案例（多个公司、多条推文、多个数据源）时，最常见的错误是"平行案例堆叠"——每个案例独立一节，像新闻摘要。

错误结构示例：
```
§ ClickUp 案例
§ Stack Overflow 案例  
§ 合规案例
§ SpaceX 案例
```

读者读起来像在看"今日AI快讯"，而非一篇有论点的文章。

## 解法：一条主线贯穿所有案例

每个案例必须服务递进论点链中的**一环**，而非独立存在。

飞哥确认的偏好结构（2026-05-27）：
```
1. 开场钩子：两件怪事 → 一个共同指向
2. 范式框架：三个时代 → 宝玉点睛
3. 解剖机制：ClickUp 深挖 → 替代的不是人，是"信息节点"
4. 资产重定义：SO + 合规 + SpaceX → 什么值钱变了
5. 新权力法则：1000 并发 + AI Native vs AI User + Agent 递归
6. 冷静边界：四个边界 + TrapDoor
7. 你的行动：三件事
8. 升华：判断力是唯一护城河
```

## 关键规则

1. **每个案例只论证一个点**。ClickUp 只论证"信息节点替代"，不掺杂其他论点。
2. **串起来的不是"信息"，是"判断"**。不是"X 说了 A、Y 说了 B"，而是你自己的判断把它们串成逻辑链。
3. **案例之间必须有递进关系**。前一个案例的结论是后一个案例的起点。
4. **冷思考必须在行动之前（铁律）**。先踩刹车去幻想（"Agent不是什么"），再给清醒行动建议（"你现在就该开始的三件事"）。读者不会带着焦虑离开——他们先清醒认识边界，再决定怎么动。
5. **结尾不总结，要升华**。用金句收束，不是"综上所述"。

## 飞哥纠偏实例

### 2026-05-27《Agent-First》第一版
**问题**：ClickUp、SO、合规、SpaceX 各自独立一节，像新闻摘要。读起来"比较松散，没有主线"。

**修正**：重构为一条主线——
- ClickUp → 机制（替代信息节点）
- SO + 合规 + SpaceX → 资产重定义（数据/信任/基础设施）
- Peter + ECC → 权力转移（一个人 = 军队）

### 2026-05-27《Agent-First》第二版
**问题**：行动建议在冷思考之前。飞哥纠正："至少需要将'行动'和'冷思考'换一个位置"。

**修正**：冷思考（Agent 不是什么）→ 行动（三件事）→ 升华（判断力是护城河）。过渡句："我先把边界讲清楚，不是为了吓你。恰恰相反——正因为知道边界在哪，行动起来才不盲目。"

## 结构自检清单

写完后必须逐项确认：
- [ ] 每个案例是否只服务一个论点？
- [ ] 案例之间是否有递进关系（前一个结论 → 后一个起点）？
- [ ] 是否先冷思考再给行动建议？
- [ ] 结尾是否用金句升华而非总结？
- [ ] 全文是否有一条可以把每节标题串起来的口述主线？
