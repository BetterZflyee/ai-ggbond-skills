# 混合转写的主题边界与文档范围控制

## 适用场景

用户提供长篇录音转写，并要求整理成文章、讲稿、方法论文档或内部分享材料。转写中可能因录音未停止、场景切换或多人插话，混入多个无关议题。

## 核心教训

**共处于同一份转写，不等于属于同一个主题。**

不能因为一段内容先讲理论、后一段出现项目讨论，就自动将其解释为“思想框架＋实战案例”。案例是否属于主题，必须由目标、对象、方法链和用户意图共同证明。

## 写作前的范围门禁

先写一份简短范围声明：

```text
主标题：
核心命题：
第一部分回答：
第二部分回答：
保留素材：
排除素材：
贯穿案例：
```

检查每一段素材：

1. 是否回答主标题提出的问题？
2. 是否与核心命题存在直接因果或方法关系？
3. 删除后是否影响主线成立？
4. 它是案例证据，还是仅仅在时间轴上相邻？
5. 用户是否明确把它归入当前主题？

若第1、2、5项无法确认，默认独立处理，不纳入主文档。

## 主题切分信号

- 参与者和说话人群体突变
- 业务对象或责任主体突变
- 从演讲独白切换为现场项目会议
- 从个人能力讨论切换到安全、监管、成本等另一套决策链
- 目标由“分享方法”变为“推动具体项目”
- 出现导航播报、电话、路人交谈等环境噪声

## 用户纠正后的清理协议

用户指出某个主题无关时，不能只删除独立章节。必须全文搜索并清理：

- 标题和副标题
- 摘要
- 目录
- 开篇钩子
- 章节案例
- 表格与清单
- 风险边界
- 行动建议
- 结尾回扣
- 关键词、同义词和隐性影射
- 生成脚本中的硬编码内容与验证标题

清理后重新检查：

- 章节编号是否连续
- 过渡句是否成立
- 是否留下“详见某案例”等悬空引用
- 主线是否仍完整
- 替代案例是否来自主题内真实素材，且没有虚构数据

## 更合适的替代方式

如果文章需要一个实战案例，应优先选择与主命题同构的案例。例如“沟通即交付”适合使用：

```text
会议/Excel/零散材料
→ 逐字稿和事实底稿
→ 结构化研究材料
→ 决策与Action
→ HTML或领导汇报
→ 工程文件库
→ Memory/Skill/案例资产
```

它直接证明沟通如何转化为交付，不需要借用另一个高风险业务项目。

## 一句话自检

> 我是在使用一个真正支持论点的案例，还是在替同一份录音里的相邻内容强行建立关系？
