# Benchmark × Harness × 成本反差型文章写法

适用于把「能力跑分上升」与「调用成本上升」两类事件写成一篇行业观察，而不是两条新闻摘要。

## 核心论证链

```text
两件表面矛盾的事件
→ 纠正榜单认知：Agent 分数不是裸模型分数
→ 揭示隐藏变量：模型 × Harness × 工具 × 上下文 × 验证器
→ 引入成本现实：Token 单价只是原料价
→ 重定义经济指标：单个成功任务总成本
→ 推导产业权力：厂商从卖模型扩张到控制任务入口与执行轨迹
→ 迁移到普通人/垂直行业：建立自己的真实任务集与验收器
→ 冷静边界
→ 行动建议
→ 金句升华
```

## 写作规则

1. **反差必须在机制层合流**：不要分别讲完跑分、Harness、涨价；用「能力可测量后，成本才成为硬约束」把三者串起来。
2. **榜单归因要准确**：明确 Agent 成绩属于系统组合，不把分数全部归因给裸模型。
3. **成本不要只抄报价表**：至少讨论缓存命中/未命中、输出、工具费、运行时间、人工接管和严重错误。
4. **统一核心指标**：文章最终落到「成功交付一个可验收任务的总成本」，而非每百万 Token 单价。
5. **第三方横评须加边界**：说明测试任务、版本和配置不同，数据只证明 Harness 会改变成功率/成本，不包装成绝对排行榜。
6. **行业迁移迁的是方法，不是题目**：真实任务、冻结环境、有限工具、隐藏验收、安全红线、结果计分。
7. **普通人行动要极简**：先做 10 个真实任务，记录成功率、总成本、时间、人工接管、严重错误。
8. **先冷思考，再行动**：开发者预览、题库失真、验收漏洞、成本漏算、高分不可迁移等边界讲清后，再给建议。

## 可复用金句框架

- Token 单价是油价，Harness 决定百公里油耗。
- 没有自己的任务集，任何排行榜都只是别人的体检报告。
- 排行榜告诉你谁跑得快，自己的任务集才告诉你谁能把货送到。
- 最稀缺的不只是造模型的人，还有定义「什么叫做对」的人。

使用时应根据主题重写，不要机械复制。

## 事实审校清单

- 官方 Benchmark 分数是否注明具体 Harness、推理强度和采样设置
- 价格是否注明生效日期、峰谷时段和计价单位
- 涨幅是否经工具计算，而非心算
- 第三方横评是否保留测试条件与非绝对排名声明
- 有争议或撤回的结论是否删除，只保留仍成立的计价/方法论问题
