# 微信公众号发布前洁净度预检（飞哥公众号文章）

适用场景：将飞哥公众号长文 HTML/Markdown 推送到微信公众号草稿箱前，尤其是从 `ai-ggbond-article-writer` 生成的 HTML 精排版。

## 背景

2026-05-19《AI工具的下半场》发布后发现：正文出现了排版工具痕迹，包括阅读元信息、图片图注、alt 文本可见化，以及独立金句卡片和引用卡片连续堆叠。问题不在微信 API，而在发布前没有做“正文洁净度”预检。

发布技能不能只检查图片能否上传，也要拦截明显不该进入正文的可见文本。

## P0 禁止项

发布版正文不得出现以下可见内容：

- `建议阅读`
- `点击右上角`
- `全文核心信息图`
- `配图：`
- `图片说明`
- `<figcaption`

说明：
- 阅读时长、字数、听阅提示只能作为内部审校信息，不进入正文。
- 图片 `alt` 可保留用于上传识别/可访问性，但不得渲染成图注。
- 图片是视觉断点，不是二次标题。

## 视觉重组件原则

发布前人工/脚本检查：

- 引用卡片和独立金句卡片不要连续出现。
- 如果引用卡片超过 2 个，独立金句卡片最多 1 个。
- 任意两个视觉重组件之间至少间隔 2 个自然段。
- 重组件包括：图片、引用卡片、独立金句卡片、CTA 卡片。

## 快速预检命令

```bash
python3 - <<'PY'
from pathlib import Path
p = Path('/path/to/publish.html')
s = p.read_text(encoding='utf-8')
bad = ['建议阅读', '点击右上角', '全文核心信息图', '配图：', '图片说明', '<figcaption']
found = [x for x in bad if x in s]
if found:
    print('BAD_VISIBLE_TEXT:', found)
    raise SystemExit(1)
print('clean preflight ok')
PY
```

## 执行规则

如果命中 P0 禁止项，不要继续推送公众号草稿。先回到 article-writer 阶段清理 HTML，再 dry-run，再正式发布。

一句话原则：**发布技能的职责不只是把内容发出去，也要防止明显脏内容被发出去。**
