# 公众号长文转 X Thread 压缩指南

将 5000+ 字公众号深度文章压缩为 6 条以内的 X Thread，保持论证链完整。

---

## 压缩原则

1. **保留主线，删案例细节**：读者不需要知道 ClickUp 内部信的原文，只需要知道"裁的是协调层"
2. **理论只提名字，不展开**：帕累托、贝叶斯、阿什比——三个词就够了，想深入了解的会点原文
3. **金句原位保留**：结尾金句一个字不改，它是 Thread 的锚点
4. **每条一个独立论点**：不能把两个逻辑层次塞进同一条

---

## Thread 结构模板（6 条版）

```
1/N：现象钩子 + 核心判断
    - 用数据或新闻开篇（ClickUp 22%、SO 镜像曲线）
    - 一句话给出判断（范式转移）
    
2/N：机制揭示
    - 引用关键人物/洞见（宝玉的"执行主体转移"）
    - 一句话说清楚核心机制
    
3/N：案例证据
    - 2-3 个案例合并，每个案例一行
    - 不叙事，只给结论
    
4/N：理论纵深 + 恐怖推论
    - 理论骨架一行（帕累托/贝叶斯/阿什比）
    - 最让人发怵的结论
    
5/N：行动 + 边界
    - 三件事（①②③格式压缩）
    - 冷思考一行
    
6/N：金句收尾
    - 不加"你怎么看""欢迎讨论"
    - 让金句自己说话
```

## 写作风格（2026-05-28 飞哥4轮纠偏确认）

### 核心铁律：不劝、不邀、不推销

飞哥4轮迭代后明确：X 推荐文案要让读者**自己决定点进来**，不能有任何引导/邀请/推销感。

| ❌ 禁止 | ✅ 通过 |
|---------|---------|
| "你怎么看？来聊聊" | 只说判断，不加问句 |
| "这篇写得特别好，推荐" | 直接给信息差钩子 |
| "写完更困惑了，想听你说" | "写到一半想删""自己都有点发怵" |
| "你们感觉到了吗" | 不结尾提问，让金句自己结尾 |

### 去 AI 味规则

| ❌ 禁用 | ✅ 替换 |
|---------|---------|
| 此外、另外、值得注意的是 | 直接开始新句 |
| 深入探讨、赋能、优化 | 聊、让、改 |
| 总而言之、综上所述 | 删掉 |
| "你怎么看？欢迎留言" | 不写，让内容自己钩人 |
| 在...背景下 | 直接开始 |

**节奏要求**：
- 长短句交替（3-10 字短句 + 20-40 字长句）
- 不用过渡词开头
- 允许句子片段（"不是降本，是重构。"）
