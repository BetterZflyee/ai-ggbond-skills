# 设计原则：为什么 Memory 驱动 > 硬编码 Persona

本文档记录 `ai-ggbond-run-xiaohongshu` v2.0 重构背后的设计决策，供未来 skill 开发参考。

---

## 问题：v1.0 为什么是错的

v1.0 在 `personas/` 目录下放了 `feige-ai-native.md`，并在 SKILL.md 中将其列为推荐默认：

```markdown
选择 Persona：
- @飞哥AI Native — 专业深度、结果导向、AI战略视角
- @虾薯傲娇 — 傲娇嘴硬、短句口语
- @通用专业 — 默认模板
```

**这导致的问题**：
- 飞哥用 → 正常工作
- 换一个人用 → skill 仍然推荐"飞哥AI Native"人格
- 新用户的 Memory 是设计师/投资人/学生 → skill 还在说"你的AI战略定位"
- **结论：这不是一个通用 skill，这是飞哥的 skill 换了个名字**

---

## 架构原则

### 原则 1：身份来自 Memory，不来自预设

```
错误：personas/ 目录下放具体人物预设 → 预设绑定特定人
正确：personas/ 目录下放纯风格模板（专业/温暖/犀利） → 风格不绑定任何人
```

**判断标准**：如果删除你的 Memory，这个 skill 还能正常工作吗？
- 如果答案是否，说明身份被硬编码在 skill 里

### 原则 2：风格模板 = 表达方式覆盖，≠ 身份覆盖

```
风格模板只改语气和表达方式：
- "用专业风格" → 语气更严谨，但身份不变
- "用温暖风格" → 语气更柔和，但身份不变
- "用犀利风格" → 语气更直接，但身份不变

身份永远从 Memory 来：
- 你是谁 → Memory User Profile
- 你做什么 → Memory 专业领域
- 你该发什么 → Memory 目标 + 优先级
```

### 原则 3：自检——换个人用会怎样

每次写 skill 文档时，用陌生人的视角读一遍：

```
"如果你完全不知道这个 skill 的创建者是谁，
 你作为新用户第一次使用，
 它会读取你的 Memory 并给你个性化的结果吗？
 还是它在假设你是某个特定的人？"
```

## 文件结构设计

```
personas/
├── README.md         # 说明：身份来自 Memory，这里只做微调
├── _default.md       # 纯模板，无任何具体人名
├── professional.md   # 专业深度风格（语气模板，不绑定人）
├── warm.md           # 温暖治愈风格
├── sharp.md          # 犀利直接风格
└── tsundere.md       # 傲娇毒舌风格
```

**注意**：`professional.md` 不是"某人的专业风格"，它是"任何想要专业表达的人都可以用的风格"。区别在于：
- 它没有写"你是一个AI从业者"
- 它没有写"用你的AI战略视角"
- 它只写了"直接给结论、逻辑清晰、用数据支撑"

## SKILL.md 文档规范

### 示例写法对比

**错误（绑定人）：**
```markdown
Persona 选择：
- @飞哥AI Native — 专业深度、AI战略视角
```

**正确（通用）：**
```markdown
Persona 自动构建（从你的 Memory）：
- 身份：{从 User Profile 自动提取}
- 风格：{从风格偏好自动推断}
- 内容支柱：{从专业领域自动推导}

可选微调：说「用专业风格」可调整语气
```

## 知识库中的 `[XHS-*]` 前缀

Memory 条目使用 `[XHS-*]` 前缀来区分小红书相关记忆：

- `[XHS-Pattern]` — 已验证的内容模式
- `[XHS-Positioning]` — 账号定位更新
- `[XHS-Pitfall]` — 避坑经验
- `[XHS-Persona]` — 风格偏好微调

这些条目是**用户级别的**——飞哥的 `[XHS-Pattern]` 不会出现在别人的 Memory 中。
