# XHS Comment Ops（Memory + Persona 增强版）

本文件定义小红书评论检查与回复的标准流程。
**增强：回复文案由 active Persona 驱动，不再硬编码虾薯风格。**

## 0. 目标与原则（增强）

- 目标：先准确检查，再按用户指令回复
- 默认：**检查不等于自动回复**
- 回复动作必须遵循：先对位、再输入、后发送
- **回复文案生成前，必须先读取 active Persona 的语气规则**
- 一次默认只发 1 条

## 1. 检查流程（同原版）

1. 打开 `/notification`，进入「评论和@」
2. 抓取最新评论：用户名、评论文本、时间
3. 输出检查结果
4. 等待用户确认是否回复

## 2. 回复文案生成规则（NEW — Persona 驱动）

### 2.1 Persona 解析
生成回复前：
1. 确认当前 active Persona（从 Runtime Context）
2. 加载该 Persona 的：语气规则、口头禅、禁忌、回复结构
3. 按 Persona 规则生成回复文案

### 2.2 通用回复结构（可被 Persona 覆盖）

```
1) 对问题（1句）— 先接住评论的问题或情绪
2) 给结论（1句）— 你的立场/答案
3) 给价值（最多1句）— 一点有用的信息，不展开
4) 收尾（1句）— Persona 风格的收尾语
```

### 2.3 Persona 示例映射

| 评论类型 | 专业风格 | 傲娇风格 |
|---------|-------------|---------|
| 专业提问 | "好问题。先说结论：___" | "这题我会。但我不说太多：___" |
| 夸赞 | "谢谢。后续会继续分享___" | "哼（并不骄傲）" |
| 质疑 | "理解你的顾虑。实际数据是___" | "懂了。不争了我下班" |
| 敏感请求 | "这个不能发，涉及___。可以说的是___" | "这个真不能发，发了我就地失业😅。最多说到这：___" |

## 3-5. 通知页/帖子内回复 SOP + 风控 + 长度约束（同原版，略）

## 6. 常见故障（同原版 + Hermes 适配）

- 误点搜索框：点击空白处收起，重新定位通知行
- 回复对象漂移：placeholder 不匹配时立刻取消重来
- 连续两次发送失败：停止自动化，转人工确认
- 输入时如需使用 `fill`，先确认环境支持

## 7. Memory 沉淀建议

回复完成后可选：
- 将高频问题+有效回复沉淀到 knowledge-base
- 将优质回复话术存入 Hermes Memory: `[XHS-Reply] <问题类型> — <有效回复模板>`
