# 预测台账与打脸率

## 为什么必须有这个

**没有台账的研究，做一百次还是第一次。**

推演完就结束，你永远不知道自己错了多少，也永远无法改进。
这个文件让技能具备**自我校准能力**——这是它区别于所有"政策解读"内容的根本。

---

## 每条推演必须登记

格式见 `templates/ledger-entry.json`，核心字段：

| 字段 | 说明 |
|---|---|
| `id` | 推演编号（日期+城市+主题） |
| `date` | 推演日期 |
| `city` | 城市 / 区县 |
| `policy` | 政策名称与层级 |
| `persona` | 画像摘要（七参数） |
| `claims` | 每条前瞻判断（分 3/5/10 年） |
| `falsifier` | 每条判断的证伪信号 |
| `horizon` | 回访时点（3 年 / 5 年 / 10 年） |
| `status` | `pending` / `hit` / `direction_miss` / `magnitude_miss` / `timing_miss` |
| `review_note` | 回访记录 |

---

## 打脸率的三种口径

不要笼统地说"准不准"，必须区分三种错：

| 类型 | 定义 | 说明什么 |
|---|---|---|
| **方向错** `direction_miss` | 判断在增长，实际在收缩 | **模型坏了**，必须重构框架 |
| **幅度错** `magnitude_miss` | 方向对，程度差一倍以上 | 参数问题，调系数即可 |
| **时点错** `timing_miss` | 方向对、幅度对，但晚了 1 年以上 | 执行摩擦估低了，调折扣 |

**统计口径**：
> 方向准确率 = hit ÷ (hit + direction_miss)
> 方向准确率 < 60% → 该领域框架作废，回去重写
> 60–75% → 可用，但所有结论必须标"低置信"
> \> 75% → 该领域可信

---

## 回访机制

- **3 年线**：到期必须回访，逐条打勾
- **5 年线**：同上
- **10 年线**：只回访方向，不回访幅度
- **中途触发**：只要证伪信号出现，提前结案，不等到期

**提前结案是好事**——它说明证伪条件设计得有效。

---

## 校准原则

1. **错了就记错，不许事后改口径。** 改了台账，这个技能就废了。
2. **区分"我错了"和"世界变了"。** 政策推翻导致结论失效，记 `external_change`，不计入准确率，但要单独统计频率——如果外部变化率超过 40%，说明这个领域本质上不可预测，应降低输出置信度。
3. **反向校准**：如果某个指标连续三次预测偏差同向，说明它是系统性高估或低估，直接调整系数。
