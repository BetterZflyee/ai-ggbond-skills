# 按信息任务选组件

优先选择能让内容更清楚的最小组件组合。目录是检索入口，不是每篇都要选满的清单。

贴图或连续多图素材可通过同级贴图 Skill 的计划复用，详见 [贴图能力衔接](sticker-integration.md)。公众号原生贴图与长文章使用不同交接格式，避免把图片消息的文案再套 HTML 主题。

| 信息任务 | 本地直接支持 | 更复杂效果 |
|---|---|---|
| 连续论证、故事 | paragraph、heading、image | 少用互动打断 |
| 引述原话 | quote + attribution | 不把整段解释塞进引文 |
| 操作方法 | steps、list、code、faq | 分步切换可查上游，但保留全流程静态版 |
| 方案比较 | table、comparison | 短表保留矩阵；宽表分组重复关键列；逐条查询再选记录列表 |
| 时间与因果 | timeline | 视差/运动路径只在帮助理解时使用 |
| 数字与结果 | metrics、chart、table | 瀑布、漏斗、雷达查上游，先检查数值和尺度 |
| 先问后答 | reveal，含静态完整答案 | 可选点击揭秘 SVG 实验版 |
| 测验/配对 | 参考上游说明 | 题数和状态有限，不等于后台统计或收集表单 |
| 账号关注、视频 | 到平台原生插入 | 真实账号名片、权限和视频材料必需 |

## 50 项上游索引

`upstream-catalog.json` 保留 50 项稳定 ID、用途、固定版本源链接及作者的验证说明。用关键词查询：

```bash
python3 "<skill-dir>/scripts/layout.py" catalog --query 表格
python3 "<skill-dir>/scripts/layout.py" catalog --query 答题
```

`reference_only` 表示参考入口，本地未安装该组件。`vendored_generator` 仅表示已经内置脚本，不等于通过秀米、公众号或手机验证。

## 已内置互动

点击揭秘和柱形图采用固定提交的 SVG/SMIL 生成器。无外部 JavaScript、无网络和后台存储。内置的静态输出保留完整问答与数值，不支持互动的平台也能阅读。

多层视差、拼图、擦除对比等名称不能证明支持自由手势拖动；按具体说明核对。黑胶旋转不带音频播放。测验类属于有限状态演示，不自动收集用户答案。浏览器 FAQ 展开或视频标签也不能直接当作公众号原生能力。

新增组件时：先记录信息目的及必需输入，明确常规版如何读到全部内容；再核对源码许可、图片授权及平台说明，最后记录独立浏览器/目标平台证据。不因页面演示好看就默认纳入所有文章。

## 内容与组件失配的信号

- 对比表转成多张长卡片后，需要上下翻屏才能比较同一指标：优先分组矩阵，保留共同的关键列。
- 所有数字都和标签同字号：用指标字阶突出少量关键数值；大量数据仍用表格。
- 横向流程图缩小后文字难读：改为纵向流程、拆图或可编辑步骤，不依赖图片文件很大就判断清晰。
- 文章充满引文、提示框与数据块：复核每个组件的作用，按语义调整，不机械插入两段正文来满足密度配额。
- 连续叙述被一连串步骤打断：恢复原文的叙述结构，组件不能改变论证顺序。

完成后结合 `design-review.json` 和实际尺寸截图判断；自动报告没有发现问题不能代替设计审查。
