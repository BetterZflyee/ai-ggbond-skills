# 贴图能力衔接

同级 `ai-ggbond-sticker-writer` v3 负责短文案、连续多图、主题角色、准确上图文字、原生图片消息交接及图文核对。本模块负责文章阅读层级、可编辑组件与正文 HTML。

## 复用路径

1. 读取贴图 `plan.json` 和 `design-review.json`，确认图片含义、来源、页序和核对范围；文件存在不等于中文和事实已核实。
2. 原生公众号贴图：使用 `newspic-bundle.json`，纯文本文案与图片列表交原有发布器，不通过 `layout.py` 转成 HTML。
3. 长文信息卡：使用贴图导出的 `layout-input.json` 调用本模块。保留文章完整文本；图片标题、日期、数据与来源对应段落语义。
4. 适合可编辑表达的内容采用 steps/table/comparison/timeline/metrics/chart/faq。人物或概念角色、情境插画仍保留图片，不机械把所有信息都卡片化。
5. 原生第一图承担封面；长文封面在 meta.cover，默认不再出现在正文。一个完整长图不能未经检查缩成无法阅读的文章配图。

## 视觉与核对

文章的白底、正文颜色和字号不强制覆盖贴图内部。深色科技风、双语或主题角色按已确认方向保留，图片需要检查阅读宽度、字阶、边缘和裁切。标签留在原生正文，不渲染进图内；alt 不自动成为可见图注。

已知原图最小字号可传递给本模块的 `source_min_text_px`；未知时保留人工检查项。贴图中的 review 绑定图片哈希，重新生成、改图或压缩后重新核对。图内文字与来源的语义判断不能由两个工具间的格式转换替代。

`layout-input.json` 的字段保真与生成包哈希由本模块检查；原生包的图片顺序和字节哈希由贴图模块检查。两个报告分别保留，平台验收继续使用已有分层记录。
