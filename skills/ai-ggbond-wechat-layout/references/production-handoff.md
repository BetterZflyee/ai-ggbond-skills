# 草稿交接与分层验收

交给现有推送 Skill 的是 `article.html`：body 只有正文，样式内联。`preview.html` 是查看界面，`reading-preview.html` 含文字调整测试脚本，`review.html` 是设计检查页，这三者均不能上传。`interactive.html` 要先单独验证 SVG 保留，不能默认替代普通正文。

原生公众号贴图走同级贴图模块的 `newspic-bundle.json --type newspic` 路径，内容为纯文本＋有序图片。需要复用为长文章时使用其 `layout-input.json` 在本模块重新生成正文，封面与正文图片区分保留。

`handoff.json` 保存元信息、图片原路径与哈希、目标账号和已有草稿 ID。未知字段保持空值，不从别的 Profile 偷填。用户仅要求排版时本地交付；已要求推送时沿当前授权执行，不重复批准。草稿写入和公开群发是不同操作。

## 现有入口

Hermes：`~/.hermes/skills/productivity/ai-ggbond-post-to-wechat/`。
Codex：`~/.codex/skills/ai-ggbond-post-to-wechat/`；共享工具入口位于 `~/.agents/skills/`。

读取当次实际 Skill，版本可能不同。本地 dry-run 示例：

```bash
"$HOME/.bun/bin/bun" "<publisher-skill>/scripts/wechat-api.ts" \
  "/path/to/bundle/article.html" \
  --title '标题' --author 'AI朱朱侠' --summary '摘要' --dry-run
```

dry-run 仅证明当前脚本可读文件和元信息，不证明上传图片、保存草稿或手机效果。缺少 Bun 时先查现有运行时，不为本地排版强制安装发布依赖。不要打印密钥、Cookie 或完整环境变量。

## 验收记录

| 层级 | 检查 | 可声称的结果 |
|---|---|---|
| 本地生成 | 文字字段、数值、图片、HTML、哈希 | 本地结构通过 |
| 设计审查 | 内容归属、中文行尾、数字对齐、表格比较关系、图内文字 | 对应样稿的编辑检查完成，非自动认证 |
| 浏览器预览 | 320/375/390/430px、实际 iframe 内宽、文字放大、图片比例、裁切和点击 | 指定浏览器和尺寸通过 |
| 秀米重开 | 目标账号保存后重开同一草稿 | 该草稿秀米重开通过 |
| 公众号草稿 | 核对 ID，读回正文、图片、元信息、SVG | 该草稿写入读回通过 |
| 手机微信 | 真机预览、正常/深色模式、链接、触摸及动效 | 测试设备/模式通过 |

每条记录附文件哈希、日期、工具/设备与证据路径，放入交付包 `verification.json`。未测试标 `not_tested`，上游作者记录不能代替自己的验收。

预览窗口较窄时，选定正文宽度应保持不变，通过外围滚动查看；必须测量 iframe 内 `innerWidth`，不能把外框尺寸当作正文宽度。文字放大到 200% 和增加间距用于暴露裁切、内容遮挡或数据丢失；不声称这等同于手机微信的系统字号行为。`scripts/browser_audit.js` 只读测量，行尾提示需要人工看图。没有查看截图时，记录为脚本检查，不记录为视觉复核。

Ego lite 是可选浏览器执行工具。实际能读页面标题/URL 才算连通；存在 Skill 文件不算。需要用户扫码时只暂停依赖操作，本地生成继续。

原生名片/视频/布局按对应组件说明插入。SVG 经现有 API 管道保留情况未知时，使用静态正文，互动候选另走秀米验证。修改旧稿优先更新已有草稿 ID，避免重复创建；保存后重开与读回。没有真实写入不称“已推送”，没有真机测试不称“微信完全兼容”。
