# 专业排版审查方法

适用：用户要求审查现有版式、整体迭代、提升阅读质量。先看实际页面，记录可以复现的现象，再修改 profile、组件或布局规则。关注阅读任务和内容关系，不通过添加装饰证明改版发生过。

## 审查顺序

1. **内容完整与归属**：主标题/摘要是否重复进正文；数据与单位、引文与出处是否对应；分组后还能否比较；重要信息能否在静态版完整读到。
2. **层级与节奏**：标题后距应明显小于章节前距；相邻段落、引文和说明靠语义组织。长文不需要每节相同组件、每段相同长度。大于十行的段落是复核线索，不是拆段命令。
3. **中文与混排**：查看行首闭合标点、行尾开放标点、孤立的标题末行、中英混排空隙和长 URL。保持 `word-break:normal` 与严格中文换行；必要时只调整局部对齐。不要靠硬插空格/换行/不换行空格去凑某台机器的行尾。
4. **表格与数字**：首先判断比较还是逐条查询。列数不是唯一依据。保留矩阵的短表、重复关键列的分组表、字段列表各有用途；检查表头关联、数值精度、单位、数字对齐和尺度。
5. **图片**：实际宽度下能否读清图中文字；是否放大了低分辨率图；圆角是否遮住截图边缘；来源是否确需可见。文件存在和长宽比正确，不等于图片可读。
6. **可调整性与交付**：测试窄屏、放大文字和额外间距。预览必须忠实于目标视口。独立检查发布版、阅读测试副本和互动候选，避免把 UI 或测试脚本送入草稿。

## 两类规则

**有可计算参考的项目**：颜色对比度、视口宽度、图片比例、文字是否被裁切、数据字段对应关系。

**需要编辑判断的项目**：段落呼吸感、标题末行、强调是否太多、图表是否帮助理解、出处位置。脚本只提示；没有用户研究数据时不宣称某种排版一定提高完读率或转化。

`design-review.json` 中的图中文字 12px、段落行数和组件密度阈值是本模块的复核起点，非普遍标准。必须说明实际样稿和测量条件。图片区块可填 `source_min_text_px`，未提供时不能声称自动核实了图内字号；脚本不做 OCR。

## 可复现的浏览器检查

在独立本地浏览器中执行 `scripts/browser_audit.js` 这个表达式，保存返回 JSON，并补充必要截图。它只读 DOM，不写文章。调用方式随实际浏览器工具能力选择；没有浏览器测量能力就如实保留未测项目。

- 基础宽度：320/375/390/430px；至少一篇真实长文与含长文本/数字的边界样稿。
- 放大文字：125%、150%、200% 中选择与问题相关的档位，检查裁切与数据完整。额外间距可用于发现依赖固定高度的布局。
- 数字和代码：小数、单位不在窄列中拆散；超宽二维表允许容器内横向查看，并记录滚动。代码保留源文本空白，浏览器换行使用 `pre-wrap` 与 `break-spaces` 渐进增强，检查长缩进和长行。目标编辑器是否保留这些样式仍需验证。
- 预览自身：在 320px 窗口选择 375px，测量 iframe 内 `innerWidth`；外围边框尺寸不能代替正文视口。
- 图内文字：`原图字号 × 实际显示宽度 / 原图宽度` 是未裁切、等比例显示时的估计；仍需人工看字形、图片压缩及原图内容。
- 标题：测量到前一组和所属内容的间距；行尾检测会受字体度量影响，报警后查看截图，不盲改文案。

`text-wrap:balance` 是浏览器增强，可能被目标编辑器忽略；正文结构和字号不能依赖它才能可用。普通 HTML 保持完整静态信息，互动单独验证。

## 参考与证据边界

- [W3C 中文排版需求](https://www.w3.org/TR/clreq/)：用于理解行首尾标点、段落与中西文混排。查阅时为工作组草案，作为设计研究材料，不把它称为微信兼容规范。
- [W3C 对比度解释](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)：本模块对正文、次要文字和链接使用 4.5:1 作为颜色检查参考；大字和其他例外有不同条件。本模块不做完整 WCAG 认证。
- [W3C 文字间距解释](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html)：强调用户调整间距后内容仍可用，所列间距不是要求所有文章采用的默认值。公众号及手机微信的实际行为仍需验证。

## 输出审查意见

每项写清：具体问题 → 测量/截图/源码依据 → 改动 → 代价或剩余验证。先处理信息丢失、误导预览与不可读文字，再处理层级和细节。既有授权足够时直接完成调整；只有内容改写或新的业务决定需要补充信息时，才针对该缺项提问。
